# 领域文档约定

本仓库包含多个独立应用和共享包，采用多上下文布局。跨应用或跨包的领域知识应归属到实际负责该知识的应用或包，避免把所有实现细节堆入仓库根目录。

## 文档布局

- 应用领域文档放在 `apps/<slug>/docs/`。
- 共享包领域文档放在 `packages/<name>/docs/`。
- 当多个上下文之间出现需要统一导航的术语或决策时，在仓库根目录建立 `GLOSSARY-MAP.md`，指向各上下文自己的 glossary；只在确有稳定术语需要记录时创建对应 glossary。
- 架构决策记录放在负责该决策的上下文 `docs/adr/` 目录；跨上下文决策可以放在仓库级 `docs/adr/`。

目前不预建 glossary、索引或 ADR 文件。新增这些文档前，先确认有可复用的领域知识或需要追溯的架构决策。

## Agent 使用规则

开始任务时读取对应应用或包的 `AGENTS.md`，再按需读取该上下文的领域文档。跨多个上下文时分别读取相关资料；不要把一个应用的约定默认套用到其他应用。新增或调整 ADR 时，记录背景、备选方案、决定和影响。
