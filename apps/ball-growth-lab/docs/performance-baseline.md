# 性能与物理质量基准

## 测量范围

基准由 `npm run benchmark` 执行，测量 Node 下的 Rapier 固定步长，不包含浏览器消息传递、PixiJS 绘制、GPU 或设备功耗。物理场景使用无重叠六角初始排布、重力 9.8、恢复系数 1、关闭繁殖；球径为场地宽度的 2.4%。规模矩阵预热 30 步、测量 120 步；精度扫描预热 60 步、测量 240 步。单次时间受宿主负载影响，应结合重复运行结果判断。

穿透量定义为同一时刻两球直径之和减去球心距离；表中只列正值。它用于比较拥挤堆叠的稳定性，不代表完整的物理误差指标。

## 求解器与规模对比

同一规模矩阵中对照 Planck 6/2、Rapier 4/2 和 typed-array/均匀网格批量候选 4/2。以下数值为一次本地基准的平均毫秒/步：

| 球数 | 场地 | Planck 6/2 | Rapier 6/2 | 批量候选 6/2 |
| ---: | --- | ---: | ---: | ---: |
| 100 | 正方形 | 0.422 ms | 0.312 ms | 0.185 ms |
| 100 | 圆形 | 0.673 ms | 0.284 ms | 0.176 ms |
| 500 | 正方形 | 1.367 ms | 1.026 ms | 0.835 ms |
| 500 | 圆形 | 1.008 ms | 0.795 ms | 0.629 ms |
| 1000 | 正方形 | 2.768 ms | 1.799 ms | 1.014 ms |
| 1000 | 圆形 | 3.137 ms | 2.498 ms | 1.071 ms |

该次规模矩阵测 120 步，重力 9.8、无初速网格排布，不能单独作为密集长期运动质量结论。Rapier 圆形 1000 球平均 2.498 ms/步，按 1/240 物理频率折算约 10.0 ms/60 Hz 画面帧的 Node 物理时间；方形约 7.2 ms。批量候选吞吐最高，但更长密堆测试显示其最大穿透会扩大到 0.39–0.48 个场地单位，因此保留为实验对照；Planck 也不进入正式 worker。

原始求解器对比使用 1/60 秒步长。当前生产设置提高到 1/240 秒、6 次速度迭代和 2 次位置迭代，允许线性误差仍为 0.001。提高物理频率改善高密度碰撞下的能量稳定性，同时会增加 CPU 成本；本地 1000 球 1/240 基准见下文。

精度扫描中 1000 球的历史 1/60 步长结果（保留作版本对照）：

| Rapier 设置 | 正方形平均步进 / 最大穿透 | 圆形平均步进 / 最大穿透 |
| --- | ---: | ---: |
| 2/1 / 0.001 | 1.67 ms / 0.033 | 1.72 ms / 0.046 |
| 4/2 / 0.001 | 2.31 ms / 0.031 | 2.27 ms / 0.035 |
| 6/4 / 0.001 | 3.45 ms / 0.036 | 3.42 ms / 0.044 |

手写批量候选使用 `Float64Array` 保存状态，以均匀网格找邻近球，并比较了顺序位置修正的 2/1、4/2、8/8 和 16/8。增加迭代可降低部分场景的误差，却不能解决密堆里的位置振荡：1000 球圆形场地最大穿透仍约 0.39–0.48，部分球心几乎重合。候选代码保存在 `scripts/experimental/CircleBatchSimulation.ts`，方便继续优化和复测。

另以 100 个初始球、繁殖概率 0.35、球对冷却 0.7 秒运行 600 步（模拟 2.5 秒，当前步长下）。该场景用于确认增长事件开启时的负载，不是增长率预测。

## 流动性与能量回归

重力不是耗能项：它在动能和重力势能之间转换能量。旧版的恢复系数默认 0.9、并允许刚体休眠，这两项会让速度逐次下降并最终停住；Rapier 文档说明 `canSleep` 默认开启，低速刚体可在数秒后停止模拟。[Rapier 刚体与休眠](https://rapier.rs/docs/user_guides/javascript/rigid_bodies/) 恢复系数 1 表示单次接触的法向速度大小相等，但高密度多球接触的数值误差仍需单独验证。[Rapier 恢复系数](https://rapier.rs/docs/user_guides/javascript/collider_restitution/)

当前生产场景设置边界与球恢复系数为 1、摩擦与阻尼为 0、禁用刚体休眠，基础步长 1/240 秒。繁殖方案若让新球直接复制一位父球的完整速度，每次出生就会额外注入该球的动能，球数快速增加时可能推高总能量和个别球速；这轮开发中检查并移除了这种方案。当前繁殖规则会重分配两位父球和新球的速度，以保持总动量及新球生成前后的机械能（包含新球所在高度的重力势能）。高处能量不足时不生成新球并记为“未出生”，不通过阻尼或降速消除能量。

单球的瞬时速度高于初始值，不等同于总能量在增长：重力会在下落时把势能转换成动能，球间碰撞也会转移动能。旧线上版本没有记录单球最高速度或全局机械能，因此无法仅凭当时观察到的球速还原具体能量来源；恢复系数 1 也只描述接触碰撞的恢复行为，不会限制每一颗球的速度。

20 球同步落地压力场景（正方形、20 m、无繁殖、顶部 5×4 排布、重力 9.8）比较同一 10 秒的步长和求解精度：

| 步长 | 求解器 | 初始机械能 | 10 秒机械能 | 相对漂移 |
| ---: | ---: | ---: | ---: | ---: |
| 1/60 | 4/2 | 1571.92 | -701.78 | -144.7% |
| 1/120 | 4/2 | 1571.92 | -733.84 | -146.7% |
| 1/240 | 4/2 | 1571.92 | 1652.25 | +5.1% |
| 1/240 | 6/2 | 1571.92 | 1558.79 | -0.8% |

同步落地是极端压力场景，显示 1/60、1/120 在密集同时接触下会产生严重数值能量损失；1/240 + 6/2 把该场景的漂移降到约 1%。这也是提高固定频率和迭代数的依据。1000 球、重力 2、方形网格场景预热 1 秒并测量 2 秒：1/240 下 4/2 为 9.47 ms/60 Hz 画面帧、6/2 为 10.34 ms、8/4 为 13.69 ms（Node，物理线程时间；不含渲染）。因此生产默认取 6/2；这不代表手机实机可维持目标帧率。

另一个流动性样本使用 20 个由同一随机种子生成、初速 11 m/s 且球间波动 ±30%、方向 270° ±120° 的球，模拟 20 秒后采样 5 次。各场景 20/20 个球速度仍高于 0.3 m/s；重力 9.8 时平均 13.6 个球位于下半区，重力 2 时为 10.2 个，重力 0 时为 8.2 个。重力 2 同时仍形成明显抛物线，是默认值；重力 0 则只有直线飞行和碰撞转向。结果说明重力会改变空间分布，不能把“更多聚在下方”直接等同于能量损失。

高速球使用按速度自适应的物理子步：每个内部子步的预计位移不超过 0.75 个球半径，最多 32 个子步；常见速度仍只做一个子步。这样可以减少快速球穿过动态球体或折线边界的情况，不设置速度硬上限。Worker 快照由 30 Hz 提高到 60 Hz，另外在结果区显示当前最高球速。

繁殖压力样本使用种子 `GROW-*`、重力 2、初速 11 m/s、繁殖概率 0.35、冷却 0.7 秒；达到 1000 球目标后立即结束。以下为单次本地运行中观测的最高速度：

| 初始球数 | 最终球数 / 出生数 | 最高速度 |
| ---: | ---: | ---: |
| 2 | 3 / 1 | 14.58 m/s |
| 20 | 1000 / 980 | 20.76 m/s |
| 100 | 1000 / 900 | 25.34 m/s |

该样本用于回归繁殖能量和高速步进，不是长期速度分布保证。求解器仍可能在高密度接触中产生数值误差，极端速度超过 32 子步能处理的范围时也可能发生穿透；最高速度读数用于发现这类问题。

最近一次规模基准在 1/240 秒、6/2 设置下运行 30 步预热和 120 步测量，并启用速度扫描/自适应子步逻辑：

| 球数 | 场地 | 平均 ms/步 | P95 ms/步 | 折算每 60 Hz 帧的 Worker 物理时间 |
| ---: | --- | ---: | ---: | ---: |
| 100 | 正方形 | 0.398 | 0.539 | 1.6 ms |
| 100 | 圆形 | 0.436 | 0.600 | 1.7 ms |
| 500 | 正方形 | 1.143 | 1.758 | 4.6 ms |
| 500 | 圆形 | 1.252 | 1.715 | 5.0 ms |
| 1000 | 正方形 | 2.219 | 3.666 | 8.9 ms |
| 1000 | 圆形 | 2.667 | 3.541 | 10.7 ms |

折算按 1/240 秒步长、每个 60 Hz 画面帧执行 4 步计算；这是 Node 物理线程的单次本地结果，不包含 UI、快照传输或 GPU，也不能证明手机实机达到 60 FPS。

## 缺口宽度扫描

`npm run benchmark:gaps` 对 Planck 和 Rapier 各跑正方形、圆形场地，设置两个周长等距缺口。单球从顶部缺口落入并从底部离开；17 个初始横向偏移覆盖球半径范围，单次最多运行 4 秒：

| 缺口宽度 / 球径 | Rapier 正方形 / 圆形 | Planck 正方形 / 圆形 |
| ---: | ---: | ---: |
| 1.05× | 1/17 · 1/17 | 1/17 · 1/17 |
| 1.25× | 5/17 · 3/17 | 3/17 · 3/17 |
| 1.45× | 7/17 · 7/17 | 7/17 · 7/17 |
| 1.75× | 13/17 · 13/17 | 13/17 · 13/17 |
| 2.00× | 17/17 · 17/17 | 17/17 · 17/17 |
| 2.50× | 17/17 · 17/17 | 17/17 · 17/17 |
| 3.00× | 17/17 · 17/17 | 17/17 · 17/17 |

默认缺口宽度因此设为球径的 2 倍：这组样本的完整通过率为 100%，同时比 2.5–3 倍保留更多边界。结果只适用于本次球径、速度、步长和偏移样本；滑块仍允许用户自行调节。

## 运行命令与限制

```bash
# 规模、形状、求解器和迭代数可以组合缩小扫描范围
BENCHMARK_COUNTS=100,500,1000 \
BENCHMARK_SHAPES=square,circle \
BENCHMARK_ALGORITHMS=planck,circle-batch,rapier \
BENCHMARK_TUNINGS=2/1,4/2,6/2,6/4 \
BENCHMARK_FRAMES=120 WARMUP_FRAMES=30 npm run benchmark

# Rapier 的误差阈值可附在迭代配置后，例如 4/2/0.0001
BENCHMARK_ALGORITHMS=rapier \
BENCHMARK_TUNINGS=2/1/0.01,2/1/0.001,4/2/0.001,4/2/0.0001 \
BENCHMARK_COUNTS=1000 BENCHMARK_FRAMES=240 WARMUP_FRAMES=60 npm run benchmark

# 带繁殖负载；输出最终球数、出生数和未出生数
BENCHMARK_COUNTS=100 BENCHMARK_BIRTH_PROBABILITY=0.35 \
BENCHMARK_PAIR_COOLDOWN=0.7 BENCHMARK_FRAMES=600 \
BENCHMARK_ALGORITHMS=rapier BENCHMARK_TUNINGS=4/2 npm run benchmark

GAP_SCAN_SAMPLES=101 npm run benchmark:gaps
```

Rapier WASM 延迟到用户开始实验时才由 Worker 加载；当前 Vite 产物中的 WASM 文件约 2.4 MB（gzip 约 0.92 MB）。PixiJS 主应用 chunk 为 505 KB（gzip 约 153 KB），略高于 Vite 500 KB 的提示阈值；构建通过。物理 Worker 每秒最多发 60 次快照，React 不逐步更新坐标。Node 数据不能证明浏览器或真实手机帧率；后续需在目标浏览器和手机上记录机型、系统、浏览器及实际球数。
