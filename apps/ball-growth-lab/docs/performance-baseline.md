# 性能与物理质量基准

## 测量范围

基准由 `npm run benchmark` 执行，测量 Node 下固定 1/60 秒的物理步进，不包含浏览器消息传递、PixiJS 绘制、GPU 或设备功耗。场景使用无重叠六角初始排布、重力 9.8、恢复系数 0.9、关闭繁殖；球径为场地宽度的 2.4%。规模矩阵预热 30 步、测量 120 步；精度扫描预热 60 步、测量 240 步。单次时间受宿主负载影响，应结合重复运行结果判断。

穿透量定义为同一时刻两球直径之和减去球心距离；表中只列正值。它用于比较拥挤堆叠的稳定性，不代表完整的物理误差指标。

## 求解器与规模对比

同一规模矩阵中对照 Planck 6/2、Rapier 4/2 和 typed-array/均匀网格批量候选 4/2。以下数值为一次本地基准的平均毫秒/步：

| 球数 | 场地 | Planck 6/2 | Rapier 4/2 | 批量候选 4/2 |
| ---: | --- | ---: | ---: | ---: |
| 100 | 正方形 | 0.709 ms | 0.504 ms | 0.070 ms |
| 100 | 圆形 | 0.681 ms | 0.421 ms | 0.087 ms |
| 500 | 正方形 | 5.067 ms | 1.139 ms | 0.546 ms |
| 500 | 圆形 | 3.764 ms | 1.184 ms | 0.606 ms |
| 1000 | 正方形 | 13.177 ms | 2.494 ms | 1.398 ms |
| 1000 | 圆形 | 14.755 ms | 2.560 ms | 1.461 ms |

批量候选吞吐最高，但在 1000 球的堆叠场景中穿透过大，不能作为游戏物理引擎。Rapier 4/2 在 1000 球下仍比 16.67 ms 的 60 Hz 步进预算快约 6 倍，同时将最大穿透控制在约 0.03–0.05 个场地单位；Planck 在相同场景达到约 0.11–0.20。批量候选和 Planck 保留在基准工具中，不进入正式 worker。

生产求解器选择 Rapier WASM，默认 4 次速度迭代、2 次位置迭代、允许线性误差 0.001。该配置相对 2/1 增加约 30–40% 步进成本，在 1000 球圆形场景将最大穿透从约 0.046 降到约 0.035；增加到 6/4 后吞吐进一步下降，穿透没有稳定改善。紧缩允许误差也没有带来一致的质量提升，因此默认保留 0.001。

精度扫描中 1000 球的代表结果：

| Rapier 设置 | 正方形平均步进 / 最大穿透 | 圆形平均步进 / 最大穿透 |
| --- | ---: | ---: |
| 2/1 / 0.001 | 1.67 ms / 0.033 | 1.72 ms / 0.046 |
| 4/2 / 0.001 | 2.31 ms / 0.031 | 2.27 ms / 0.035 |
| 6/4 / 0.001 | 3.45 ms / 0.036 | 3.42 ms / 0.044 |

手写批量候选使用 `Float64Array` 保存状态，以均匀网格找邻近球，并比较了顺序位置修正的 2/1、4/2、8/8 和 16/8。增加迭代可降低部分场景的误差，却不能解决密堆里的位置振荡：1000 球圆形场地最大穿透仍约 0.39–0.48，部分球心几乎重合。候选代码保存在 `scripts/experimental/CircleBatchSimulation.ts`，方便继续优化和复测。

另以 100 个初始球、繁殖概率 0.35、球对冷却 0.7 秒运行 600 步（模拟 10 秒）。Rapier 4/2 平均每步 0.89 ms（正方形，出生 207 个）和 0.47 ms（圆形，出生 120 个）；对应的场地占用会令一些出生位置失败，未出生数分别为 383 和 278。这个场景用于确认增长事件开启时的负载，不是增长率预测。

## 缺口宽度扫描

`npm run benchmark:gaps` 对 Planck 和 Rapier 各跑正方形、圆形场地，设置两个周长等距缺口。单球从顶部缺口落入并从底部离开；17 个初始横向偏移覆盖球半径范围，单次最多运行 4 秒：

| 缺口宽度 / 球径 | Rapier 正方形 / 圆形 | Planck 正方形 / 圆形 |
| ---: | ---: | ---: |
| 1.05× | 0/17 · 2/17 | 3/17 · 1/17 |
| 1.25× | 3/17 · 3/17 | 3/17 · 3/17 |
| 1.45× | 7/17 · 7/17 | 7/17 · 7/17 |
| 1.75× | 11/17 · 11/17 | 13/17 · 13/17 |
| 2.00× | 17/17 · 17/17 | 17/17 · 17/17 |
| 2.50× | 17/17 · 17/17 | 17/17 · 17/17 |
| 3.00× | 17/17 · 17/17 | 17/17 · 17/17 |

默认缺口宽度因此设为球径的 2 倍：这组样本的完整通过率为 100%，同时比 2.5–3 倍保留更多边界。结果只适用于本次球径、速度、步长和偏移样本；滑块仍允许用户自行调节。

## 运行命令与限制

```bash
# 规模、形状、求解器和迭代数可以组合缩小扫描范围
BENCHMARK_COUNTS=100,500,1000 \
BENCHMARK_SHAPES=square,circle \
BENCHMARK_ALGORITHMS=planck,circle-batch,rapier \
BENCHMARK_TUNINGS=2/1,4/2,6/2,6/4 \
BENCHMARK_FRAMES=120 WARMUP_FRAMES=30 npm run benchmark

# Rapier 的误差阈值可附在迭代配置后，例如 4/2/0.0001
BENCHMARK_ALGORITHMS=rapier \
BENCHMARK_TUNINGS=2/1/0.01,2/1/0.001,4/2/0.001,4/2/0.0001 \
BENCHMARK_COUNTS=1000 BENCHMARK_FRAMES=240 WARMUP_FRAMES=60 npm run benchmark

# 带繁殖负载；输出最终球数、出生数和未出生数
BENCHMARK_COUNTS=100 BENCHMARK_BIRTH_PROBABILITY=0.35 \
BENCHMARK_PAIR_COOLDOWN=0.7 BENCHMARK_FRAMES=600 \
BENCHMARK_ALGORITHMS=rapier BENCHMARK_TUNINGS=4/2 npm run benchmark

GAP_SCAN_SAMPLES=101 npm run benchmark:gaps
```

Rapier WASM 延迟到用户开始实验时才由 Worker 加载；当前 Vite 产物中的 WASM 文件约 2.4 MB（gzip 约 0.92 MB）。PixiJS 主应用 chunk 为 505 KB（gzip 约 153 KB），略高于 Vite 500 KB 的提示阈值；构建通过。物理 worker 每秒最多发 30 次快照，React 不逐帧处理坐标。Node 数据不能证明浏览器或真实手机帧率；后续需在目标浏览器和手机上记录机型、系统、浏览器及实际球数。
