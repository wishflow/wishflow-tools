# P4 任务：结构化变量与历史观察

对应规格：[P4 结构化变量与历史观察](../specs/p04-structured-variable-history.md)。依赖 P3 已发布的执行事件和回放；本阶段只扩展真实 CPython 记录，不实现教学 VM、历史恢复或跨事件对象图。

## 实施启动门

P4 的快照 DTO、帧身份规则、截断语义和采集预算构成新增 Worker 数据契约。开始 T01 前，先取得用户对 [P4 spec §2–4](../specs/p04-structured-variable-history.md) 的明确确认；之后不再对已确认字段逐项重复征询。实现前复核当前 P3 Worker 消息、trace 回调和 `ExecutionPanel` 消费方式，按现有风格做最小调整；如发现实现需要增加依赖或改变此契约，暂停该部分并重新整理影响。

## T01：在 Worker 内采集不可变、有界快照

- **规格**：§2–4。
- **前置**：实施启动门通过；复核 P3 Worker 执行路径。
- **改动边界**：为事件定义快照 DTO；在 trace 回调内读取模块全局和活动用户帧局部值；以精确内建类型判断和有界递归生成普通可传输数据；为调用段分配并回收 `frameId`；在单事件及单次运行预算耗尽后停止对象展开，但继续记录 P3 基本事件。不得把 frame、`f_locals` proxy 或用户值留在 UI 状态，也不得因序列化调用用户自定义 `repr`、`str`、property、描述符或迭代器。
- **验收**：固定 Pyodide/CPython 实际运行用例证明全局与函数局部可采集；递归帧身份不同且同一活动帧在相邻事件稳定；精确容器被复制而旧快照不受后续修改影响；超过整数位数、字符串、深度、条目数、节点数和帧数限制时 DTO 明确标记不完整，P3 轨迹与运行仍可用。
- **验证**：先新增针对 Python serializer 的真实 Pyodide 浏览器用例；需要纯函数测试时只覆盖独立格式化/预算逻辑，不用手写 mock 代替 CPython 行为。检查成功、异常、停止、超时、Retry 后 `sys.settrace`、标准流及 Worker 重置行为。
- **主要文件**：`src/analysis/types.ts`、`src/worker/pyodide.worker.ts`、`e2e/execution-trace.spec.ts` 及必要的测试文件；实现前以当前树为准。

## T02：在事件回放面板查看 Globals 与帧变量

- **规格**：§5–6。
- **前置**：T01。
- **改动边界**：在现有执行面板随回放游标展示快照；Globals 独立显示；增加当前事件帧选择器和有界容器的原生折叠展开。默认选中触发该事件的帧；不增加路由、UI 依赖或第二套语言状态。完整/截断信息必须与 P3 trace 截断分别呈现。
- **验收**：上一/下一事件或键盘移动游标时快照与选中事件同步；帧切换只切换观察范围、不再次执行 Python；全局不重复出现在模块局部变量；容器深度、子项、回指标记和摘要可读且不会递归展开；双语切换、键盘焦点和 320/768/1024/1440px 布局通过。
- **验证**：Playwright 以真实 Worker 运行函数、递归和嵌套内建容器，校验帧选项、全局/局部作用域和回放同步；用窄视口及键盘测试检查无横向溢出与焦点可见。
- **主要文件**：`src/components/ExecutionPanel.tsx`、`src/locales.ts`、`src/styles.css`、`e2e/execution-trace.spec.ts`；实现前以当前树为准。

## T03：比较相邻事件并诚实呈现不完整范围

- **规格**：§3、§5–6。
- **前置**：T01、T02。
- **改动边界**：以纯 TypeScript 比较相邻两个已保存 DTO；全局按名称，局部按 `(frameId, name)`；比较嵌套有序值时忽略事件局部 `referenceId`。加入“全部值/相邻变化”切换及新增、变化、移除、未知/部分、无变化的文字状态。不得读取用户代码、重跑或推导不可见自定义对象内部是否改变。
- **验收**：赋值、删除、列表/字典的深层修改和相同值重赋值产生正确状态；完整范围单侧缺项可标新增/移除；任一侧范围不完整时，缺项结果为未知/部分而非猜测；首事件显示为基准观察点；差异达到 200 项上限时明示截断；trace 事件发生于当前行之前的语义不被 UI 说成“当前行执行后”。
- **验证**：独立 TypeScript 单测覆盖完整/不完整范围、递归容器、引用 ID 变化、帧进入/返回、值相等和差异上限；Playwright 校验事件游标前后变化及本地化状态文案。
- **主要文件**：新增最小的 `src/analysis/snapshot-diff.ts` 与单测（若当前架构适合），以及执行面板、双语文案和端到端用例；实现前以当前树为准。

## T04：边界回归、文档记录与发布验收

- **规格**：§6–7。
- **前置**：T01–T03。
- **改动边界**：完成安全和资源回归、无障碍检查、计划与任务证据；不改变共享壳、站点安全头、Pyodide 版本或无关 CI。
- **验收**：真实 Pyodide 用例验证超大整数不会触发长整数十进制转换失败；对象的 `__repr__`、property、`__iter__` 故意抛错时快照、展开和差异仍可用且副作用未触发；停止/异常/反复运行后无旧快照串入；P1–P3 无回归。
- **验证**：应用 `pnpm run test:ci`、根 `pnpm run test:catalog`、根 `pnpm run build:site`、相对链接检查、`git diff --check`；检查 `/python-interpreter-lab/` 子路径 bundle。按已授权发布流程提交、合并和推送，等现有 workflow 成功，再在线上核对运行版本、快照冻结、回放、截断和响应式显示。
- **记录**：逐项更新下表及整体计划；本地通过、CI 部署成功和线上实测分开记录。线上门未通过时不得标记 P4 发布完成。

## 依赖关系与检查点

```text
用户确认快照数据契约
  └── T01 Worker 有界快照
        └── T02 回放面板
              └── T03 相邻事件差异
                    └── T04 回归、发布与线上验收
```

- **检查点 A（T01）**：事件 DTO 完全是有界普通数据，采集在 trace 回调内完成，PyProxy/帧不进入历史；快照耗尽不影响 P3 事件。
- **检查点 B（T02）**：用户能按事件、全局范围和调用帧检查冻结的结构化值；仅回放观察位置。
- **检查点 C（T03）**：变量变化状态可以独立核验；截断范围不误报新增/移除。
- **完成门（T04）**：本地、CI/CD 与线上验收均通过后，才将 P4 标为完成并开始 P5。
