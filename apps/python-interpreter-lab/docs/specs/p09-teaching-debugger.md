# P9 规格草案：教学调试控制

对应整体计划：[P9 教学调试控制](../implementation-plan.md)，任务拆分见 [P9 tasks 草案](../tasks/p09-teaching-debugger.md)。本文是供确认的方案草案，**语义确认前不能作为实现授权**。本阶段只控制 `mini-vm-v4` 教学 VM，不改变真实 Pyodide/CPython 视图。

## 1. 目标与边界

在现有教学 VM 的逐指令执行、暂停、复位和历史快照上增加可预测的源码级调试能力：源码行断点、教学指令断点、行步进、Step Into/Over/Out、Continue 和运行速度选择。用户能从 AST、教学指令和运行快照间定位位置，并能解释程序为什么在某个位置暂停。

沿用 React、TypeScript、Vite、共享站点壳、原生 `textarea` 和既有 Teaching VM Worker。预期扩展现有消息协议以传递调试命令和运行选项；不新增 Worker、第三方编辑器、状态库、服务或依赖。教学字节码和语言语义不变，版本继续标为 `mini-vm-v4`；P5–P8 的指令执行、对象身份、函数作用域和 5,000 条动态指令上限继续有效。

## 2. 现有代码基线

本草案对照 P8 已发布代码核过以下接口，后续实现应沿用这些状态，而不是另造并行执行模型：

- `TeachingInstruction` 已有稳定的程序内 `index`、opcode 和 `SourceSpan`；`TeachingFunction` 已有入口/结束索引及定义位置。指令索引只是教学程序位置，不是 CPython offset。
- `TeachingVmSnapshot` 已包含 `pc`、最后执行/下一条指令索引、执行计数、运行状态、帧栈、变量、值栈、堆和输出；可以在既有快照上增加受限的暂停原因/命中信息。
- Teaching VM Worker 已有 `run`、`pause`、`reset`、运行代次取消和 session/sourceRevision 隔离。运行循环每批最多执行 8 条指令，批次间等待 16ms；Pause 在指令边界检查。建议速度档只配置批量大小与调度间隔，不改执行语义。
- 当前运行历史最多 500 个快照，动态指令上限为 5,000，编译指令上限为 2,000；断点集合应有界，并与当前编译结果绑定。
- 页面使用原生 `textarea`，AST 和教学指令面板已有源码定位控件；不应通过新增编辑器依赖实现 gutter。断点入口可从现有 AST/指令位置建立，并提供可访问的断点概览。
- 时间轴已提供“回到执行头”操作，且在查看旧快照时禁用运行按钮。P9 如提供“Continue 会自动回执行头”，必须清楚标示状态变化，并保持历史只读、不分叉。

## 3. 本草案的建议行为

| 能力 | 建议语义 | 待用户确认 |
| --- | --- | --- |
| 源码行断点 | 绑定当前编译结果中该行首个可执行教学指令；命中时在执行该指令前暂停。递归或循环再次到达该行时可再次命中 | 无可执行指令的空行/注释行是否拒绝添加，还是显示待绑定断点 |
| 教学指令断点 | 绑定编译结果中的指令索引；在该指令执行前暂停 | 指令表改版后按索引清除，还是尝试迁移 |
| Continue | 从当前执行头继续；如果暂停原因是断点，则仅跳过这一次当前位置的命中，执行后同一断点在循环/递归再次到达时正常暂停 | 当前断点是否仅忽略一次，还是在本次 Continue 期间禁用 |
| 历史位置 | 时间轴处于旧快照时，Continue 先返回执行头再运行；不从旧快照分叉，也不改变历史 | 是否需要在返回执行头时显示明确提示 |
| 复位/重新编译 | 复位保留当前编译版本的断点；源码变化导致编译结果失效时清除已绑定断点 | 重新编译但源码文本没变化时是否保留断点 |
| 运行速度 | 提供“慢 / 标准 / 快”档，仅改变自动运行时的执行批次和展示节奏；单步与步进命令不受影响 | 推荐档位暂为：慢 1 条/250ms，标准 8 条/16ms（保留当前默认），快 32 条/16ms；数值是最大批量/调度间隔，不承诺硬实时速率 |
| 执行预算 | 继续沿用每次运行最多 5,000 条动态指令；断点暂停不消费指令预算，已执行指令仍计入预算 | 无 |

断点和运行控制状态按当前源码修订与编译结果绑定。编辑源码或切换引擎后，旧编译结果失效，调试操作禁用；不会让旧 Worker 响应更新新源码状态。教学 VM 的程序输出、错误诊断和历史记录保持原语义。

## 4. 步进语义待确认

总体计划列出了 Step Line 和 Step Into/Over/Out，但尚未定义 Step Line 与函数调用深度的关系。需要在下列方向中确认其最终含义：

1. **标准调试器组合（建议）**：保留单指令 Step；Step Into/Over/Out 按源码行与调用帧深度工作；将 Step Line 定义为“运行到下一可执行源码行”，并明确它是否等同 Step Over，或从工具栏中移除重复入口。
2. **增加独立行步进**：单指令 Step 后增加一种与 Into/Over/Out 不同的 Step Line；需要具体定义其跨越同一行多条指令、调用和返回的停止条件。

为便于确认，以下行为在本草案中只作为候选，不是已接受语义：

| 命令 | 候选停止条件 |
| --- | --- |
| Step Into | 执行当前指令，停在下一可执行源码行；若进入函数，则在新帧首个可执行行停下 |
| Step Over | 执行当前源码行；函数调用在当前命令内完成，停在原帧下一可执行行或当前函数返回到调用者后 |
| Step Out | 在当前函数帧内运行到返回；停在调用者后续可执行位置。模块帧无调用者，应禁用并提供说明 |
| Step Line | 由用户在上方选定；不得与 Into/Over 产生不可解释的重复行为 |

对于同一源代码行映射多条指令，命令应按上述源码行/帧条件推进，而不是把一次源码步进误作一条字节码。进入、返回、循环回边和条件跳转均以 Teaching VM 实际执行状态为准。用户确认的语义需进一步写成精确状态转移表，再开始实现。

## 5. 断点和暂停状态

建议的调试状态包括：当前编译源码修订、已启用的源码行/指令断点集合、暂停原因（用户暂停/断点/步进完成/终止）、命中的断点 ID、执行头位置和当前步进目标。UI 显示断点位置和暂停原因；程序计数器仍指向下一条待执行指令。

- 断点判定发生在教学指令执行前。命中只把运行状态切换为 `paused` 并记录可观察原因，不增加动态指令计数，也不改变值栈、变量、帧或容器堆。
- Continue 离开当前位置时必须保证不会立即重复命中同一断点；循环或递归之后真实再次抵达该位置仍会命中。
- Pause 请求在当前原子指令完成后生效；不在运算中间暴露半更新的栈或对象堆。
- 编译错误、运行错误、指令预算耗尽和正常完成是终态；断点和步进命令不得从终态隐式恢复。
- 浏览历史只改变观察游标。除 Continue 的“先回执行头”行为外，用户不能从历史状态继续、修改变量或建立新执行分支。

## 6. 交互与无障碍

- 不引入代码编辑器依赖或自绘代码编辑器。断点可以从现有源码位置链接、AST 节点或教学指令表设置；具体入口应能显示它对应的源行/指令与启用状态。
- 控制区至少提供：单指令步进、确认后的源码步进模式、Continue、Pause、Reset、断点概览与运行速度选择。不可用的操作使用禁用状态和可读说明。
- 可通过键盘添加/移除断点、触发步进命令、选档和恢复执行；焦点可见；暂停原因通过 `role="status"` 等可访问方式播报。
- 当前/命中指令、对应源码位置和调用帧应可互相定位。历史浏览状态与实时运行状态明显区分。
- 中英文使用共享语言状态；视口覆盖 320、768、1024、1440px；长指令表在面板内滚动，页面不横向溢出；动画遵循 `prefers-reduced-motion`。

## 7. 验收场景

以下先固定为待写测试的行为类别；具体期望需按第 3 节确认后补成精确断言。

| 场景 | 需要证明 |
| --- | --- |
| 同一行编译成多条教学指令 | 行断点只在该行首次执行前暂停；源码步进推进到定义的下一个位置 |
| While/for 回到断点行 | 继续不会立刻重复暂停；下一次循环命中可以再次停下 |
| 递归调用 | Into/Over/Out 的活动帧 ID、当前行和暂停原因满足确认的调用深度规则 |
| 函数返回 | Step Out 在调用者的实际续行处暂停，不停在已弹出的帧 |
| Continue 与断点 | 从断点继续先前进，未来命中仍生效；已完成或错误程序不能继续 |
| 历史游标位于过去 | Continue 返回执行头并继续，不修改旧快照或产生历史分支 |
| Pause 与速度档 | Pause 在原子指令边界生效；速度档只改变自动运行节奏，不影响终态与 5,000 条预算 |
| 复位/编辑/编译/切引擎 | Reset 保留或清除断点符合确认规则；过期 Worker 消息和旧断点不能污染新程序 |

## 8. 验证门与回滚

- VM 单元测试覆盖断点命中前状态、重复命中抑制、同源行多指令、跳转/循环、帧深度变化、步进目标、暂停原子性和预算边界。
- Worker 测试覆盖新旧 session/sourceRevision 隔离、运行批次、断点/暂停竞争、速度档切换、历史回看后 Continue 和 Reset。
- Playwright 通过生产构建和真实 Worker 验证源码行/教学指令断点、键盘操作、递归 Into/Over/Out、历史执行头恢复、终止态、双语和响应式。
- 运行应用 `pnpm run test:ci`、根 `pnpm run test:catalog`、`pnpm run build:site` 和 `git diff --check`；发布 workflow 成功后，用 Codex 内置浏览器验收正式子路径。
- P9 不改变语法、指令集和数据持久化。回滚可移除高级调试控件与 Worker 调试命令，保留 P5–P8 的单指令 Step、Continue/旧有 Run/Pause/Reset 和全部语言能力。
