# P8 规格：列表、字典与对象引用

对应整体计划：[P8 列表、字典与对象引用](../implementation-plan.md)，能力拆分见[能力地图](../../P8-CAPABILITY-MAP.md)，任务与执行记录见 [P8 tasks](../tasks/p08-mutable-containers.md)。本文定义 `mini-vm-v4` 的实施边界，P5–P7 已发布能力和应用[前端契约](../../AGENTS.md)继续有效。

## 1. 目标与边界

教学 VM 支持可变列表和字典的字面量、下标读取与赋值，并把引用身份和对象内容纳入有界历史。用户可观察变量是否指向同一对象、修改如何通过别名传播、嵌套和循环引用如何显示，以及历史如何保留修改前的对象状态。

本阶段沿用独立 Teaching VM Worker、React + TypeScript + Vite 和共享 `@wishflow/site-shell`。不新增依赖、服务、路由或 Worker 消息协议；真实 Pyodide/CPython 视图保持不变。教学对象 ID 是 VM 自己的展示身份，不是 CPython 地址、`id()` 结果或真实对象布局。

## 2. 值与引用语义

| 能力 | P8 语义 | 边界 |
| --- | --- | --- |
| 列表构造 | `[]` 和 `[expr, ...]`；可嵌套列表/字典；每次执行字面量均分配新对象 | 不支持推导式、元组、集合、切片和列表方法 |
| 字典构造 | `{}` 和 `{key: value, ...}`；每次执行字面量均分配新对象；按插入顺序保存条目 | 不支持推导式、关键字构造、视图和字典方法 |
| 列表读取 | `value[index]`；索引必须为整数或布尔值；允许负索引，`True`/`False` 分别按 `1`/`0` 处理 | 不支持切片；字符串、`None` 或容器索引产生类型诊断；越界产生 `IndexError` 类诊断 |
| 列表写入 | `value[index] = expression` 替换已有位置；可以通过嵌套下标修改嵌套对象 | 不支持扩容、`append`、删除和多目标赋值 |
| 字典键 | 仅接受整数、布尔值、字符串和 `None`；键按相应标量相等规则匹配，`True` 与 `1`、`False` 与 `0` 指向同一条目 | 列表/字典等可变容器不能作为键，产生 `TypeError` 类诊断 |
| 字典读取/写入 | `value[key]` 读取；`value[key] = expression` 新增或更新；更新不改变已有条目顺序；缺少键产生 `KeyError` 类诊断 | 不支持删除、迭代、`in`、`get`、`pop`、`update` 等 API |
| 别名 | 名称赋值、形参、返回值和容器元素传递同一对象引用，不隐式复制；新执行的字面量具有不同对象 ID | 不支持源代码查询 ID 或 `is` / `is not`；身份通过教学 UI 中的引用 ID 观察 |
| 真值 | 空列表/字典为假，非空为真 | 不扩展其他类型的真值规则 |
| 相等 | 列表和列表按元素递归比较；字典和字典按键值对比较且忽略插入顺序；列表与字典不相等；支持 `==` / `!=` | 不支持容器大小比较；循环对象比较用已访问对象对终止递归，按教学 VM 的循环安全规则给出结果 |

列表索引、字典插入顺序、可哈希键以及 `True`/`1` 键等价遵循 Python 内建容器的对应规则。P8 将字典键限制在已有标量子集；循环比较和展示按本规格中的有界教学规则处理。[序列类型](https://docs.python.org/3.14/library/stdtypes.html#sequence-types-list-tuple-range) · [映射类型](https://docs.python.org/3.14/library/stdtypes.html#mapping-types-dict) · [订阅表达式](https://docs.python.org/3.14/reference/expressions.html#subscriptions)

## 3. 语法子集与求值顺序

```ebnf
assignment       ::= NAME "=" expression
                    | subscriptTarget "=" expression
subscriptTarget  ::= primary ("[" expression "]")+
listLiteral      ::= "[" [expression ("," expression)* [","]] "]"
dictLiteral      ::= "{" [expression ":" expression
                      ("," expression ":" expression)* [","]] "}"
subscript        ::= primary ("[" expression "]")+
primary          ::= INTEGER | STRING | "True" | "False" | "None"
                    | NAME | directFunctionCall | listLiteral
                    | dictLiteral | "(" expression ")"
```

- 列表和字典字面量允许尾逗号；空 `{}` 表示空字典。集合字面量、空集合、切片和属性访问不支持。
- 下标可连续出现，例如 `matrix[0][1]`；下标表达式自身可包含当前支持的任意表达式。
- 赋值右侧先求值，再从左到右求值目标容器和每一层下标，最后写入目标。这与 Python 赋值目标的求值顺序一致。[赋值语句](https://docs.python.org/3.14/reference/simple_stmts.html#assignment-statements)
- 列表/字典字面量元素按源码从左到右求值。字典中重复键的后一个值覆盖前值，但条目保留第一次插入的位置。
- 函数内的 `a[index] = value` 读取已有的局部或全局 `a`，不把 `a` 归类为新局部赋值；只有 `name = value` 仍按 P7 规则静态绑定局部名。
- `for` 继续只支持 P6 的 `range(...)`，不迭代列表或字典。表达式语句、`del`、链式赋值和逗号分隔的多目标赋值仍不支持。

## 4. 教学指令集 `mini-vm-v4`

| 指令 | 行为 |
| --- | --- |
| `BUILD_LIST count` | 消费栈顶 `count` 个元素引用/标量，创建全新的列表对象并压入对象引用 |
| `BUILD_MAP count` | 消费栈顶 `count` 组键和值，创建全新的有序字典对象并压入对象引用 |
| `BINARY_SUBSCR` | 消费容器和索引/键，读取元素并压入结果 |
| `STORE_SUBSCR` | 按 `[value, container, index]` 栈顺序写入元素；不遗留临时值 |

指令索引仍是教学程序数组索引，不是 CPython byte offset。单步仍恰好执行一条指令；列表/字典的键验证、索引和存储都属于对应下标指令的一步。超限与类型错误定位到构造或下标操作的源码范围。

## 5. 堆、对象图和历史 DTO

- Worker 内部为列表和字典分配单调递增的对象 ID；每次编译/复位的新运行从 `#1` 开始。ID 在同一运行期间不复用；覆盖或失去最后一个变量引用不会重排其他 ID。
- `RuntimeValue` 中的列表/字典值只包含类型和对象 ID；可变条目集中存放在 VM 私有 heap。Worker 不向主线程发送原生循环引用。
- 每个 `TeachingVmSnapshot` 包含可序列化的 `heap` 对象表。容器值只包含 ID 引用；对象记录包含直接元素或键值引用。快照对象表只包含从模块变量、活动帧局部变量及帧求值栈可达的对象。
- 每步快照复制当前可达对象表并深度冻结；历史快照不得引用可变 VM heap。浏览旧步骤只能观察旧对象内容，不改变当前执行。
- 对象图视图以平面对象记录展示 ID、容器类型、元素/键和值引用；不把对象递归内嵌展开。引用 ID 可定位对应记录；回边展示为普通引用，不触发无限展开。
- 活动帧变量、模块变量和求值栈把引用显示为例如 `list #3` / `dict #4`；相同 ID 表示别名，同值而不同 ID 表示不同对象。对象记录显示于当前所选历史快照。
- `print` 保持 P5 的逐值输出。容器使用 Python 风格列表/字典表示；字符串在容器内部带引号。递归路径遇到当前正在格式化的对象时，列表输出 `[...]`、字典输出 `{...}`；共享但非循环的对象可在不同位置重复表示。
- 容器结构相等比较使用对象对集合检测循环；首次遇到的一对容器递归比较，已处理过的同一对象对视作本次比较相等以终止递归。该规则只定义 Teaching VM，不声称复刻 CPython 的递归比较错误细节。

## 6. 资源预算和错误

| 资源 | 上限 | 超限行为 |
| --- | ---: | --- |
| 单次运行分配对象数 | 256 | 新对象分配前报告 `heap-object-limit-exceeded`；对象 ID 不回收 |
| 单个容器条目数 | 256 | 构造时在分配前报告 `container-size-limit-exceeded` |
| 本次运行累计列表项/字典条目 | 2,048 | 创建或插入前报告 `heap-entry-limit-exceeded`；更新已有字典键不增加条目数 |
| 单个快照对象数与条目数合计 | 2,304 | 由对象数和条目上限共同约束，快照始终完整 |
| 历史容器对象/条目总记录数 | 50,000 | 淘汰最早快照，置 `history.truncated`；保留当前快照及其完整对象图 |
| 历史快照数 | 500 | 沿用现有限制；最早快照淘汰时置截断标志 |
| 动态教学指令 | 5,000 | 沿用现有限制 |
| 源码 / 编译指令 / 名称 | 20,000 UTF-16 code units / 2,000 / 200 | 沿用现有限制 |
| 标准输出 | 32,768 Unicode 码点 | 格式化时有界累积；超限报告 `output-too-long`，不先构造无界字符串 |

历史容器总记录数以保留快照的 `heap.objects.length + 所有对象 entries.length` 求和。新增快照后，从最旧端淘汰快照，直到快照数量和记录总数均满足限制；当前快照不能被淘汰。编译失败、VM 资源错误及字典键/下标错误均使用有界诊断和准确源码位置。

## 7. 前端和兼容要求

- 沿用应用单页、共享语言状态、独立 Teaching VM Worker 和现有会话身份；不变更 Worker 消息 envelope。编译结果版本升为 `mini-vm-v4`。
- 对象图应能在当前快照和历史快照之间切换；列表/字典别名及对象条目由引用 ID 表达，历史修改前状态不被污染。
- 对象图使用键盘可操作的引用定位控件、可见焦点和中英文名称；数据全部以文本安全渲染。对象表有限、内部滚动，不产生页面横向溢出；遵循 `prefers-reduced-motion`。
- P7 函数实参、局部/全局槽位、返回值和循环内赋值可保存列表/字典引用；帧的调用、返回和名字绑定规则不变。
- CPython 执行模式不加载 Teaching VM 数据、不改其输出/字节码/执行轨迹。

## 8. 验收样例

| 输入 | 预期 |
| --- | --- |
| `a = [1, 2]` 后 `b = a`，再执行 `b[0] = 9` | `a`、`b` 都指向同一 ID，内容为 `[9, 2]`；修改前快照仍是 `[1, 2]` |
| `a = [1, 2]` 与 `b = [1, 2]` | 两个值相等，但对象 ID 不同 |
| `a = [None]`；`a[0] = a`；`print(a)` | 运行结束，显示有限的 `[[...]]`；对象图显示自引用边 |
| `d = {}`；`d['self'] = d`；`print(d)` | 运行结束，显示有限的 `{'self': {...}}`；对象图显示自引用边 |
| `d = {True: 'a', 1: 'b'}` | 一个条目，键按第一次插入保留，值更新为 `'b'` |
| `items[-1]` / `items[True]` | 分别读取末项 / 索引 1 |
| `items[99]` / `d['missing']` / `{[]: 1}` | 分别得到 IndexError、KeyError 和 unhashable-key 类诊断，含源码位置 |
| `def update(items): items[0] = 7` 后传入模块列表 | 函数帧中显示同一对象 ID，模块变量观察到修改 |
| 在历史预算压力下继续执行 | 最旧对象快照按预算淘汰，当前对象图完整，截断提示可见，复位可重新运行 |

## 9. 测试和发布门

- 单元测试分别覆盖 tokenizer/parser AST 与错误范围、编译指令顺序、对象引用、别名写入、列表/字典语义、循环安全格式化/相等、历史不可变性及资源预算。
- Playwright 使用生产构建和真实 Worker：编译并单步 `a/b` 别名样例，检查对象 ID 与修改前后历史；运行嵌套/循环对象；验证容器在 P7 函数中的引用；用键盘定位对象；切换历史、复位、切换引擎及中英文。
- 固定 Pyodide / CPython 3.14.2 对照共同支持的列表/字典输出、键冲突、索引和缺失键错误类别。对象 ID、对象图与教学历史仅与 Teaching VM 自身断言。
- 发布前运行应用 `pnpm run test:ci`、根 `pnpm run test:catalog`、`pnpm run build:site` 和文档链接/差异检查；生产 workflow 成功后，通过 Codex 内置浏览器实测 Cloudflare Pages 的两种模式。

## 10. 回滚

撤回 P8 语法、heap、对象快照与对象图 UI，恢复 `mini-vm-v3` 的标量/控制流/函数数据模型；真实 CPython 视图、站点壳和 P5–P7 的教学执行能力继续可用。由于 Worker 消息 envelope 不变，回滚只需随编译版本恢复对应客户端和 Worker 代码，不涉及持久数据迁移。
