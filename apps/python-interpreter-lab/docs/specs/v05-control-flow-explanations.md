# V5 规格：控制流与既有运行错误的连续解释

对应[执行可视化体验计划 V5](../visual-execution-plan.md#v5控制流与既有运行错误)。本阶段沿用 P6 的控制流指令、P9 的调试状态，以及 V3/V4 的快照驱动讲解播放；只增加教学解释，不改变 Python 子集或 VM 执行语义。

## 1. 目标

讲解播放应能说明教学 VM 实际执行了哪条分支、跳到哪里、循环为何回到循环头、逻辑表达式是否短路，以及运行错误发生时哪些值和状态仍未改变。每条说明必须对应实际执行指令和相邻 Worker 快照，不能由源码或指令名称猜测运行结果。

## 2. 项目约束与当前基础

- 应用使用 React、TypeScript、Vite、共享站点壳与双语文案；Teaching VM 在独立 Worker 中执行。沿用现有架构和依赖，不新增 Worker 消息、第三方依赖、路由或持久化状态。
- 教学指令集保持 `mini-vm-v5`。控制流、异常状态、帧、操作数栈、变量、对象堆、输出和执行位置仍以真实 Worker 快照为准。
- P6 已实现 `POP_JUMP_IF_FALSE`、`JUMP`、`JUMP_IF_FALSE_OR_POP`、`JUMP_IF_TRUE_OR_POP` 和 `FOR_ITER`；快照已有 `controlFlow` 摘要。P9 已实现断点、源码步进、Continue、Pause、Reset、历史和 5,000 条动态指令预算。
- V3/V4 已有最多 12 条的源码步进过渡限制、连续快照校验、调用/返回动画和真实错误诊断。V5 复用该限制和串行 Step Over 调度，不生成第二套执行或播放模型。
- 真实 CPython 视图保持独立，不能把教学 VM 的分支、栈或指令事件显示成 CPython 内部状态。

## 3. 事件与快照校验

所有事件须由连续的前后快照、执行计数和对应指令共同确认。无法确认时不播放该事件，保留 Worker 已确认的最终状态并显示现有诊断或“无法派生”说明。

| 事件 | 必须验证 | 显示信息 |
| --- | --- | --- |
| 条件分支 | `POP_JUMP_IF_FALSE`；前态活动帧 `pc` 指向该指令；条件值来自前态栈顶；后态同一帧恰好弹出该值；`controlFlow.kind/outcome/nextInstructionIndex`、指令目标及后态 PC 一致 | 条件的实际值、分支结果、实际下一条指令及其源码行；不执行的分支明确为“跳过” |
| 无条件跳转 | `JUMP`；前后帧身份不变；后态 PC 等于指令参数；栈、变量、堆和输出没有额外变化 | 跳转的实际目标；目标在当前指令之前时说明回到循环位置，否则说明跳至后续目标 |
| 短路 | `JUMP_IF_FALSE_OR_POP` / `JUMP_IF_TRUE_OR_POP`；前态左操作数和后态栈变化符合 `shortCircuit` 摘要；摘要的实际下一指令等于后态 PC | 左操作数、是否保留左值并跳过右侧、或弹出左值并开始求值右侧；最终表达式值只在快照能确认时显示 |
| 迭代 | `FOR_ITER`；前态栈顶为迭代器；后态 `iteration` 摘要与指令退出目标及 PC 一致；有值时只产生真实的当前迭代值并更新迭代器，无值时只弹出迭代器并退出 | 实际产生的值及下一条指令，或迭代结束和退出目标；循环变量的绑定仍由后续 `STORE_NAME` 单独说明 |
| 指令运行失败 | 单条指令的执行计数增加 1；诊断为 runtime 且故障索引/源码范围匹配该指令；前后帧 ID、各帧 PC/栈/绑定、堆和输出均未发生该失败指令不应造成的提交 | 实际诊断、失败指令和故障前操作数；明确失败操作未提交。调用相关诊断继续使用 V4 `call-rejected` |
| 执行预算耗尽 | 执行计数不变；诊断为 `instruction-budget-exceeded`；故障索引等于尚未执行的下一条指令；执行位置、帧、栈、绑定、堆和输出保持不变 | 明确指出预算耗尽、下一条指令未执行，并定位其源码位置 |

- 分支结果和目标使用 `controlFlow`、快照 `pc` 及编译结果指令范围交叉校验；不得仅根据布尔值或编译器生成形态猜测分支方向。
- `JUMP` 的目标索引是教学指令索引，不是 CPython offset。无法映射到有效源码行时只显示指令位置。
- 短路必须区分 `and` 和 `or` 的保留左值情形。短路路径不得显示右侧表达式求值或其副作用；继续求值路径不得提前显示右侧结果。
- 错误事件不伪造成功的赋值、容器更新、输出、函数帧或返回值。若失败指令前的同一源码步已有成功指令，已验证的过渡仍按序显示，然后显示失败。
- 对比历史有缺口、状态被裁剪或前后快照不一致时，不从源码重建中间状态。仍显示可用最终快照和现有 Worker 诊断。

## 4. 展示与调度

- 在现有“执行前 / 执行后”讲解卡中显示控制流和错误说明；活动帧、操作数栈、变量、对象堆、输出和当前位置继续绑定同一条实际快照。
- 目标定位使用目标教学指令的源码范围；不执行用户代码、不读取 Worker 外部状态，也不将一个源码行内的后续状态提前到当前过渡。
- 循环中的每一次实际决策依序展示。复用每个源码步最多 12 条过渡的上限；被省略事件必须计入省略数，最终快照始终可见。调用/返回及控制流/失败边界在上限内优先于普通算术/数据过渡；边界本身超过上限时，按原顺序保留开头与结尾边界并报告省略数。
- 历史浏览只读，不启动讲解或推进 VM。Step Into/Over/Out、断点、Continue、Pause、Reset 与 V3/V4 既有语义保持不变。暂停必须等待 Worker 在指令边界确认；取消、源码编辑、重新编译、引擎切换或重置不得留下旧过渡。
- 中英文词条通过共享语言状态提供。减少动态效果时保留相同原因、目标和错误信息；键盘操作、焦点、320px 窄屏内部滚动继续可用。

## 5. 支持错误边界

- 解释 Teaching VM 当前可产生的运行时诊断，不引入新的异常类型或异常控制流。包括名称未定义/未绑定、类型不匹配、下标越界、字典键不存在、range 步长为零、整数/字符串/容器/输出限制和教学指令预算耗尽等既有类别。
- 对已由 V4 解释的未定义/不可调用目标、参数数量、调用帧或名称预算导致的失败，继续使用 `call-rejected`，不得重复显示成通用成功调用事件。
- 只有前后状态能证明失败操作未提交时才显示操作数“保留”或状态“未改变”。未知错误代码、内部 VM 不变量错误或存在状态变化的错误只显示 Worker 的实际诊断和最终快照，不做猜测性动画。
- 不实现 `try`、`except`、`raise`、异常捕获/展开、跨帧异常返回或新的运行时恢复行为（这些属于 P10 或后续决策）。错误后仍按 P9 终态规则要求 Reset。

## 6. 验收标准

1. `if/elif/else` 的真、假路径都能显示实际条件值和下一个执行位置；未选择分支明确标为跳过。
2. `while` 示例能按序显示条件决策与向前/回边跳转；`for ... in range(...)` 能显示迭代值和最终退出，零次迭代不伪造循环变量绑定。
3. `and` 与 `or` 均覆盖短路和继续求值；被跳过右侧的 NameError/打印副作用不出现，表达式按 Python 规则保留实际操作数。
4. 类型错误、失败下标读取/赋值、缺少字典键、零步长等路径显示真实诊断；失败前的操作数仍可见，绑定、堆或输出没有伪提交。
5. 5,000 条预算耗尽时说明下一条指令没有执行；可 Reset 后重跑。循环断点每次命中、Continue 只跳过当前命中一次，历史继续先回执行头，Pause/Reset 不产生过期动画。
6. 超过 12 条过渡的循环仍受限；调用/控制流/错误优先规则、原始顺序、省略数和最终状态一致。
7. 中英文、减少动态效果、320/768/1024/1440px、真实 Worker 和现有 V3/V4 场景通过回归验收；真实 CPython 数据和语义不变。

## 7. 验证命令

- 聚焦单测：`pnpm --dir apps/python-interpreter-lab exec node --import tsx --test tests/teaching-animation.test.ts`。
- 教学 VM / 观察回归：`pnpm --dir apps/python-interpreter-lab exec node --import tsx --test tests/teaching-vm-runtime.test.ts tests/teaching-observation.test.ts tests/teaching-debugger.test.ts`。
- 应用全量：`pnpm --dir apps/python-interpreter-lab run test:ci`；浏览器测试使用真实 Teaching VM Worker，不用 mock 替代。
- 根目录：`pnpm test:catalog`、`pnpm build:site`、`git diff --check`。
- 发布后用 Codex 内置浏览器实测 Teaching VM 分支/循环/短路/失败解释和真实 CPython 的 AST、字节码及运行输出；记录 workflow 与线上结果。

## 8. 风险与回滚

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 控制流摘要和 PC 不一致 | 演示跳错行或讲错分支 | 必须同时校验 opcode、摘要、目标参数和前后态；不一致时退化为静态最终状态 |
| 循环过渡超过容量 | 演示积压、丢失退出原因 | 保留现有 12 条上限；按规则选择边界并显示省略数 |
| 把失败操作展示成成功 | 用户误解变量或容器已改变 | 只对结构化未提交状态显示失败过渡；和现有诊断/快照对照 |
| 预算耗尽缺少执行前快照 | 无法确认下一条未执行指令 | 不动画；保留诊断面板与执行位置，标记过渡不可派生 |

回滚仅撤销 V5 控制流/失败过渡和双语说明，保留 V4 调用/返回动画、P6/P9 教学 VM 行为、历史、断点和真实 CPython 视图。
