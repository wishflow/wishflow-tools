# V3 规格：操作数栈与对象引用动画

## 1. 目标与依据

本阶段依据[体验实施计划 V3](../visual-execution-plan.md#v3操作数栈与对象引用动画)，在 V2 统一观察位置和快照差异上增加教学 VM 的“讲解播放”。它用已记录的相邻快照解释值如何入栈、参与运算、完成名字绑定、创建容器或修改容器条目。

成功标准：播放 `b = a` 时用户看到的是同一个对象引用被绑定到另一个名字；播放 `b[0] = 9` 时用户看到该对象的条目改变而对象身份不变；播放 `b = [2]` 时用户看到新对象创建后再绑定。展示结束时，所有运行现场回到 Worker 已确认的最新快照。

## 2. 用户行为与控制语义

### 2.1 独立的“讲解播放”

- 教学模式增加“讲解播放 / 暂停讲解”控件。讲解播放是前端调度的连续源码步进，不调用 Worker 的自动 `run`；它依次请求 `stepSource('over')`，等待 Worker 对本次源码步进的响应，再播放该步有界历史记录中的动作，动作展示结束后才请求下一步。
- 现有“运行 / 继续”和慢、标准、快三档保持 Worker 自动执行语义。速度选择只影响 Worker 的 Run/Continue，不影响讲解播放的固定演示时长，也不改变单步或断点行为。
- 讲解播放仅在教学 VM 已编译、位于执行头、状态为 ready/paused 时可启动；从历史观察位置启动前必须由用户回到执行头。播放期间禁用单步、源码步进、Run/Continue、断点编辑和重复启动，避免两个推进者竞争。普通 Pause 不与讲解播放重复展示。
- 每次源码步进完成后，调度器只消费该步执行期间 Worker 实际记录的连续快照。其间不重放 Python、不重新执行指令、不根据 opcode 猜测执行结果。
- 如果本步在断点、用户暂停、正常结束或运行错误处结束，讲解播放停止在该真实 Worker 响应；不得自动越过断点、失败或终态。

### 2.2 暂停、取消与重置

- 用户在 Worker 执行源码步进时按“暂停讲解”，前端立即停止发起新请求并向 Worker 发送 Pause；界面只有收到 Worker 的 paused/终态快照后才标记执行停止。不能只冻结 CSS 动画并声称暂停成功。
- 用户在 Worker 已确认一步完成、前端正在展示动作时按“暂停讲解”，前端取消当前展示定时器并停止后续源码步进；该步的 Worker 已处于 paused，界面恢复到该步最后一个已确认快照。
- Reset、源码编辑、重新编译、引擎切换及卸载都使当前播放代次失效，清除动画帧、定时器和待展示队列。旧代次的 Promise/定时器不得更新新会话 UI。
- 快速重复点击播放、暂停或 Reset 具有幂等效果；同一时刻最多存在一个未完成的 Worker 源码步进请求与一个展示计时器。

### 2.3 动作说明

动作只使用执行前后快照、对应教学指令和教学 VM 的稳定对象 ID。没有精确可识别的已记录动作时，退化为静态快照，不补造动画。

| 实际教学指令 | 展示语义 | 可视区域 |
| --- | --- | --- |
| `LOAD_CONST`、`LOAD_NAME` | 常量/名字的实际值被压入当前活动帧栈顶 | 当前活动帧、值栈顶 |
| `UNARY_*`、`BINARY_*`、`COMPARE_OP`、`BINARY_SUBSCR` | 已记录操作数被消费，实际结果出现在栈顶；不在 UI 重算表达式 | 当前活动帧值栈 |
| `STORE_NAME` | 栈顶实际值被绑定到对应名字；容器显示对象 ID 与已有引用一致 | 当前活动帧栈与变量绑定 |
| `BUILD_LIST`、`BUILD_MAP` | 快照中新出现的对象 ID 被创建，并由栈顶引用 | 值栈与堆对象 |
| `STORE_SUBSCR` | 同一对象 ID 的对应列表项/字典项发生实际变化 | 堆对象与条目 |

- 其他指令、循环/分支、函数调用/返回、输出和错误在 V3 不做运动演示；它们仍按 Worker 记录更新静态快照。函数调用/返回动画属于 V4，控制流动画属于 V5。
- 空栈、重复标量、相同显示文本、别名及循环引用均按帧 ID、栈位置、变量身份和对象 ID 识别，不按格式化显示文本猜测身份。循环引用继续使用既有安全快照格式。
- 一次动画最多突出显示一个目标堆对象和两个操作数；不复制或重新排布堆对象。名字/栈/堆区域只在已有位置高亮，动画不跨区域创建会漂移的对象副本。

## 3. 快照与动画边界

- V3 的前态、后态、指令身份及值来自 `TeachingVmHistory` 中相邻且连续的 `TeachingVmSnapshot` 与当前 `TeachingCompileResult`。动作为纯派生的展示数据，不写入 VM，也不增加 Worker 消息、VM 状态字段、历史 DTO 或效果事件协议。
- 动画期间所有运行现场面板消费同一个正在展示的历史快照；历史控制和 VM 执行状态仍由 `useTeachingVm` 管理。动画帧只是短暂选择一条只读历史记录的渲染时刻，不构成可写的第二个历史游标或第三种 VM 状态。展示结束/暂停后回到最后一条 Worker 已确认快照。
- 起始快照缺失、历史在本步前态处已裁剪、`stepIndex` 不连续、执行计数差异不为 1、对应指令缺失或帧身份发生变化时，该过渡不播放。界面显示静态后态，并以中英文明确说明无法从现有记录还原完整过渡。
- 每个源码步进最多排队并播放 12 条实际指令过渡，按执行顺序取前 12 条；更多过渡合并到最终状态，并标出被省略的实际指令数。历史仍遵循既有 500 快照上限，不因播放扩容；播放处理范围不超过该上限。
- 每条可动画过渡的固定演示时间为 240ms；过渡高亮最多 160ms，余下时间展示稳定后态。减少动态效果时禁用移动/渐变，保留同一动作说明和最终快照；讲解播放仍按同一序列运行。
- 动画不创建对象副本、不触发自动滚动、不改变源码焦点；堆对象位置稳定。用户可继续使用现有对象引用按钮定位相关堆对象。

## 4. 界面、无障碍与双语

- 使用当前 SourcePanel 的控件层级和共享外壳样式；讲解播放按钮在教学执行控制区。播放中按钮显示“暂停讲解”，状态和等待 Worker 确认的提示使用文本表达，不仅靠颜色或动效。
- 播放/暂停、等待响应、展示中、因断点/终态/错误停止、省略过渡和基线不可用均有中英文文案。动作说明使用 `aria-live="polite"`，不为每个 CSS 帧制造屏幕阅读器噪声；键盘可启动/暂停，控件有可见焦点与明确名称。
- 所有新增词条进入共享 `registerMessages` 双语词条，不添加语言状态或语言控件。
- 在 320、768、1024、1440 CSS px 下，操作控件和说明自然换行；页面不产生横向滚动。栈和堆继续使用各自现有滚动容器。

## 5. 非目标与禁止事项

- 不改变真实 CPython 页、Pyodide 版本/加载策略、教学 VM 支持语法、指令预算、Worker 自动运行速度、断点/Step Over/Pause/Reset 语义或 V2 历史差异。
- 不新增 Worker 协议、VM 中间状态、动画效果 DTO、全局状态库、物理布局引擎、动画依赖或超出 12 条的前端待播放队列。
- 不扩展 500 快照、256 堆对象或 2048 容器项预算；不通过扩大历史来补足动画数据。
- 不重建真实对象图、不宣称动画路径等价于 CPython 内存分配、垃圾回收或真实字节码栈行为。教学快照仍只代表 `mini-vm-v5` 的教学模型。

## 6. 验收与验证

1. **动作派生**：对真实教学历史验证常量/名字入栈、算术结果、变量绑定、列表/字典创建和下标写入；`b = a` 保持同一 `objectId`，`b[0] = 9` 修改同一堆对象，`b = [2]` 新建对象并更新绑定。
2. **边界退化**：空栈、重复值、列表/字典引用、循环引用、帧变化、非数据指令和历史截断均不产生猜测动作；未支持动画时静态最终快照与 VM 完全一致。
3. **串行调度**：第二次 Step Over 只能在本次 Worker 响应并完成展示后发生；连续播放不会并发发请求。快照多于 12 条时仍有界并准确报告省略数。
4. **暂停与清理**：分别覆盖 Worker 执行中暂停、展示中暂停、断点、运行结束、错误、Reset、编辑、编译、引擎切换和重复点击；Worker 确认前不报告暂停成功，旧代次不能回填 UI。
5. **速度与快照一致性**：Run/Continue 的速度设置不改变讲解播放时长；播放中的栈/绑定/堆/源码定位属于同一展示快照；动画结束后与真实执行头快照一致。
6. **体验**：Playwright 覆盖算术主例、别名/列表变更主例、暂停/Reset/断点、键盘、中英切换、减少动态效果，以及 320/768/1024/1440px。
7. **命令**：

   ```sh
   pnpm --dir apps/python-interpreter-lab run typecheck
   pnpm --dir apps/python-interpreter-lab run test:unit
   pnpm --dir apps/python-interpreter-lab run build
   pnpm --dir apps/python-interpreter-lab run test:e2e
   pnpm test:catalog
   pnpm build:site
   ```

8. **发布验收**：通过本地验证后提交、合并 `master`、推送并等待 CI/CD。使用 Codex 内置浏览器访问生产站，实测默认教学模式、单次和连续讲解播放、Worker 确认暂停、对象别名/原位修改/重新绑定、历史静态观察和真实 CPython 路径；发布未完成前不标记阶段完成。

## 7. 回滚

撤回讲解播放调度、动画过渡说明和新增样式/文案，恢复 V2 静态历史差异和既有 VM 控件；保留 P5–P9 VM、Worker、历史、对象图和协议不变。
