# V4 规格：函数调用、参数与返回的连续解释

对应[执行可视化体验实施计划 V4](../visual-execution-plan.md#v4函数调用参数与返回的连续解释)。本阶段建立在 V3 的快照驱动讲解播放和 P7 教学 VM 帧模型上；实现只解释真实记录的函数帧变化，不修改 Python 子集或 VM 执行语义。

## 1. 目标

讲解播放遇到函数调用时，连续显示实参从调用方求值栈进入新函数帧的形参绑定；函数返回时，显示当前帧退出、返回值进入调用方求值栈。递归调用显示各自不同的帧身份、参数和返回位置，使用户能够区分同名函数的多个活动调用。

## 2. 项目约束与当前基础

- 沿用 React、TypeScript、Vite、`@wishflow/site-shell`、共享语言状态及 Teaching VM Worker；不增加依赖、路由、服务或 Worker 消息。
- 教学指令集仍为 `mini-vm-v5`。V4 是展示能力，不升级指令集，也不声称教学帧等同 CPython 内部帧。
- P7 已实现顶层函数、必需位置参数、显式帧栈、递归、返回续行以及帧/历史快照。V3 已实现相邻快照派生过渡和前端串行 Step Over 播放。
- Worker 快照和已编译程序是唯一数据源。表现层只读取历史快照、执行指令、函数元数据和实际诊断；不得重新执行表达式或自行推测局部状态。
- 使用现有 `src/teaching-vm/animation.ts`、`src/components/TeachingAnimationPanel.tsx`、`src/components/TeachingVmPanel.tsx` 和双语词条模式；新增逻辑保持小型纯函数，避免扩大现有大面板的职责。

## 3. 事件推导约定

所有过渡都必须基于连续的相邻快照，并按照对应教学指令验证栈与帧变化。历史缺口、快照不一致或无法确认的状态不得生成成功动画；展示最终 Worker 快照并明确说明无法派生。

| 事件 | 必须验证的真实变化 | 展示内容 |
| --- | --- | --- |
| 成功调用 | 最近执行指令为 `CALL_FUNCTION`；帧栈只增加一个新函数帧；原帧身份及调用续行正确；实参数量与函数形参匹配；新帧局部值与实参逐一相等 | 调用方/被调方帧 ID、函数名、调用位置，以及按顺序排列的“实参 → 形参”绑定；容器值只显示稳定对象 ID，不展开或复制对象 |
| 成功返回 | 最近执行指令为 `RETURN_VALUE` 或 `RETURN_NONE`；恰好退出一个活动函数帧；调用方身份及返回续行正确；调用方栈只增加一个与返回值一致的值 | 返回帧 ID → 调用方帧 ID、函数名及实际返回值；随后仍按真实 `STORE_NAME` 指令单独展示变量绑定 |
| 调用拒绝 | 故障指令是 `CHECK_CALL_TARGET` 或 `CALL_FUNCTION`；Worker 诊断对应当前指令；前后快照没有新增帧 | 显示目标/调用失败和真实诊断，并明确没有创建被调帧；不显示参数绑定或成功入帧 |

- 调用和返回过渡保持历史中的原始顺序。递归中的相同函数名始终由各自帧 ID 区分；参数相等或对象别名不能合并成一个帧。
- `None` 返回（包括裸 `return` 和自然结束）按实际 `None` 值显示；返回列表/字典时保留原对象 ID。
- 已有 V3 数据动作继续沿用每个源码步最多 12 条过渡的限制。超限时优先保留调用、返回和拒绝边界；边界事件不超过 12 条时全部保留，空间不足时保留历史开头与结尾的边界，再按原顺序补入普通数据过渡。显示省略数和最终快照；不得为展示而扩大 Worker 历史或制造额外中间状态。
- 连续历史中发生调用/返回后仍可继续推导后续动作；错误发生前已验证的过渡可以依序展示。错误指令本身不伪装成成功过渡，最终错误状态使用 Worker 诊断。

## 4. 讲解呈现

- 继续使用 V3 的“执行前 / 执行后”展示阶段和固定演示时长。动画期间值栈、活动帧、变量、堆及帧栈必须来自该过渡的同一份快照。
- 调用演示在执行前标出调用方待传递的实参；执行后显示新帧及形参值。返回演示在执行前标出返回帧中的值；执行后显示调用方新增的栈顶值。来源和目标同时使用帧 ID 与函数名标识。
- `TeachingAnimationPanel` 提供可读的调用路线和绑定/返回详情；帧列表与值栈使用现有实际活动帧状态，高亮不得改变快照或对象位置。
- Step Into、Step Over、Step Out 和讲解播放继续遵循 P9/V3 既有停靠语义。浏览历史只改变观察状态，不启动动画或推进 VM；从执行头重新开始讲解时才生成新过渡。
- 所有新文案经共享语言状态提供中英文版本。新增动态提示支持键盘用户和可访问名称；`prefers-reduced-motion` 下保留相同动作信息和最终状态。

## 5. 边界

- 不改变编译器、帧创建/销毁、名字解析、参数规则、预算、断点、历史协议或 Worker API。
- 不实现默认/关键字参数、闭包、函数值、异常处理、单步动画控制或新的运行时模型。
- 不将快照解释成真实 CPython 帧、调用约定或 opcode；不按函数名推测参数，不用显示字符串推测对象身份。
- 复用 V3 的动画队列与上限，不引入第三方动画、图布局或状态管理依赖。

## 6. 验收与验证

### 行为验收

1. `def bump(xs): xs[0] = 9; return xs[0]` 调用中，动画显示参数 `xs` 与调用方列表具有相同对象 ID；返回值 `9` 先进入调用方栈，后续绑定由独立指令呈现。
2. `fact(3)` 的递归帧具有不同 ID、正确参数和返回位置；返回按 LIFO 顺序逐帧回到调用方，不把同名帧合并。
3. 显式 `return`、裸 `return` 和自然结束分别按 Worker 记录的值（含 `None`）显示；列表/字典返回保留对象身份。
4. 参数数量、调用目标、帧预算或名称预算错误不会显示成功入帧。调用失败提示只出现在可由故障指令和前后帧快照确认的情形。
5. 不连续历史、历史回放、暂停、Reset、编辑源码、切换引擎和减少动态效果均不制造幽灵帧、错误返回值或过期动画。

### 测试命令

- 聚焦单测：从仓库根目录运行 `pnpm --dir apps/python-interpreter-lab exec node --import tsx --test tests/teaching-animation.test.ts`。
- 应用全量验证：`pnpm --dir apps/python-interpreter-lab run test:ci`。
- 仓库入口与站点：`pnpm test:catalog`、`pnpm build:site`。
- Playwright 必须经应用生产构建/现有测试服务器和真实 Teaching VM Worker 覆盖函数调用、递归帧、返回值、暂停/历史和中英文；不能仅以 mock 或纯函数测试替代。
- 发布后通过 Codex 内置浏览器实测公开页面的 Teaching VM 函数讲解与真实 CPython 模式，并记录 Actions、线上结果和文档副本。

## 7. 明确不做

- 不在本阶段增加控制流动画（V5）或真实 CPython 代码片段对照（V6）。
- 不改变 P7 已确定的最多 64 个活动帧和 P6 的 5,000 条动态指令预算。
- 不为避免展示省略而调高快照上限、加速 Worker 或压缩真实调用记录。
