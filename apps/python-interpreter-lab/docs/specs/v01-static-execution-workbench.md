# V1 规格：静态执行工作台

## 1. 目标与状态

把教学 VM 从当前“先看 AST/指令、再向下找运行状态”的页面，调整为以源码和运行现场为主的静态工作台。用户在不播放动画的情况下，可以依据同一份教学快照辨认当前调用帧、操作数栈、变量绑定、可变对象及其稳定对象编号；编译材料移至按需展开区域。

本规格对应[体验实施计划 V1](../visual-execution-plan.md#v1静态执行现场与默认教学入口)。总体体验方向已确认；本阶段仅使用现有教学 VM 数据和控制协议。

## 2. 用户行为

### 2.1 默认进入教学模式

- 页面首次打开时选择“教学 VM / Teaching VM”。不自动编译、运行或改变示例源码。
- “真实 CPython / Real CPython”继续作为明确可选项；切换引擎仍沿用现有清理逻辑，切回后需按原控件重新分析、执行或编译。
- 语言仍由 `@wishflow/site-shell` 提供；引擎选择不新增持久化状态。

### 2.2 教学工作台层级

编译后，教学视图按以下顺序组织内容：

1. **源码与控制**：保留现有编辑器、编译、单指令、Into/Over/Out、Run/Continue/Pause/Reset、速度和断点行为。
2. **运行现场**：把历史位置、当前/下一/失败指令及其源码位置、活动帧和状态放在主要视觉区；Frame、操作数栈、变量、输出与对象堆共同读取 `snapshot`。
3. **编译材料**：AST 和完整教学指令/断点区置于可展开的原生折叠区，默认收起。标题与键盘操作可访问；展开后保留源码联动、现有断点按钮和状态标记。

未编译时仍显示现有空状态；不因进入默认模式而启动编译。CPython 结果页结构和控件行为不随教学布局调整。

### 2.3 静态运行现场

| 内容 | 展示规则 |
| --- | --- |
| 当前动作 | 按快照显示实际最后执行、下一条或失败的教学指令及其源码位置。未执行时显示首条待执行位置；已结束时保留最后记录。不得根据源码补造指令或加入 V2 的一句话变化说明。 |
| 活动帧 | 活动帧有清晰标签和视觉强调；其调用位置、返回位置、变量和操作数栈属于该帧。模块帧与函数帧使用相同的状态来源。 |
| 其他帧 | 保持可读但从属的层级。展开/收起或检查非活动帧只改变面板呈现，不选择/切换 VM 帧，不发 Worker 请求，也不改变历史游标或执行头。 |
| 操作数栈 | 与变量区分标题和容器；展示槽位顺序与 TOP 标记。空栈仍显示明确空状态。栈顺序沿用快照顺序，最后一个元素为栈顶。 |
| 变量绑定 | 按帧展示名称和当前值；未绑定局部名仍显示现有提示。变量名称不能用截断后标签作为身份。 |
| 容器引用 | 对象值与堆卡片显示相同、稳定的 `#objectId`；别名显示相同编号，点击引用仍可定位对象。对象编号仅代表教学 VM 对象身份，不代表地址或真实 CPython 对象。 |
| 输出与错误 | 使用当前选中快照的输出、诊断与失败位置；保留历史浏览和执行头语义、输出上限说明。 |

“当前动作”仅复用教学指令索引、源码范围和快照状态；不增加解释器 effect/transition DTO，不重新执行程序，不从 UI 推导变量变化。

### 2.4 按需查看 AST 和完整指令

- 默认折叠 AST 与完整指令，避免它们压过运行现场。
- 用户可用 `<details>/<summary>` 或等价的原生、可访问结构查看。两处默认关闭，状态仅为本地界面状态。
- 教学 AST 仍标明教学指令集版本。完整指令表保留行/指令断点、当前/下一/失败高亮、源码定位与断点命中提示。
- AST/指令展开与收起不得触发编译、运行、重置或改变历史位置。
- 教学 Token 不加入；CPython Tokens/AST/字节码与真实执行结果继续由真实 CPython 入口查看。

## 3. 数据与架构边界

- 仅消费现有 `TeachingCompileResult`、`TeachingVmSnapshot`、`TeachingVmHistory`、诊断和断点 props。
- 执行事实只取自 `useTeachingVm` 的 snapshot/history 和当前编译程序。展示层不维护第二个执行游标，也不修改活动帧。
- 不更改 Mini VM 语法、`mini-vm-v5` 指令集、Worker DTO、历史预算、断点语义、运行步进语义或 Pyodide 加载策略。
- 真实 CPython 页面保留 Tokens、真实 AST、代码对象、字节码、真实执行轨迹和当前操作。
- 继续沿用应用 CSS、React 组件和共享语言消息；不新增依赖、路由、全局状态管理或布局库。

## 4. 布局与无障碍

- 桌面视口下，源码编辑与运行现场并排；运行现场先于 AST/完整指令。页面宽度不足时自然改为纵向布局。
- 运行现场用清晰区域标题区分当前动作、帧、栈、绑定、堆、输出和历史；不以颜色作为唯一含义。
- 在 320、768、1024、1440 CSS px 下检查无整页横向溢出；长源码、指令表、对象内容只能在对应容器内滚动或换行。
- 所有交互使用原生按钮、链接、选择框或 details/summary；具备键盘焦点样式、可读名称和状态文本。
- 遵守 `prefers-reduced-motion`；本阶段不新增动画。
- 中英文标签、帮助正文和现有控件一致，不增加第二套语言状态。

## 5. 非目标

- 不交付 V2 的历史语句分组、前后变化解释、统一观察协议或变化动画。
- 不新增教学 Token，不同步教学与 CPython 的逐条 opcode。
- 不更改 CPython 结果页布局、不增加新的示例系统、不改源代码默认内容或自动执行时机。
- 不调整 VM 执行协议、预算、快照采集、引擎恢复、发布配置或 Worker 资源托管。

## 6. 验收与验证

1. **默认入口**：初次打开选择教学 VM；教学 Worker Ready 后仍未编译程序；可切到真实 CPython 并使用原分析/运行入口。
2. **同屏静态语义**：编译并逐步运行别名、下标修改和 `bump(xs)` 样例后，可在教学运行现场同时找到源码、当前指令位置、帧、栈、变量绑定、对象堆和输出。
3. **对象身份**：`a` 与 `b` 绑定同一列表时显示相同 `#id`；修改条目仍定位同一卡片；重新绑定后可辨认不同的当前对象。
4. **帧语义**：函数内 `xs` 和模块变量 `a` 的对象编号相同；活动帧明确；查看/收起模块帧不会改变活动帧、历史位置、下一条指令或输出。
5. **指令细节**：AST 与完整指令默认折叠；手动展开后能正常查看 AST、源码链接和 P9 断点行为，收起后当前运行状态不变。
6. **原有调试**：Into/Over/Out、单指令、断点命中、Run/Pause/Continue/Reset、历史只读、输出及错误显示继续通过既有回归。
7. **中英和响应式**：共享语言切换后教学/CPython 两种模式均可读；320/768/1024/1440px 页面无横向溢出；键盘可展开编译材料并操作现有控件。
8. **项目验证**：应用 `typecheck`、单元测试、构建、Playwright，根目录 `pnpm test:catalog` 和 `pnpm build:site` 通过；部署后按根 README 公布的站点地址实测教学默认入口及 CPython 切换。

项目命令：

```sh
pnpm --dir apps/python-interpreter-lab run typecheck
pnpm --dir apps/python-interpreter-lab run test:unit
pnpm --dir apps/python-interpreter-lab run build
pnpm --dir apps/python-interpreter-lab run test:e2e
pnpm test:catalog
pnpm build:site
```

## 7. 回滚

回滚本阶段提交可恢复原默认引擎和原面板顺序。V0 帮助入口及两种引擎继续保留；若回滚，也同步恢复与实际界面一致的双语指南。
