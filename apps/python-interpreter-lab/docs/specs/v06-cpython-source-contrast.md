# V6 规格：真实 CPython 源码片段对照

## 1. 目标

让用户从教学 VM 当前编辑的源码范围进入真实 Pyodide/CPython 观察，检查真实 AST、代码对象、字节码以及用户主动运行后记录的执行事件和结果。页面明确说明教学模型与 CPython 实证之间的差异，不把源码范围映射说成指令一一对应，也不把 CPython 字节码称为机器码。

本阶段只组合已有编译、运行、回放、源码映射和引擎切换能力；不扩展 Python 子集，不新增运行协议或依赖。

## 2. 基线与前置

- 体验基线：V2 统一观察位置与源码映射；V3/V4 教学状态可以继续独立演进。
- 真实运行时：现有固定 Pyodide 314.0.7，页面展示运行时报告的 CPython 版本（当前为 3.14.2）。所有运行时行为由该浏览器内 Pyodide/CPython 实测，不以系统 Python 结果代替。
- 两种引擎分别拥有自己的编译结果、执行状态和历史；切换时沿用 `App.tsx` 现有清理规则。
- 默认页面仍为教学 VM。真实 CPython 入口仍可从“执行视图”直接切换。

## 3. 交互行为

### 3.1 从源码范围进入真实 CPython

| 条件/动作 | 规定行为 |
| --- | --- |
| 用户在教学模式中选中一段非空源码 | 现有 `SourceLink.range` 是 JavaScript UTF-16 源码偏移；范围可来自编辑器或教学 AST/指令定位 |
| 选择范围为空、来源没有可靠位置、源码超长或 Pyodide 尚未就绪 | 不可启动对照；控件禁用并保留可理解的说明 |
| 点击“在真实 CPython 中检查所选范围” | 保留完整源码和所选范围；取消教学讲解播放；按现有规则清理教学 VM 会话与旧 CPython 执行结果；切换到真实 CPython 并调用现有 `analyze(source)` |
| 分析成功 | 所选范围继续用于真实 Tokens、AST 和字节码的范围联动；跨引擎只共享源码文本与所选范围，不共享执行头、帧、栈、堆或快照 |
| 分析完成后 | 不自动运行用户源码，不产生执行轨迹；用户必须另行点击“运行 Python” |
| 分析失败或运行时不可用 | 保留源码；显示现有真实诊断/重试入口。不得回退为教学 AST 或合成 CPython 指令 |

入口只在教学模式呈现。无需选中范围时，用户仍可使用顶部“执行视图”切换；该普通切换继续清理来源链接和会话，不自动分析。

点击入口后自动分析**整份源码**，不是把选区切成独立 Python 程序。提示中须说明选区仅供联动；源码上下文、缩进和模块语义都保持完整。教学 VM 不支持但真实 CPython 支持的合法语法可以借此检查。

### 3.2 CPython 实证说明

真实 CPython 结果区域增加双语、键盘可达的概念说明，至少表达以下内容：

1. 当前显示的 Tokens、AST、代码对象和字节码由页面标示的固定 Pyodide/CPython 实际生成；源码范围由真实位置元数据映射。
2. 编译优化可能合并或折叠表达式。例如 AST 保留 `1 + 2`，而字节码可能直接载入 `3`；不得根据源码补造未生成的操作码。
3. 一个源码范围可能对应零条、一条或多条指令；多个源码范围也可能映射到同一行事件。只显示运行时实际报告的位置和已记录内容。
4. 执行轨迹来自现有 `sys.settrace()` 记录的调用、行、异常与返回等事件。行事件按 CPython 实际粒度记录；轨迹不代表逐 opcode 单步，回放只浏览记录，不重新执行。
5. Python 字节码不是 CPU 机器码。本应用的 Pyodide 将 CPython 运行时提供在 WebAssembly 环境中；本页面不显示逐条 Wasm/CPU 指令，也不承诺每条 Python 字节码到机器码的对应关系。

概念图使用如下方向，图旁明确它是运行环境关系而非逐指令翻译：

```text
Python 源码 ──CPython 编译──> AST / code object / CPython 字节码
                                           │
                                   由 CPython 运行时解释
                                           ▼
                         Pyodide 中编译到 WebAssembly 的运行时
                                           ▼
                              浏览器 Wasm 引擎 / 宿主 CPU
```

不在真实 CPython 面板添加教学 VM 的操作数栈、教学帧、对象身份或动画。

## 4. 源码映射与正确性

- 按现有 `createSourcePositionIndex`、`astNodeSourceRange`、`instructionSourceRange` 和 `rangesOverlap` 处理范围。
- CPython AST/字节码列位置为 UTF-8 字节偏移；内部选区为 JavaScript UTF-16 偏移。中文、emoji、CRLF 和换行边界不得错位。
- 对常量折叠示例，AST 可继续显示原表达式；字节码表只显示真实 `dis` 结果。范围没有匹配项时使用现有“没有匹配”的状态，不推测缺失指令。
- 嵌套函数仍由真实嵌套 code object 展示；切换 code object 不丢弃选区。
- 执行轨迹仅用实际 trace 事件来源位置；不按行号生成 opcode 记录，也不将教学 VM 的源码步进结果合并进 CPython 历史。

## 5. 语言、可访问性与布局

- 所有新增界面文案通过现有 `locales.ts` 和共享站点语言状态提供中英文；帮助正文同步更新 `usage.zh-CN.md` 与 `usage.en.md`。
- 按钮有明确名称和 `disabled` 原因提示；键盘可触发且焦点可见。概念说明可用语义化 `details/summary` 或等价可访问结构。
- 在 320、768、1024、1440px 视口不引入页面横向溢出；源码与图示允许在自身容器换行/滚动。
- 不新增动画；遵守现有 `prefers-reduced-motion` 约束。

## 6. 验收与验证

| 场景 | 预期 |
| --- | --- |
| 教学 VM 选中合法片段后打开对照 | 同一完整源码进入 CPython，自动分析；真实 AST/字节码就绪，所选范围继续高亮；没有执行事件或输出 |
| 教学语法不支持、但 CPython 可编译的合法语法 | 教学 VM 保持其“不支持”边界；对照入口由真实 CPython 编译且不运行 |
| `value = 1 + 2` | 实际 CPython AST 保留二元表达式；真实字节码体现目标版本优化，不虚构 `BINARY_OP` |
| 函数和嵌套函数 | 真实 code object 层级与实际指令可查看；选区跨 code object 仍可联动 |
| 中文及 emoji 位于被选语句之前 | CPython UTF-8 位置换算到 textarea 的 UTF-16 范围准确 |
| 运行真实 CPython 样例 | 用户另行点击运行后，最终输出与真实轨迹一致；事件滑块/回放不增加执行次数 |
| 事件位置、报告精度或优化结果缺少 | 页面明确显示已有记录粒度/无匹配，不推断逐条指令或不存在的数据 |
| 中英文与窄屏 | 两种语言完整；320/768/1024/1440px 无页面横向溢出，控件可键盘操作 |

必须运行固定 Pyodide 的 Playwright 浏览器测试；本机 Python 只可辅助理解，不能作为 V6 正式证据。
