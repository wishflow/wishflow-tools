## 下一批：Nevada Level 43 Reno（APK map46）

先完成静态内容审计并细化实现切片，再开始接入；不按地图文件序号推断玩法，不重复实现 Sioux Falls Level 40，也不要求完整通关或启动 Android。

1. **确认内容入口与基线。**读取当前正式关卡目录、地图/路线 builder、波次解析入口和 Nevada 相邻关卡测试；查找 APK map46 对应的既有 REA、Smali、TDM 与资源证据。验收：记录入口、消费链和可复用构件的文件及符号位置。
2. **建立原版内容清单。**逐项核对 TDM 地图对象/图层、出生点与方向映射、可移动路线、波次请求、玩家单位池/生成点、参数、对白及解锁身份；区分原始记录、运行时语义和网页派生值。验收：每项结论可追溯到 APK/REA 证据，缺失资料标为未知，不从相邻关卡补值。
3. **对照网页能力并列出差异。**将原版清单映射到现有内容工厂和共享规则，判断哪些只需数据、哪些需要独立规则切片；扫描正式关卡数量、地区可玩数、进度快照和 E2E 基线。验收：差异、依赖和回归文件明确；新增契约必须有证据说明现有规则无法表达。
4. **细化可独立验证的实现步骤。**按地图对象、路线/波次、单位池及正式目录接入拆分；每片列出目标文件、输入和明确预期。验收：静态内容检查、短 `GameSession` 轨迹、生产绘制/资源核对及共享目录断言覆盖关键行为；地图对象和路线作为后续数据接入的前置。
5. **实施前停止检查。**若审计发现关键参数语义仍不清楚，先补静态证据并更新本计划；确认规则、测试输入和验收门槛均可判定后，再开始逐片实现。

## 稳定交付门槛

- 每个切片先跑针对性测试并提交；批次结束再运行应用完整检查与相关共享检查。
- 默认窗口模式、静音测试；仅在验收对应行为时使用全屏或声音。无需完整通关。
- 普通公开发布比例目标不高于20%；修复批次按完整验收结果如实记录，不拆分或延后工作美化比例。
- 每个已复现并关闭的问题更新[经验记录](experience-log.md)，记录复现条件、证据支持的根因、漏测点、修复和防回归要求。
- 修改 Markdown 后检查链接和 `git diff --check`，并按仓库规则复制到 `/tmp/var/wishflow-tools/`。
