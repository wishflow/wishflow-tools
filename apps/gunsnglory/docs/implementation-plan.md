## 下一批：资源重试保留启动菜单

资源加载失败时，玩家可以查看恢复画面并重试；成功重试只应恢复资源和原有界面，不能替玩家选择并启动关卡。开发用 `?testBattle=1` 的显式调试入口可以保留其测试用途，但不得改变正常启动流程。

### 步骤与验收

1. **增加失败回归用例：已完成。**正常入口拦截必需图片，确认恢复提示期间仍显示主菜单；解除拦截后，旧代码会自动隐藏菜单并进入第一波对白。新 E2E 在修复前按预期失败，覆盖“不自动开局”和玩家主动开局链路。
2. **修复重试后的路由：已完成。**只有显式 `?testBattle=1` 开发调试入口才会在重试成功后打开 Cow Gulch；正常启动保持当前主菜单。新 E2E 通过（1/1）；原 `t20-campaign-progress` 资源恢复用例 6/6 通过，确认调试入口兼容；TypeScript 检查通过。
3. **本地界面验收：已完成。**Playwright 真实拦截并恢复必需图片，确认提示消失后仍在主菜单、未出现战斗对白且没有创建档案；随后显式执行 Start → New Mexico → Cow Gulch → Play → Easy 才进入战斗。Codex 内置浏览器在当前工作树严格端口 `5307`、窗口模式和静音下核对同一正常菜单与主动开局路径。失败资源分支由 E2E 覆盖，内置浏览器未模拟网络拦截。
4. **批次完整本地检查：已完成。**`CI=1 PLAYWRIGHT_PORT=43131 pnpm --dir apps/gunsnglory run test:ci` 通过类型检查、1504 项单测、生产构建和 220 项 E2E；`pnpm run test:catalog` 20/20 通过；`pnpm run build:site` 成功。应用构建保留既有约 4.8 MB 主 JS chunk 提示。
5. **集成发布与线上验收：待执行。**以一个 squash commit 将本批从 `gunsnglory` 集成到 `master`，推送并等待 Pages 工作流成功；核对 GitHub Pages 与 Cloudflare Pages 的 `build-info.json` 来源 SHA 均等于发布提交，再用 Codex 内置浏览器检查版本化页面的主菜单、关卡导航和正常开局。资源失败/恢复分支由本地 E2E 实际拦截验证。发布后将发布提交合并回 `gunsnglory` 并核对远端及相关工作树；按实际历史更新发布比例。此 bugfix 批次完整验收后发布，不单独发布计划文档。

- 每个切片运行针对性测试并本地提交；批次结束再跑完整应用与共享检查。
- 默认在窗口模式、静音状态测试；只有对应验收需要时才使用全屏或音效。无需完整通关。
- 普通公开发布比例目标不高于 20%；修复批次按完整批次发布并如实记录，不拆分或延后工作美化比例。
