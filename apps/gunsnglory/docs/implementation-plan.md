## 下一批：Level 42 Bombington

### 范围

接入 APK 正式战役中的 Nevada Level 42「Bombington」。当前目录仅能确认关卡目录项指向 map file 45 / title resource 45；这不是内容、路线或规则已验证的证据。APK 的波次入口已初步定位为 `GameDesignWaves.setWaves(i == 42)`，完整参数语义仍待本批逐项核对。

只实现这一关及其必要的目录/存档集成。Level 43–60、全局规则重构、无证据的平衡调整、完整战役通关和 Android 实战不在本批范围。

### 步骤与验收

1. **M6-A：完成 APK 内容审计。**从 APK 的 `td_map_45.tdm`、`GameDesignData`、`GameDesignWaves`、关卡字符串/对白、单位与地图对象资源交叉核对地图尺寸和格码、所有路线分支、静态对象、敌人请求、玩家生成池、难度参数、经济/生命、奖励与解锁、头像、音乐及回放映射。新增一份按主题组织的 Bombington 审计文档；每项区分 APK 直接证据、推导、网页现状和未知，禁止用相邻关卡参数补空缺。通过条件：必需字段均有来源；未解决字段带具体阻塞和所需证据。
2. **M6-B：接入地图、路线与静态场景。**由原始 TDM 生成网页地图和路线，不手工画直线代替原路线；校验出生点到出口的每个有效分支、地形可走性、道路/桥面贴合、对象图层与锚点。通过条件：TDM 与提取结果逐格一致；各路线可达且不越界、不穿越阻挡地形；生产 `drawGame()` 的地图层映射有针对性测试。
3. **M6-C：接入单位、碰撞与运输实体。**依据 TDM marker 和原始组数据登记睡眠/活动角色、建筑、障碍和交通部件；核对 APK 碰撞框、单位脚底、车辆/列车组距和轨迹。通过条件：每个 marker 有 APK 类别映射；实际存在的运输组都有移动与生产绘制断言；不存在的单位明确由 TDM 证明不适用。
4. **M6-D：接入玩法与关卡入口。**逐项实现波次顺序/请求、难度倍率、敌方属性、玩家单位池、开局与波次对白、奖励、音乐选择、正式战役解锁/结算、Free Play 和 replay 分派。通过条件：数值和内容来自 M6-A；短 `GameSession` 断言覆盖所有波次请求及结算边界；目录、区域关卡数、进度快照、Free Play 与 replay 测试一致；Free Play 不写战役进度。
5. **M6-E：关卡批次验收。**每个切片先跑针对性测试并提交；关卡集成后运行应用 `pnpm run test:ci` 和适用的共享检查，修复后重跑失败项及完整检查。内置浏览器以窗口模式、静音从菜单打开 Bombington，检查地图、代表性波次对白和战斗 HUD；不要求手动通关。全部通过后按发布比例和完整功能批次规则决定是否与后续关卡一起发布。

### 本批边界与停止条件

- APK 静态分析优先。只有静态代码和资源无法回答一个明确行为问题时，才考虑 Android 定点观察；不为收集通关记录启动整场战役。
- 贴图边缘、动画逐帧和 APK 同种子动态画面对照不由静态反编译证明。发现用户可见偏差时记录关卡、视口、对象和时间/回放证据，再单独判断是否阻塞。
- 不新增游戏引擎或依赖。只有现有内容接口明确无法表达 APK 行为时，才提出最小接口扩展，并先说明消费者、存储兼容和测试影响。

## 稳定交付门槛

- 每个切片先跑针对性测试并本地提交；批次完成后再跑完整应用与相关共享检查，不在每个提交后重复整套测试。
- 浏览器默认窗口模式、静音；仅对应验收时使用全屏或声音。无需手动完成整场战役。
- 发布前按最新已验收实现切片和公开发布次数复核比例，目标不高于 20%；不拆分或延后已验收工作美化比例。
- 每个已复现并关闭的问题更新[经验记录](experience-log.md)；结论写明证据与边界。
- 修改 Markdown 后检查链接和 `git diff --check`，并按相对路径复制成品到 `/tmp/var/wishflow-tools/`。文档更新本身不触发公开发布。
