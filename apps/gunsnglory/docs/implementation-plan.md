# 实施计划

本文是 Guns’n’Glory 唯一活动进度与任务来源，只保留未完成工作。产品规则见[产品规格](spec.md)，模块边界见[架构](architecture.md)，存档边界见[存储契约](storage-contracts.md)，模拟与测试约束见[模拟与自动化契约](simulation-and-automation.md)。

每轮先核对当前代码、测试与提交，再细化后续步骤的范围和验收。每个切片先跑针对性测试并提交；步骤完成后更新本文，删除已完成项。整批结束再跑一次完整检查，不重复已通过的检查。

## 当前状态

- 正式战役已完成 **3/60** 关：Cow Gulch、Apache Valley、Fort Kaboom。
- 当前工作在 `codex/gng-spawn-field-restore`；该分支包含 `gunsnglory` 集成分支，尚未集成到公开 `master`。公开版本为 `e922c3f`，本地代码不等于已发布版本。
- Tech Town 的地图、路线、静态对象、普通与特殊单位、Gambler/Casino、列车、Gatling、随机流及会话结算底层均已实现。仍缺正式关卡的波次、玩家生成池、初始经济、双语对白、档案解锁与结算接入；不要重复实现已有机制或人工通关整关。
- 现有全屏入口与横屏请求已接通，但全屏 CSS 仍固定 16:9，宽屏会留下未使用区域。已有全屏 E2E 只验证 API 状态和横屏请求，没有验证画面实际铺满；因此全屏适配尚未通过。
- 站点 Usagi Widget 固定在 `z-index: 80`，游戏窗口为 `z-index: 81`，窗口模式下宠物会被游戏盖住。此问题属于网页堆叠层级，不属于 Canvas 内对象绘制顺序。
- 发布比例基线为 5 次成功发布 / 27 个已验收实现切片（18.5%）；完成新的发布批次后再按规则更新计数。

## 下一步

### 1. 核心显示修复

- **窗口模式层级：**让站点 Usagi Widget 高于游戏窗口并保持可交互；只调整 Guns’n’Glory 页面的层级，不改变共享 Widget 的全站样式，也不改 Canvas 内部绘制顺序。
- **全屏视口：**游戏窗口铺满可用屏幕。视口和地图相机随宽高比调整，维持角色与图块比例，不拉伸、不裁切、不留大片黑边；支持横屏锁定时请求横屏，锁定不可用时仍适配当前方向。全屏期间 Usagi 隐藏，退出后恢复。
- **验收：**单元测试覆盖不同屏幕比例、画布坐标映射和方形图块；浏览器检查窗口模式桌面、手机横屏及全屏后的尺寸、游戏元素比例和 Widget 状态。只在本切片验收时进入一次全屏，结束后退出并保持静音。
- **批次：**针对性测试通过后提交切片，整批结束再跑应用完整检查。此为核心显示缺陷修复批次，按应用修复批次发布规则处理。

### 2. Tech Town 正式关卡集成

先用现有 REA/JADX 证据完成尚未闭合的字段消费者、波次向量及玩家池动作语义核对；只对明确的静态证据缺口调用 REA。静态证据足够时不启动 Android。

在现有框架内一次性接入八波与敌方池、玩家招募池与波次动作、关卡经济和结算参数、八段双语对白与肖像、正式资源预加载、map04 解锁和档案结算。若证据证明当前通用规则框架缺少某项必要能力，再将该能力单独切片，并先更新计划。

验收要求：

- 测试逐项核对 APK 派生的波次矩阵、玩家池、可映射参数、对白资源和解锁阈值；未知字段不生成猜测性行为。
- Game 会话测试覆盖正式内容的波次推进、经济与唯一结算；不要求在浏览器手工打完整关卡。
- 浏览器只检查选关、进入 Tech Town、代表性战斗交互和界面适配；默认窗口模式、静音。
- 此功能批次完成后运行一次完整应用检查，按正式功能批次规则集成与发布。

### 3. 后续战役

map04 验收后逐关处理 New Mexico map05–10，再处理 Mississippi map14–23、Oregon map24–33、Dakota map34–43、Nevada map44–53、Alaska map54–63。每关先复核 APK 与现有框架，只实现该关实际需要的数据或新机制；APK 地图文件 11–13 不计入 60 关战役。首次出现的新敌人、建筑、交通工具或规则只在真实使用场景验证。

## 证据与发布门槛

- 每个新增规则或参数都能追溯到 APK 资源、REA 结果、DEX 位置或明确标记的运行观察；JADX Java 伪代码不是原始源码。曾发现 `GameObjectManager.createGameObjectsFromBasicMap()` 的 Java `switch` 输出有控制流错误，码位判断以 DEX smali 为准。
- 只有具体行为无法由静态证据回答时，才执行一次最小 Android 观察；记录问题、设备状态、判定标准和结果。不重复看启动页，不模拟完整战役。
- 发布按应用规则执行：每个切片先定向验证并提交；批次全套检查通过后以一个 squash commit 集成。普通发布比例目标不高于 20%，核心缺陷修复按实际情况记录；公开发布核对 CI、来源 SHA 与内置浏览器结果。文档整理不计实现切片、不单独发布。
