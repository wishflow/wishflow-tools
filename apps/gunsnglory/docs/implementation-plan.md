# 实施计划

本文是 Guns’n’Glory 的唯一活动进度与任务来源，只保留未完成的工作。产品行为见[产品规格](spec.md)，模块边界见[架构](architecture.md)，存储边界见[存储契约](storage-contracts.md)，步进和随机语义见[模拟与自动化契约](simulation-and-automation.md)。

已关闭任务从活动清单删除，代码与提交记录保留实现历史。每完成一个切片，先核对实际代码和验证结果，再从本计划移除并细化下一项，避免照旧清单重复工作。

## 版本同步门槛

公开发布提交 `e922c3f` 已包含 Apache Valley（map02）和核心 UI/UX。GitHub Pages 与 Cloudflare Pages 的 `build-info.json` 均报告该提交的完整来源 SHA；内置浏览器确认公开游戏页面的主菜单、New Mexico 关卡入口、全屏与战斗内地图缩放可用。`gunsnglory` 远端及相关工作树已同步并包含该发布。本仓库只在 `master` 推送时构建并发布静态站点，见[Pages 工作流](../../../.github/workflows/pages.yml)。

下一次公开发布必须满足以下条件：

1. 发布内容包含当前已验收的 Apache Valley（map02）集成代码；发布提交来自 `master`，不以本地 `gunsnglory` 或旧标签页代替发布来源。
2. 构建产物提供可直接读取的源代码提交 SHA；部署完成后，公开页面报告的 SHA 必须与预期 `master` 发布提交一致。
3. Actions 发布工作流成功后，用 Codex 内置浏览器访问无旧 `release` 参数的公开 URL，核对来源 SHA、战役关卡数量与整批功能。至少确认 map02 已显示并可按档案状态进入；随后按本计划中的待办验收 UI/UX 功能。
4. 若 SHA 不匹配、无法读取，或页面仍显示旧关卡清单，保持发布未完成，先修复来源标记、发布同步或缓存问题，再重新执行核验。

来源 SHA 现由公开站点根目录的 `build-info.json` 提供。后续发布仍须按本节要求核对该文件；URL 参数、工作流成功或旧浏览器标签不能替代来源 SHA。

### 批次完成门槛

- 三个剩余步骤各自运行针对性验证并本地提交；不得在每个步骤后重跑整套应用检查。
- 全部步骤通过后运行一次 `pnpm run test:ci` 及适用的共享检查；失败时先将修复范围写回本计划，再修复并重验。
- map03 只有在正式关卡数据、地图空间、全 10 波、结算与档案端到端条件通过后才计为 **3/60**。真实地图内容测试和正式关卡 E2E 不能由 fixture 代替。
- 批次完成前不单独发布小切片。发布仍需满足本计划中的重要缺陷/里程碑条件和不高于 20% 的普通发布目标；若比例门槛未达到，继续积累后续已验收切片，不通过虚增任务数改善比例。
- 不使用 APK 模拟器重复确认已经能由字节、smali、资源或本地规则测试回答的问题。只有具体静态证据缺口影响验收时，才制定一次定点运行观察。

### 实验与平衡分析

- 在需要扩展到完整战役前，先审查现有 `Experiments`、批次、回放与报告代码，保留已有的确定性、版本冻结、预算分类、取消及串并行结果，不重复实现已有能力。

- 远程档案、内容分发和远程批次服务仍按需独立规划，不作为纯前端战役完成的前置条件。

## 集成与发布门槛

实现任务在 `gunsnglory` 集成分支上积累可独立验收、可回滚的切片。普通公开发布次数除以已验收实现切片数不高于 20%，只在完整里程碑或核心可玩性、结算、档案安全的重要缺陷时提前发布，例外也计入比例。已确认起点为 3 次成功发布/6 个验收切片；本轮首关验收与地图视口修复已随里程碑发布，当前累计为 **5 次成功发布 / 25 个已验收实现切片（20%）**。检查点和文档更新不计产品切片，不单独发布。后续公开发布按仓库流程合并到 `master` 并推送；等待现有工作流成功，静态应用确有部署时，再以 Codex 内置浏览器实测线上行为。未通过 CI 或线上实测不得报告发布完成。
