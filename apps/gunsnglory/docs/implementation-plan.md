- Tech Town 已登记为 New Mexico 第 4 关，接入原图、四条路线、八波、初态、玩家池动作、双语对白、正式进度和结算路径。关卡首次开放时只出现 type 1–4 普通单位；重玩时按档案里程碑开放已解锁的特殊地图单位，Gambler 与 Casino 同步出现或隐藏。
- 全屏构图已修复：逻辑视口固定1024×576，全屏舞台完整等比居中，不裁切、不拉伸；全屏适配不再改地图缩放，舞台外输入无效。Playwright定向测试覆盖16:9、宽/窄横屏和竖屏旋转门；内置浏览器真实全屏实测窗口1728×1080、舞台1728×972、上下各留54px，退出后恢复窗口模式。普通页面中的Usagi覆盖游戏窗口，全屏时隐藏。常规验收仍默认窗口模式。
- 自由游玩已接入独立首页入口。四个已实现关卡无视战役前置状态开放，简单/中等/困难均可选；56个未实现关卡仍显示并禁用。`free` 会话使用正式波次、生成池、关卡对白和结算规则，但不会调用 Progress；难度只保存在菜单临时状态。空档案进入 Tech Town 时，仅为构造该关卡提供其基础地图访问单位，其他特殊单位仍按档案里程碑解锁。自由结算明确显示不写档案，回放记录和导入验证保留 `free` 源模式。
- 自由模式切片定向验证通过：`tests/free-play.test.ts`、Progress 正式结算隔离、难度/回放/战役回归共26项单测通过，类型检查通过；Playwright 菜单回归3项通过，自由模式端到端测试1项通过，覆盖零进度进入 Apache Valley 困难、四关入口状态、Tech Town 首波及档案难度/进度/最高分/revision 保持不变。
- Profile 档案和实验数据档案已实现为两个独立的 v1 JSON 文件。Profile 档案不含 revision，导入前确认并通过 ProfileRepository 条件事务整体替换；实验档案包含所有数值方案及完整比较报告，在单个 IndexedDB 事务中合并方案、比较索引与附件，重复内容跳过、标识冲突保留本地并报告。当前代码把档案入口和实验工具放在主菜单“选项”，并把实验面板动态挂入选项页；模拟速度还同时出现在调试工具栏与选项页。战斗回放位于页面外侧栏，格式未改。本批会统一迁移到外部实验工作台，不改变这些数据语义。
- 数据档案切片定向验证通过：类型检查通过；Progress、两类档案编解码、实验仓库和实验流程相关单测共44项通过；Playwright `t38-data-archives.spec.ts` 两项通过，覆盖档案下载/替换/取消/未知版本、实验导出导入/重复去重/冲突保留、跨数据库隔离，以及 profile 和实验 IndexedDB 写事务失败后无部分写入。
- Playwright 定向 E2E 使用 `pnpm exec playwright test tests/e2e/<spec>.spec.ts --workers=1`；避免在 `pnpm run test:e2e -- ...` 后追加 spec 参数，该转发形式会误触发全套测试。
- IndexedDB repository 的多个实例共用相同数据库；共享契约在同库上验证幂等导入与冲突，只有需要验证“导入到空库”时才另开浏览器 context。检查弹窗是否留在游戏窗口内应验证 `closest('.game-frame')`，不要要求它是直接子元素，因为 `.game-stage` 是合法的中间容器。
- 浏览器测试默认静音；除专门验收音效外，不开启声音。REA/APK 静态材料优先；仅当具体问题无法从静态证据判断时，才安排一次 Android 定点观察，不重复启动或检查已证实行为。
- 上一批的显示修复、Gold Transport、玩家池多槽动作、Tech Town、全屏构图和自由模式共 6 个实现切片已完成。本地完整检查通过：类型检查、391 项单测、构建和 97 项 Playwright E2E；E2E 需允许本地服务绑定 `127.0.0.1:4173`。该批通过 GitHub Actions `42253109012` 发布到 GitHub Pages 与 Cloudflare Pages；两处 `build-info.json` 的来源均为 `6940fcbaa4b2520d8be5f1a81243c9a25815e4e0`。内置浏览器在窗口模式、静音下验证主菜单、地区/关卡选择、进入 Cow Gulch、退出未完成关卡和 Usagi 拖动；未启用全屏或音效。移动端竖屏由 Chrome 157 定向检查和完整 E2E 覆盖；当时的内置浏览器会话未提供移动视口覆写。构建仍提示主 JS chunk 超过 500KB，但不影响构建或测试。
- 手机竖屏 CI 曾连续三次发现清除选择按钮超出可视区：Chrome 157/Linux 测得操作行宽 255.6px，主要按钮与间距约 265px，超出 9.4px。扩大操作行或把摘要移出叠层会遮住地图并导致触屏选择、拖动和缩放回归，均已撤回。最终保持原摘要与操作行布局，将窄屏按钮水平内边距从 0.3rem 缩至 0.18rem，主要按钮总宽减少约 11.5px；定向 CI、全套本地检查和最终发布 CI 均通过。

## 当前批次：游戏外实验工作台与原版风格统一

**目标：**实验与档案操作属于后续网页实验工作流，不属于 APK 的游戏 Options。将它们集中到游戏画框外的同页实验工作台；游戏内 Options 恢复为 Help 与 Sound。工作台沿用原版羊皮纸、木牌、木按钮和清晰的浅色内容底；FrameChrome 全屏按钮使用本批已生成的银灰 HUD 双状态按钮素材，不再使用 `⛶` 字符。

**边界：**不改规则、Game/Progress/Experiments 公共接口、IndexedDB 存储、Profile/实验档案 JSON 契约或回放格式。档案替换确认、实验档案合并/冲突报告、回放导入导出语义保持不变。模拟速度仍读写现有设置，只保留一个网页外实验室入口。使用站点提供的本地导航与语言状态，不新增应用专属语言存储或切换器。

### 切片 1：文档与外部工作台结构

- **实现：**在游戏页外建立可见的实验室区，并用站点本地导航连接 `#game` 与 `#lab`。将现有实验面板、Profile 档案、实验档案、回放和唯一的模拟速度控制挂到工作台；删除 Options 内实验/档案/倍速入口以及动态搬运实验面板的逻辑。Options 只保留原版风格的 Help 和 Sound；Sound 与主菜单及暂停板共用同一设置状态。
- **验收：**所有实验、档案、回放、倍速控件都不属于 `.game-frame`；Options 只含 Help 和 Sound，且三处声音状态一致。Profile 替换确认、实验档案重复与冲突报告、回放往返及速度设置存取均保持原行为。用定向单测/E2E 检查入口归属和实际操作，不只检查可见性。

### 切片 2：实验工作台视觉与响应式布局

- **实现：**依据已审阅样稿，按实验方案、比较结果、已保存报告、数据档案/回放分区；容器采用原版羊皮纸纹理和边框，行动使用一致的木质按钮，密集数据放在高对比浅色内衬上。桌面使用清楚的分栏，窄屏改为单列；表格需要时局部横向滚动，整页不得横向溢出。中英文使用站点语言状态，固定操作槽位并支持不同译文长度。
- **验收：**桌面、手机竖屏和横屏检查主要区块顺序、可读性、按钮状态、表格滚动与边界；中英文均不得重叠、裁切或溢出。浏览器截图与几何断言一起验证，不以 DOM 存在替代视觉检查。

### 切片 3：全屏按钮美术

- **实现：**将本轮生成的透明双状态金属按钮图作为项目资源，分别显示四角向外的进入全屏状态与向内的退出状态。移除按钮里的 `⛶` 文字符号；保留当前切换逻辑、游戏框角落位置、44px 级点击目标、本地化 `aria-label`/title 和可见键盘焦点。普通窗口和弹窗状态下均可命中。
- **验收：**检查资源透明边缘及两态裁切，Playwright 验证图像加载、状态图切换、辅助名称和点击；内置浏览器查看真实缩放后的按钮质感。仅本切片进行一次实际全屏进出尝试，若宿主拒绝，记录限制，不把 mock 结果当作真实全屏成功。

### 批次关闭条件

- 每个切片运行针对性测试、更新本文关闭已完成项并本地提交；不在每个切片后重跑整套检查。
- 全部切片后运行 `pnpm run test:ci`，修复后重跑失败项及最终完整检查。内置浏览器保持静音和窗口模式，除全屏按钮验收外不进入全屏。
- 全批通过后按 Guns’n’Glory 规则 squash 集成到 `master`、推送并等待部署；核对公开 `build-info.json` 来源 SHA，再用内置浏览器检查部署版本。按项目规则更新实际发布比例与限制。

## 后续批次：New Mexico 第 5 关 Billy Hills

本批 UI 工作台完成并发布后再开始 map05 静态审计；不与当前 UI 修复混合。

### 1. 先完成 map05 静态内容审计

**范围：**只使用 APK/REA 现有静态资料，不实现游戏代码、不启动 Android。以 `td_map_05.tdm`、战役关卡配置第 5 行、`GameDesignWaves` 对应记录及其实际读取点为依据。

**需要明确：**地图尺寸与网格、入口/出口/方向场及路线、静态对象和单位初态、现金/生命/升级上限、全部波次与生成池请求、玩家池/动作、敌人及特殊规则、对白键与双语文本、必需美术和声音资源、进度解锁和结算边界。分别标出直接数据、代码推导、实现假设和未知项；地图文件数量不得当作战役关卡数。

**产物：**在本文更新一份足以实现与独立测试的 map05 参数摘要，并列出已有 Game 规则可直接复用的部分及缺失机制。未知项若影响战斗结果，则先查对应静态消费者或记录阻塞，不猜值、不用完整通关来补证。

**关闭条件：**关卡数据与读取逻辑能够交叉核对；所有会影响 map05 可玩性的未知项已解决，或已明确拆成独立规则任务及所需证据。审计通过后再进入第 2 步。

### 2. 按审计结果接入 map05 正式内容

**实现边界：**若现有 Game 规则覆盖地图与波次行为，只增加正式关卡内容、资源、解锁和对白，并把它登记为 New Mexico 第 5 关；实际数据进入正式会话，不以 fixture 代替内容。若审计发现现有规则不支持必要机制，先拆出可独立验证的规则切片，再接入关卡。

**验收：**独立期望核对原始网格、路线、对象、初态、所有波次/请求、关卡参数、生成池、对白与资源；正式会话检查初始状态、代表性操作、胜败均走唯一 Progress 结算路径；map04 前序行为和 map06 锁定状态不回归。浏览器用窗口模式与静音，仅做选关、入关、一个代表流程和退出检查，不手动通关整关。

## 发布门槛

每个切片先跑针对性检查并提交；整批切片全部完成后运行一次应用完整检查与适用共享检查。公开发布按根目录及本应用 `AGENTS.md` 执行：整批验收后 squash 集成，核对 CI、部署来源 SHA，再用内置浏览器验收；普通发布比例目标不高于 20%，按实际成功发布与已验收切片数记录。
