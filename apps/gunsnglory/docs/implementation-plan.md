## 当前工作顺序

### 已接入地图的路线与步行范围视觉核对

当前 41 张可玩地图已有 TDM、路径和碰撞自动检查，但覆盖范围不等于全部地图的生产绘制画面与 APK 证据都逐项核对。先盘点现有证据，避免重复检查已经闭合的 Cow Gulch 桥面、车马双轴跟随、悬崖 raw36 和对象碰撞问题。

1. **建立覆盖矩阵。**逐关核对当前 41 张可玩地图的现有测试与研究材料，至少区分敌方路线中心/分支、背景道路和桥图层、我方脚底锚点与地形范围、静态对象碰撞、车辆/船组绘制锚点。标记已有直接证据和缺口；未实现的 Level 42–60 不计入可玩地图验收。
2. **只补未覆盖项。**对矩阵指出的缺口，用生产 route/session/render 数据生成逐关或分区截图/叠图，与 APK 派生 TDM、路线和绘制锚点对照。路线中心、脚底、精灵透明范围和碰撞框分别判定；不因高贴图压到崖壁就移动路线。优先静态证据和短 `GameSession` 检查；只有具体问题静态无法解释时才做一次 Android 定点观察。
3. **按差异修复。**只有发现网页相对 APK 的明确坐标、图层、素材或碰撞差异时改代码，并为该地图增加独立来源的回归断言。没有差异的地图关闭为“已核对”，不新增重复测试或再次截图。

**验收。**41/41 可玩地图在矩阵中有明确状态；关键路线不经过最终阻挡地形，桥面只允许 APK 定义范围，我方单位的渲染脚底、碰撞锚点与静态对象阻挡分别有证据。所有差异均附 TDM/REA/DEX 位置或生产画面引用；未完成或工具无法提供的证据注明缺口。先执行矩阵审计和缺口测试，再决定是否需要代码修复；整批最终运行 `pnpm run test:ci` 与共享目录测试。

Level 41 集成验收已关闭：`pnpm run test:ci` 通过，包含 1,219 项单测、构建和 212 项 E2E；共享目录测试通过 20 项。Free Play 关卡预览提示已独立排版，`t29-campaign-menu.spec.ts` 8/8 与类型检查通过，完整 CI 待本批收尾统一运行。全战役细节和仍未验证的视觉边界见[经验记录](experience-log.md)。本计划不要求手动完成整场战役，也不把单个浏览器/文档切片作为公开发布。

### 未闭环反馈与复核边界

- **车马画面：**前车双轴位移算法及已知 Wave 3 落后状态已覆盖；尚无 Android 原版运行帧的同轨迹对照。只有出现可复现的新轨迹差异时才继续改规则，避免重复检查已通过的 seed/岔口。
- **地图与碰撞：**路线、脚底锚点和对象碰撞已有多关静态/`GameSession` 覆盖，但不是对所有已接入地图逐关实走或逐帧并排检查。用户提供的特定关卡/坐标优先用于定点复核；不能把 27/38 张图的样本覆盖表述为全 60 关视觉验收。
- **界面视觉：**雇佣框的角色信息、关卡预览坐标系、Options 紧凑布局和 Free Play 状态提示已有代表性桌面/触屏及自动检查；与 APK 每一屏幕尺寸的逐项视觉对照仍未完成。当前明确缺口转入上方地图与场景视觉覆盖矩阵。

## 稳定交付门槛

- 每个切片先跑针对性测试并本地提交；不在每个切片提交后重复跑全套。整批结束后再运行应用完整检查与共享检查。
- 浏览器验收默认窗口模式、静音；仅验收对应功能时才启用全屏或声音。优先用 APK、REA 与静态代码证据；仅在静态证据无法回答具体问题时做一次短时 Android 定点观察。
- 普通公开发布次数占已验收实现切片数的目标不高于 20%；每次发布前根据最新提交记录复核比例，不通过拆分或延后已验收切片调整统计。
- 每个关闭的已复现问题更新[经验记录](experience-log.md)；本计划移除已完成项，并明确仍未验证的结论与边界。
- 涉及 Markdown 的切片运行 `git diff --check`，再按仓库规则复制成品到 `/tmp/var/wishflow-tools/`。本计划修改本身不触发产品发布。
