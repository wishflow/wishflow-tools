# 实施计划

本文件是 Guns’n’Glory 唯一活动进度。每轮先核对当前代码与证据，细化后续步骤和验收；逐项实现、定向验证、更新计划并本地提交。已完成项从活动计划移除，经验与领域规则分别记录在对应文档。

## 当前基线

- **M34 Fort Knockout 已发布并回同步。**公开发布提交为 0860041；M35 从集成基线 31658ca 开始，该基线包含当时的 origin/master，分支跟踪 origin/gunsnglory。本轮开始前已刷新远端并确认工作树干净；文档修改提交后 HEAD 将前进。M34 发布和线上验收不在本计划重复安排。
- **下一关：M35 Badlands。**Dakota 第4关、global level 34、APK TDM 文件37。现有 campaign catalog 已有 Badlands 身份和 map37，但尚无可玩的完整 scenario。静态基线见[Badlands 静态审计](badlands-static-audit.md)。
- **证据与回归约束。**所有关卡事实从本关 APK 字节、目标 level 分支和对应消费者独立建立；不从邻关或压缩摘要复制。REA/JADX 伪代码、派生清单和历史报告是检索入口，不替代原始来源。路线绘制、玩家碰撞、敌方路线和对象碰撞分开验收。
- **历史文档冲突已发现。**M13 静态报告中关于 raw96–101 的旧结论与 Smali 及后续关卡报告不一致，已在本轮一并更正；相关防回归见[经验记录](experience-log.md)。
- 浏览器验收默认窗口模式并静音；无明确静态分析缺口时不启动 Android，不完整通关。

## M35：Badlands

### M35-A：静态基线

**已完成。**地图、路线、对象、单位、参数、波次、英文文案、头像和 Dakota 音乐调用见[Badlands 静态审计](badlands-static-audit.md)。该步骤不计产品实现切片。

### M35-B1：地图绘制、最终地形与敌方路线

- **范围：**从 APK 的 map37 生成固定原始 TDM fixture；接入 Dakota 地面、峡谷、道路、桥梁和铁路绘制数据；从完整转向码生成路线。不得用路线折线代替路面，也不得直接以 raw32/raw36 代替塑形后的碰撞网格。
- **依赖：**M35-A。复用 Dakota 已验证的图集与背景转换接口，但所有格点及绘制命令必须使用 map37 输入重新生成。
- **验收：**768格及全部非零 marker 数量、背景绘制、道路/桥梁/铁路覆盖、图集 source rectangle 与地图边界独立匹配 APK 派生期望；路线含68条唯一有向边、37条出生至出口路径、全部节点可达且无 raw36 墙格。三种出生 action 的 spawn ID、坐标和初始西向及代表性首转均与 APK 对照。
- **验证：**新增 dakota-04 map/routing 专题测试；以原始 TDM fixture 与独立路线期望比较，不从生产 JSON 生成预期。运行相关单测和 TypeScript 类型检查。

### M35-B2：地图对象、列车、招募单位和碰撞

- **范围：**接入岩石、树、水塔、灌木、小屋、水域、铁路挡车器、列车及 Dynamite 配对；根据 raw96–101、130/131 创建候选招募单位，并复用已确认的单位解锁快照、唯一 ID 与资源映射。地图不存在的 Fort、Saloon、Tipi、Gambler、Casino 和活动初始单位不得凭素材或参数补造。
- **依赖：**M35-B1 的原始格网、场景图层和坐标变换。
- **验收：**静态对象和单位 marker 逐个匹配类型、数量、坐标、贴图、activity 与解锁状态；列车按一个移动组构造；炸药 trigger/box 不混码；默认与全解锁快照都没有重复 ID。地形、横/竖桥、raw36 悬崖、铁路、静态建筑、睡眠单位和炸药分别用 GameSession 验证通过/阻挡边界。
- **验证：**新增 dakota-04 scene/unit/collision 专题测试，期望直接来自 TDM 与 APK 构造分支；至少覆盖真实场景中的短时移动，不用单独 AABB fixture 替代正式关卡对象。

### M35-C：经济、难度、九波和 Boss

- **范围：**global level34 对应 GameDesignData index33；按审计字段接入现金、生命、箱子、升级及三档难度。接入9个 wave header、13条请求、所有 action/间隔/请求向量、头像和第9波 Boss。APK 没有玩家池动作，本关不新增生成池。
- **依赖：**M35-B1 的路线，以及 M35-B2 的地图单位和资源。
- **验收：**独立期望逐字段比较12项参数和9波/13请求；特殊 Boss 槽与 Doc 槽不得混淆；请求向量作为加权生成请求处理，不断言固定的敌人出生顺序。确认 nonzero Gambler timer 不会在无 Gambler/Casino marker 时造出对象。
- **验证：**新增 dakota-04 campaign-rules 测试；使用正式/自由战役 GameSession 短会话核对开局资源、波次头、spawnPointId 与末波 Boss。debug 模式不得作为战役波次验证入口。

### M35-D：文案、资源预载、正式/自由入口与回放

- **范围：**接入 APK 英文标题、简介、9段对白、头像和 Dakota 环境/战斗音乐映射；中文为网页翻译；确认地图、场景、单位和头像图片进入启动预载。建立 Badlands 的内容版本快照与 replay factory，登记 global level34 正式关卡，前置为已实现的 campaign-dakota-03；Free Play 可直接进入且不改正式进度。
- **依赖：**M35-B1、M35-B2、M35-C 的独立关卡内容均通过。
- **验收：**Free Play 和正式模式都从真实菜单使用正确标题、简介、地图预览、地区 HUD、波次对白和资源；正式关卡在前置未完成时锁定、完成 Fort Knockout 后开放；结算按正式/自由语义隔离。回放根据录制内容版本重建，不读取导入者当前解锁；未知或非规范版本拒绝。既有 stage 数、地区可玩数、Progress 快照和 Free Play 范围同步更新。
- **验证：**新增 dakota-04 presentation/replay 单测和真实菜单 E2E；检查入口、开局对白、地图和代表性战斗事件，不完整手动通关。对启动预载使用项目的资源别名映射核验真实文件，不拼接资源文件名。

### M35-E：批次检查、集成发布和线上验收

- **依赖：**M35-B1 至 M35-D 全部关闭并分别本地提交。
- **本地门槛：**修复当前批次已发现失败；运行 Guns’n’Glory 完整 pnpm run test:ci 与适用的共享 catalog 检查。先确认测试进程来自当前 worktree；完整检查在批次收尾运行，不在每个切片后重复。
- **发布门槛：**将 M35 完整批次以一个 squash commit 集成到 master；推送后等待现有 workflow 成功，核对 GitHub Pages 与 Cloudflare Pages 的构建 source SHA 均匹配，再合并发布提交回 gunsnglory 并核对分支/worktree 同步。
- **线上验收：**内置浏览器窗口模式、静音打开与部署 SHA 一致的页面；从菜单验证 Free Play 与正式锁定/解锁入口、Badlands 预览、对白、地图、HUD 以及代表性游戏状态。只做代表性流程，不完整通关；除非某项静态证据无法回答，不启动 Android。

## 发布比例

- M30 结束时的核实基线为 36 次公开发布 / 195 个已验收实现切片。
- M31–M34 新增实现切片按已合并计划逐项核算：M31 7、M32 8、M33 5、M34 11，共31个；同期有6次公开部署，包含4个关卡功能批次和2个修复/诊断发布批次。
- **当前累计：42 / 226 = 18.6%。**计入修复批次实际部署，不计静态审计、文档、完整检查和分支回同步。目标仍是不高于20%。
- 若不再增加实现切片，下一次发布后为43 / 226 = 19.0%；M35 每个已验收实现切片完成时更新分母，发布后更新分子。文档提交不算产品切片，也不单独发布。

## 批次执行规则

- 每个实现切片先运行针对性验证、更新本计划并本地提交；一组步骤完成后审查尚未完成项并调整后续范围。
- 整批结束时运行完整应用检查和适用共享检查一次。失败留在当前批次修复，再重跑失败项及最终完整检查。
- APK 数据期望必须独立于生产数据；路线、绘制、碰撞、单位、规则、内容入口分别验证。不能用 DOM 可见、fixture 自洽或单张预览图证明完整行为。
- 发布是完整功能批次的决定，不按文档或单个实现切片发布。部署与内置浏览器门槛未通过时，批次保持未完成。
