## 当前活动任务：Cow Gulch 第一关完整验收

首关地图和规则基线已有证据，不重新从头调查；本阶段只核对全量关卡流程尚未闭合的差异。

1. **锁定真实验收对象。** 使用正式身份 `campaign-new-mexico-01` 和 APK 对照资料；确认初始单位、65 初始现金、50 生命、零升级上限、地图、八波数据和正式进度入口均来自生产内容。现有 fixture 可以补边界，不能替代真实关卡。
2. **完成一次真实八波流程。** 通过生产 `Game` 与正式页面，以真实可用的玩家命令和自然收入跑完八波；不注资、不改正式波次/敌人、不删请求。验证自动波次推进、对白、生成、战斗、逃逸/击败、动态难度、音画事件和最终胜负。现有 `tests/e2e/t22-original-waves.spec.ts` 只推进到第 2–8 波途中，不能代替最终结算。
3. **验证正式结算和恢复。** 至少完成一次真实胜利并确认 Progress 只应用一次、刷新后完成状态/高分仍在；单独验证失败后重开回第一波，以及未完成战局刷新后从第一波开始。正式关卡通关必须由真实正式终局产生，不能由样本或手造档案代替。
4. **完成端到端对照。** 使用内置浏览器检查桌面鼠标和手机触屏，比较原版基准状态下的地图/对象、路线、HUD、动画、对白和音频触发；行为数值用明确断言，局部截图辅助定位，不使用全图相似度替代差异判断。
5. **关闭门槛。** 所有差异均已修正或有明确、获准的范围解释；`test:ci` 通过；真实浏览器的主要操作与终局正常。通过后完整关卡数由 0/60 更新为 1/60。发现新差异时只新增对应的最小任务，不重开已通过的地图/规则基线。

### 实验与平衡分析

- 在需要扩展到完整战役前，先审查现有 `Experiments`、批次、回放与报告代码，保留已有的确定性、版本冻结、预算分类、取消及串并行结果，不重复实现已有能力。
- 按真实消费者逐项补差异：已验收关卡能以正式同源规则运行；场景、数值方案、策略、seed、时间和环境被冻结并可追溯；结果分母排除取消、超时和输入错误；指标有单位、来源和缺失说明；串行/并行同输入语义一致。
- 先用已验收真实关卡，不等待 60 关才启动基础验证；未知机制必须拒绝或明确标为未支持，不能以样本通过宣称全战役平衡。

### 全战役收口与公开发布

- 60/60 真实关卡、Progress 解锁/设置/高分、正式战役和实验记录、桌面/触屏操作、资源恢复及中英文内容均完成集成验收；性能与内存基线用真实负载测量，不以修改原版规则掩盖资源问题。

## 集成与发布门槛

实现任务在 `gunsnglory` 集成分支上积累可独立验收、可回滚的切片。普通公开发布次数除以已验收实现切片数不高于 20%，只在完整里程碑或核心可玩性、结算、档案安全的重要缺陷时提前发布，例外也计入比例。已确认起点为 3 次成功发布/6 个验收切片；本次 16 个验收切片已完成发布，当前累计为 4/22（18.2%）。下一次普通发布前至少再增加 3 个验收切片，使累计达到 5/25（20%）。检查点和文档更新不计产品切片，不单独发布。

发布达到门槛后，按仓库流程合并到 `master` 并推送；等待现有工作流成功，静态应用确有部署时，再以 Codex 内置浏览器实测线上行为。未通过 CI 或线上实测不得报告发布完成。
