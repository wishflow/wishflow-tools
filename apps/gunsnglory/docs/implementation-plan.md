# 实施计划

本文只保留当前进度和未完成任务。规则见[产品规格](spec.md)，模块边界见[架构](architecture.md)，存档及模拟契约见[存储契约](storage-contracts.md)和[模拟与自动化契约](simulation-and-automation.md)。每轮开始先核对代码、测试和提交，再细化后续步骤；每完成一个切片就更新本文并关闭已完成项。

## 当前状态

- 正式战役已完成 **4/60** 关：Cow Gulch、Apache Valley、Fort Kaboom、Tech Town。
- Tech Town 已登记为 New Mexico 第 4 关，接入原图、四条路线、八波、初态、玩家池动作、双语对白、正式进度和结算路径。关卡首次开放时只出现 type 1–4 普通单位；重玩时按档案里程碑开放已解锁的特殊地图单位，Gambler 与 Casino 同步出现或隐藏。
- 全屏构图已修复：逻辑视口固定1024×576，全屏舞台完整等比居中，不裁切、不拉伸；全屏适配不再改地图缩放，舞台外输入无效。Playwright定向测试覆盖16:9、宽/窄横屏和竖屏旋转门；内置浏览器真实全屏实测窗口1728×1080、舞台1728×972、上下各留54px，退出后恢复窗口模式。普通页面中的Usagi覆盖游戏窗口，全屏时隐藏。常规验收仍默认窗口模式。
- 自由游玩已接入独立首页入口。四个已实现关卡无视战役前置状态开放，简单/中等/困难均可选；56个未实现关卡仍显示并禁用。`free` 会话使用正式波次、生成池、关卡对白和结算规则，但不会调用 Progress；难度只保存在菜单临时状态。空档案进入 Tech Town 时，仅为构造该关卡提供其基础地图访问单位，其他特殊单位仍按档案里程碑解锁。自由结算明确显示不写档案，回放记录和导入验证保留 `free` 源模式。
- 自由模式切片定向验证通过：`tests/free-play.test.ts`、Progress 正式结算隔离、难度/回放/战役回归共26项单测通过，类型检查通过；Playwright 菜单回归3项通过，自由模式端到端测试1项通过，覆盖零进度进入 Apache Valley 困难、四关入口状态、Tech Town 首波及档案难度/进度/最高分/revision 保持不变。
- Profile 档案和实验数据档案已实现为两个独立的 v1 JSON 文件。Profile 档案不含 revision，导入前确认并通过 ProfileRepository 条件事务整体替换；实验档案包含所有数值方案及完整比较报告，在单个 IndexedDB 事务中合并方案、比较索引与附件，重复内容跳过、标识冲突保留本地并报告。两者入口均位于主菜单“选项”；实验工具在选项页内折叠，复用原有实验面板；回放格式未改。
- 数据档案切片定向验证通过：类型检查通过；Progress、两类档案编解码、实验仓库和实验流程相关单测共44项通过；Playwright `t38-data-archives.spec.ts` 两项通过，覆盖档案下载/替换/取消/未知版本、实验导出导入/重复去重/冲突保留、跨数据库隔离，以及 profile 和实验 IndexedDB 写事务失败后无部分写入。
- Playwright 定向 E2E 使用 `pnpm exec playwright test tests/e2e/<spec>.spec.ts --workers=1`；避免在 `pnpm run test:e2e -- ...` 后追加 spec 参数，该转发形式会误触发全套测试。
- IndexedDB repository 的多个实例共用相同数据库；共享契约在同库上验证幂等导入与冲突，只有需要验证“导入到空库”时才另开浏览器 context。检查弹窗是否留在游戏窗口内应验证 `closest('.game-frame')`，不要要求它是直接子元素，因为 `.game-stage` 是合法的中间容器。
- 浏览器测试默认静音；除专门验收音效外，不开启声音。REA/APK 静态材料优先；仅当具体问题无法从静态证据判断时，才安排一次 Android 定点观察，不重复启动或检查已证实行为。
- 上一批的显示修复、Gold Transport、玩家池多槽动作、Tech Town、全屏构图和自由模式共 6 个实现切片已完成。本地完整检查通过：类型检查、391 项单测、构建和 97 项 Playwright E2E；E2E 需允许本地服务绑定 `127.0.0.1:4173`。该批通过 GitHub Actions `42253109012` 发布到 GitHub Pages 与 Cloudflare Pages；两处 `build-info.json` 的来源均为 `6940fcbaa4b2520d8be5f1a81243c9a25815e4e0`。内置浏览器在窗口模式、静音下验证主菜单、地区/关卡选择、进入 Cow Gulch、退出未完成关卡和 Usagi 拖动；未启用全屏或音效。移动端竖屏由 Chrome 157 定向检查和完整 E2E 覆盖；当时的内置浏览器会话未提供移动视口覆写。构建仍提示主 JS chunk 超过 500KB，但不影响构建或测试。
- 手机竖屏 CI 曾连续三次发现清除选择按钮超出可视区：Chrome 157/Linux 测得操作行宽 255.6px，主要按钮与间距约 265px，超出 9.4px。扩大操作行或把摘要移出叠层会遮住地图并导致触屏选择、拖动和缩放回归，均已撤回。最终保持原摘要与操作行布局，将窄屏按钮水平内边距从 0.3rem 缩至 0.18rem，主要按钮总宽减少约 11.5px；定向 CI、全套本地检查和最终发布 CI 均通过。

## 当前批次：游戏内 UI 与交互重构

**范围：**在现有 TypeScript、Canvas 和游戏规则上重做游戏框内的 UI 状态、层级和交互。保留共享站点外壳、存档格式和公共 API；不引入 React/Preact，不改战斗规则。浏览器验收默认窗口模式、静音。

基础 OverlayHost、APK 暂停流程和主菜单辅助页面切片已实现：游戏面板由 frame-local 遮罩管理，FrameChrome 固定；HUD 暂停图标打开原版木牌暂停板，Continue 才恢复模拟；Restart、Close 使用原版确认框，取消返回暂停板，Options 返回时保留暂停状态，Sound 更新设置与图标。主菜单提供 Start、Free Play、Help、Options、Sound；帮助说明和网页设置已移入对应页面，战斗工具条不再显示 Controls、文字 Sound、Pause/Resume 或 Campaign 快捷按钮。详细漏测与根因见[经验记录](experience-log.md)。

### 1. 整理主菜单、帮助、选项和声音入口

- [x] 主菜单提供 Start、Free Play、Help、Options、Sound，并沿用已有原版菜单板/木按钮素材。移除仅网页添加的常驻 Controls 折叠栏、战斗文字声音按钮和 `Campaign` 快捷按钮。
- [x] 网页操作说明放进游戏风格 Help 面板，可从主菜单和暂停板的 Options/帮助路径到达。Options 收纳测试倍速、档案及实验扩展，并清楚区分原版声音设置。
- [x] 本步定向 E2E：菜单四入口可用；Help/Options 可由暂停流程进入并返回原暂停状态；Sound 状态与现有设置保持一致；中英文切换不溢出，暂停状态切换不改布局槽位。`t02`、`t09-pause`、`t29-campaign-menu` 共24项通过；菜单样式调整后重跑 `t29` 5项通过。
- [x] Help/Options 经过本地内置浏览器窗口模式、静音检查。实际截图发现帮助文字曾以浅色显示在羊皮纸上、跨入右侧装饰栏，且末项贴住返回箭头；现统一为深色文字，将标题和说明约束在左侧纸栏并留出返回控件空间。`t29` 检查实际计算颜色、字号、栏位边界和返回按钮重叠。

### 2. 将操作弹窗和结算迁入 OverlayHost

- [ ] 招募、地图雇佣、升级、Gambler、波次对白、重开/退出确认与结算面板都由 OverlayHost 管理；同一时刻仅一个主要游戏内面板可交互，嵌套确认关闭后回到正确父面板。对白打开期间不渲染或启用 Resume 控件；完成对白只关闭对白并进入该波正式状态。
- [ ] 普通面板采用 APK 确认框与木按钮资源/布局；暂停与菜单用木牌资源，波次对白保留羊皮纸专属图像。避免以通用 CSS 主题替代原版素材。
- [ ] 本步定向 E2E：逐类验证 frame 范围、遮罩、主要按钮真实点击、关闭后的模拟状态和活动面板；结算可保存/重试/返回菜单且不与其他面板重叠。

### 3. 固定网页辅助控件并完成视觉回归

- [ ] 全屏按钮固定在 FrameChrome 角落，菜单、暂停板、帮助和业务弹窗状态中均不隐藏、不搬动、不遮住主要按钮；全屏进入/退出保留当前 UI 状态。Escape 退出全屏不改变模拟状态。
- [ ] 桌面地图缩放位于地图边缘，移动端保留捏合缩放；两个网页辅助控件都不放在业务弹窗或操作工具条内。
- [ ] 按钮采用固定槽位，同语言下切换状态文案不改变相邻控件位置；切换站点语言后允许按译文重排，但不得溢出、重叠或遮挡交互目标。
- [ ] 桌面、手机竖屏和横屏用真实浏览器布局检查菜单、战斗 HUD、暂停板、确认框、Help/Options 和结算截图；窗口模式为常规验收基线，全屏仅在该功能专门验收时启用，声音保持关闭。

### 4. 批次验收、集成与发布

- [ ] 回归全部现有 E2E，清理剩余依赖旧 Controls 折叠栏的断言；按 APK 流程检查状态迁移、唯一活动面板、实际命中与结果，不能只断言元素可见。
- [ ] 分别运行每步对应的定向测试并本地提交；整个重构通过后运行一次 `pnpm run test:ci`，失败项修复后重跑失败项和最终整套检查。

## 发布门槛

每个切片先跑针对性检查并提交；整批切片全部完成后运行一次应用完整检查与适用共享检查。公开发布按根目录及本应用 `AGENTS.md` 执行：整批验收后 squash 集成，核对 CI、部署来源 SHA，再用内置浏览器验收；普通发布比例目标不高于 20%，按实际成功发布与已验收切片数记录。
