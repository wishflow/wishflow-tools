## 开工和关闭规则

每次开工先检查当前分支、近期提交、工作树改动、实现和测试，确认问题仍存在且任务未集成；计划状态不能替代代码审查。已有通过证据仅在代码回归、验收链失效或新增边界时重跑。

活动任务须能独立实现和关闭，并列清：用户可观察结果、原版/设计依据、受影响模块、独立预期、真实关卡/对象、失败边界、验证方式、前置和回滚点。实现切片可以组合紧密相关的小任务，但各退出条件须分别满足。完成后同一提交更新本计划、移除关闭条目并只扩展接下来需要执行的任务；提交说明写清行为、命令/验证结果及限制。计划不保留逐任务历史、已完成表或逐次验证日志。

## 集成与发布门槛

按已确认约定在 `gunsnglory` 分支积累独立验收切片。普通公开发布率按累计成功发布次数除以累计已验收实现切片数计算，保持不高于20%；只有完整里程碑或核心可玩性、结算、档案安全的重要缺陷可提前发布，例外也计入。当前发布门槛基线为3次成功发布/6个验收切片；下一次普通发布前至少再增加14个验收切片，使总数达到4/20。每次更新计划时同步更新这两个小计。不为文档、测试或小修单独发布。

发布达到门槛后按仓库流程集成到 master 并推送，等待现有工作流；静态应用确有部署时，再用 Codex 内置浏览器实测公开行为。未完成CI或线上检查不得报告发布完成。
