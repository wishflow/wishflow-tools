# 实施计划

本文是 Guns’n’Glory 的唯一活动进度与任务来源，只保留未完成的工作。产品行为见[产品规格](spec.md)，模块边界见[架构](architecture.md)，存储边界见[存储契约](storage-contracts.md)，步进和随机语义见[模拟与自动化契约](simulation-and-automation.md)。

已关闭任务从活动清单删除，代码与提交记录保留实现历史。每完成一个切片，先核对实际代码和验证结果，再从本计划移除并细化下一项，避免照旧清单重复工作。

## 版本同步门槛

当前代码分支与公开页面尚未同步：集成分支已包含 Apache Valley（map02），`master` 发布路径尚未包含该关；无发布参数访问公开页面时仍显示 **1/1**，第二关禁用。仓库工作流只在 `master` 推送时构建并发布静态站点，见[Pages 工作流](../../../.github/workflows/pages.yml)。页面当前没有可核验的构建来源 SHA，因此公开页面的实际提交版本无法仅凭 URL 或 UI 确认。

下一次公开发布必须满足以下条件：

1. 发布内容包含当前已验收的 Apache Valley（map02）集成代码；发布提交来自 `master`，不以本地 `gunsnglory` 或旧标签页代替发布来源。
2. 构建产物提供可直接读取的源代码提交 SHA；部署完成后，公开页面报告的 SHA 必须与预期 `master` 发布提交一致。
3. Actions 发布工作流成功后，用 Codex 内置浏览器访问无旧 `release` 参数的公开 URL，核对来源 SHA、战役关卡数量与整批功能。至少确认 map02 已显示并可按档案状态进入；随后按本计划中的待办验收 UI/UX 功能。
4. 若 SHA 不匹配、无法读取，或页面仍显示旧关卡清单，保持发布未完成，先修复来源标记、发布同步或缓存问题，再重新执行核验。

当前公开页面显示旧关卡清单是版本落后的直接信号，但它本身不能证明具体部署提交；在构建产物暴露 SHA 前，不得将 URL 参数、工作流成功或旧浏览器标签视为版本一致的证据。

## 当前活动任务：原版菜单与游戏内交互

### 下一切片：正式战斗操作与招募/升级入口

**目标与边界：** 玩家进入正式关卡后，只看到能在当前关卡产生真实结果的操作。以 APK 控件和已实现内容为基线，不为填满工具栏虚构单位、升级或战斗能力；不改变 `Game` 规则、原版价格或进度语义。

**实现与验收：**

| 项目 | 实现范围 | 可判定验收 |
| --- | --- | --- |
| 正式战斗操作 | 对照 APK 正式 HUD、当前 `game-toolbar`、`mapHireControl`、通用 `recruit-unit`/`upgrade-unit` 处理器；正式战斗仅保留可用的原版操作。实验、回放、档案和调试操作留在页面级档案区 | 从菜单进入 Cow Gulch 与 Apache Valley 后，工具栏没有无地图投放路径的通用招募；试玩/测试入口仍可访问需要的研究控制，但不会出现在正式战役 |
| 地图招募 | 复用睡眠单位地图对象和现有雇佣流程；只有选中可雇佣目标时显示/启用操作，并标出角色和价格；低余额、重复确认、失去目标时不得扣款或生成幽灵库存 | Cow Gulch 枪手与 Apache Valley 至少一种枪手、Mexican 通过真实鼠标/触屏操作成功入职；无目标、错误类型、低余额、重复点按均无额外扣款/部署；读取已确认原版费用作为测试预期 |
| 升级入口 | 逐关核对 `maxUpgrades` 与现有升级动作；Cow Gulch、Apache Valley 上限为0，不显示升级控件。只有真实可玩关卡包含可验证升级时才实现相应 UI | 两个已实现关卡均没有可点击升级入口；内核升级规则与实验/研究控制不因正式 HUD 隐藏而改变；不得为当前两关虚构升级 |
| 触屏与布局 | 鼠标和 Pointer Events 使用相同目标状态；操作位于 `.game-frame`，不遮挡地图关键区域或既有相机手势 | 桌面与320×844/844×390浏览器视口可操作；切换横竖屏、选中/取消单位、暂停和对话后状态一致，无横向溢出 |
| 验证 | 新增针对正式 HUD 投影和招募失败边界的测试；仅重跑关联 unit/E2E、`pnpm run typecheck` 与 `pnpm run build` | Playwright 使用正式入口，不注资、不改波次、不用 fixture 替代真实关卡；全套 `test:ci` 留到本 UI/UX 批次结束 |

**停止条件：** 若 APK 控件行为仍有无法由资源、反编译调用链和当前状态机确定的部分，保留当前可验证操作并记录准确阻塞，不以推测新增控件。该切片通过针对性测试后本地提交，随后更新本计划；不单独发布。

## 集成与发布门槛

实现任务在 `gunsnglory` 集成分支上积累可独立验收、可回滚的切片。普通公开发布次数除以已验收实现切片数不高于 20%，只在完整里程碑或核心可玩性、结算、档案安全的重要缺陷时提前发布，例外也计入比例。已确认起点为 3 次成功发布/6 个验收切片；本轮首关验收与地图视口修复已随里程碑发布，当前累计为 **5 次成功发布 / 25 个已验收实现切片（20%）**。检查点和文档更新不计产品切片，不单独发布。后续公开发布按仓库流程合并到 `master` 并推送；等待现有工作流成功，静态应用确有部署时，再以 Codex 内置浏览器实测线上行为。未通过 CI 或线上实测不得报告发布完成。
