# 模拟与自动化契约

本文是游戏命令、步进、时间/随机、回放与实验运行的唯一真源。公共能力边界见[架构](architecture.md)，规则结果见[产品规格](spec.md)，存储语义见[存储契约](storage-contracts.md)。

## 所有权与运行入口

浏览器、脚本和策略均复用 `Game` 的生产规则。场景/批次由 `Experiments` 协调；外部消费者不调用内部 `SessionController` 或 `ScenarioRunner`。UI传游戏意图，策略只看获准的观察档位；调试查询可以更完整但不得隐式提供给策略。

战局有正式、调试、实验、回放模式，开局固定模式。Progress 仅接受本次正式模式的终局。`Game.prepare` 解析并校验完整原版/实验参数，返回不可变 `PreparedSetup`；不创建会话、不读取时钟、不抽随机、不推进。`Game.open` 使用玩家选项或 `PreparedSetup`，返回会话及不可变 `StartRecord`，不启动循环、不推进首帧。确定性重放使用同一规则版本、内容版本、完整输入、时间与影响规则的环境，不重新猜测初始化条件。

## 命令、帧与推进

普通命令表达业务意图：选择、移动、释放、雇用、升级、确认开波和特殊对象交互。调用者不提交鼠标像素、DOM引用、`sequence` 或 `frameIndex`。Game 校验请求，内部控制器分配命令标识、序号和目标帧；在基线规定的输入边界按序消费，再执行规则更新，返回回执、事件和只读视图。暂停时拒绝会改变战局的输入。

- 可选幂等键相同且载荷相同，返回原回执；相同键不同载荷拒绝。未提供键的两次输入是两次操作。
- 实体不存在、现金不足、当前状态不允许时返回业务拒绝，不变成未分类异常。旧 session ID、过期/不连续的导入帧和越预算队列明确拒绝。
- 精确回放输入只能经受控 driver/import 路径，核验 session、顺序、帧和目标位置；普通 `dispatch` 不接受任意帧注入。回放保留已执行命令，调试记录另记拒绝输入。
- 一个会话任一时刻只有一个推进所有者。浏览器循环、脚本和实验 runner 不得并行 step；交接前先停旧 driver。步进重入或关闭后调用明确失败。

每一 `step` 同步推进一个0–100ms可变逻辑间隔，并接收明确的`dtMs`、受控`nowMs`、命令和影响规则的环境状态。模拟顺序固定为对象→敌人→单位生成→单位移动→投射物→波次→生成池→音效状态；边界、输入和终局检查按原版调用点执行。Java向零截断、float32舍入点与集合顺序均为兼容行为；实现前以独立源样例固定边界。`nowMs`不可只由累计dt推算，因为截断后的dt不一定等于读数差。

浏览器用真实间隔并按基线截断；倍速只加快消费同一帧序列，可减少绘制，不得把dt乘倍率冒充等价游戏。暂停不推进；单步固定16ms并复用普通路径，只推进一帧后保持暂停。切到后台暂停并重设计时基线，恢复不追帧。等待开波保留原版允许更新的子系统，不等价于完整暂停。长任务同时限制模拟时间、帧数和实体数，避免零dt无限运行。

## 随机、环境和视图

APK 的 `Game.Randomizer.nextInt(bound)` 先调用 Java `Random.nextInt(bound)`，随后调用 `nextLong()` 并以所得 long 重新 `setSeed()`，再将 `firstRandom` 设为 false；重置时重新置为 true。REA 静态调用图中该包装器只有 Gambler 抽奖和手牌动画的两个调用类。网页按 `StartRecord.randomSeed` 初始化规则流，回放规则版本为 `gng-rules-21`，格式版本仍为2。Gambler 规则先按规则流抽奖，再抽 `GamblerResults` 手牌模板，最后以 `[4,3,2,1]` 的边界不放回洗牌花色；结果牌面、奖项、冷却与待生成奖品均进入 GameView 和 replay checkpoint，UI 不另抽随机。规则流尚未抽取整数时奖池排除输钱项；失败和冷却拒绝不消费规则随机值。

APK 另有 `Util.random(bound)`：它调用单独的 `java.util.Random`，并在 `Util` 类初始化时以系统毫秒时钟设 seed；它与 `Game.Randomizer` 不是同一随机源。网页通过 `deriveSessionRandomSeed(StartRecord.randomSeed, 'game-util')` 派生标准 Java `Random` 兼容流，当前已接入预览敌军速度、战役波次/生成池抽取、敌军出生点与编队/颜色、路线转向、马车残骸与乘客、战役单位池、补给箱和列车烟雾。Gambler 仍只使用规则流。地图 `BackgroundMap.createVariationMap` 在 APK 会消费 `Util.random` 选择图块；网页 Tech Town 场景当前用固定内容资源组装，未按每局 seed 重抽地面/道路变体。未实现的友军随机移动尚未接入；实现对应行为时须复用会话 Util 流。

为了让视口和音频冷却不改写 `GameSession` 模拟序列，网页将 APK `SfxManager` 及单位雇用语音放在从同一 StartRecord seed 经 `'presentation'` 域派生的表现流中。位置音效在可见范围与配对冷却检查通过后才抽取变体；单位雇用语音用表现流的 double 值选变体。静音仍按相同事件处理和消费已接受的表现随机，只跳过实际播放；相机裁切可能改变表现流消费，但不得改变规则流或会话 Util 流。APK 火箭近距离跳跃角度使用 `Math.random()`；网页用独立、从会话 seed 初始化的确定性适配流，避免改变规则流调用次序。APK 的 `Util` 时钟 seed 不落盘，网页无法复现原设备的同一随机数列；域分离也意味着网页表现音效不会复现 APK 全局 Util 流与音效间逐个随机数的交错顺序。

玩家/AI的策略观察只能暴露对应能力，如公开 HUD、玩家所见目标或更宽的分析视图；隐藏的全局状态只供受控调试。控制频率、可见信息、超时、无效动作处理和动作日志属于策略版本。策略计算不得直接修改 Game 状态；脚本动作仍经过同一 Game 命令校验。

## 回放

回放是输入记录，不是续玩档案或视频。`StartRecord`保存原始规则和内容版本、完整数值/摘要、模式、初始条件、随机状态和时间环境；输入流按帧保存已接受且执行的命令及必要环境变化；规则事件/状态检查点用于比较。缺少兼容版本、输入损坏、摘要不符或序列不连续时明确拒绝，不以当前版本静默解释旧输入。

导入回放创建新 session ID，标为replay模式；原始正式记录不能使重放终局变成正式结算。相同固定输入比较规则状态、事件和终局摘要；执行实例 ID、真实耗时可不同。暂停期间输入、重开后旧命令、随机消费和绘制环境都须在格式语义里明确。正式档案不保存中途状态。

## 场景、实验和指标

Scenario由真实关卡/初始状态、玩家或固定策略、时间与环境、样本和预算组成。运行开始前冻结方案完整值、内容/规则版本、场景集、策略、seed、时间设置及预算；每场由 `Game.open` 产生实际 StartRecord，并在首帧前与冻结值核对。编辑草稿不影响运行。

运行状态与游戏结果分开。状态包括`completed`、`cancelled`、`budget-exceeded`、`failed`、`invalid-input`；只有正常规则终局的`outcome`才是`victory`或`defeat`。`stopReason`区分生命耗尽、通关、模拟预算、真实超时、资源限制与执行异常；错误、超时、取消和预算终止不得计入胜败分母。结果还保留有单位的`metrics`、逻辑产物标识`artifacts`及规则/内容/配置/策略/环境/输入来源`provenance`。报告同时列计划数、有效样本、各种停止原因、未完成比例和指标缺失。

首批指标：胜率、胜负时剩余生命、胜利耗时、现金收入/支出/余额、单位伤害与击杀成本、逐波峰值敌人/漏敌/持续时间/损失生命，以及执行耗时、帧数、实体峰值和产物大小。每项定义单位和归属；过量伤害不当成收益。相同帧/事件重复消费不能重复累加。比较报告同时显示基线、实验、差异分布和样本数；单个seed/均值不能证明总体平衡。

浏览器与Node runner按有界帧批让出事件循环，处理取消和墙钟预算；step仍同步且不改变帧/随机序列。worker独立持有会话、策略状态和随机源，可只读共享不可变内容。并行报告按输入顺序输出，单场语义结果应与串行一致；worker错误、取消与游戏败北分开。重试新建attempt，旧worker迟到结果不能覆盖新尝试；未实现检查点时重启从冻结初态再跑，不拼接轨迹。

## 当前本地批次 CLI

入口：

```bash
pnpm --dir apps/gunsnglory run simulate:batch -- --input <file.json> [--output <file.json>|-] [--workers 1-4]
```

输入为不超过1MiB的schemaVersion 1 JSON：`batchId`、1–25个唯一样本`{id, randomSeed}`及可选`budgets`。CLI固定场景`cow-gulch-single-wave@1`与策略`start-wave@1`；拒绝任意脚本、路径或`latest`版本。默认每场上限2000帧、200000ms模拟时间、100实体、30000ms墙钟时间、每40帧让出；覆盖值仍受Experiments硬上限约束。缺省串行；`--workers`可选1–4，>1时每个样本在独立Node worker执行，结果仍按输入顺序排列。

输出JSON保留输入、每场结果、分类计数、失败原输入和取消时未启动输入。批次`completed`只说明计划项均处理，不代表每场胜利。SIGINT/SIGTERM协作取消并导出已完成部分；退出码0表示已调度运行均正常完成（胜利/败北均正常），1为未完成或执行错误，2为参数/输入错误，130/143为中断/终止。CLI不得写Progress或IndexedDB。

MCP或其他agent入口仅在有实际消费者时增加，复用公共Interface；每个新agent入口按仓库规范用`pi`实际加载并完成真实调用，不能用单测或手工直调代替。
