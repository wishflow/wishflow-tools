# 可玩地图覆盖矩阵

## 范围与读法

矩阵只包含 officialCampaignStages 中的正式关卡。M0 从 official-campaign.ts、campaign-catalog.ts 和每张地图 JSON 的 source.resource 交叉生成本表；运行时目录为 41 个场景，映射到 41 个不同 TDM。关卡 1–10 使用 td_map_01–10.tdm，关卡 11–41 使用 td_map_14–44.tdm；TDM 11–13 不在正式战役映射中。Level 42–60 未接入，不计入本矩阵。

表中测试链接只是当前可查的入口索引；未逐条复核断言前，不算该分类已验收。关卡 JSON、测试和静态报告分别支持不同结论，不可互相替代。M2–M3 将逐项复核并更新状态：

- **敌方路线/道路层：**每个出生点、所有有效方向场分支、出口、道路/桥绘制层及最终地形通行性。M1 已逐图核对路线中心与静态图层；不包含动态单位脚底或完整 Canvas 镜头。
- **我方锚点/碰撞：**逻辑脚底、APK 碰撞框、地形/街道采样、睡眠与活动单位、建筑和地图专属障碍。
- **交通实体：**按 TDM 和场景生成结果判定列车、马车、蒸汽船等是否存在；存在时核对部件、组距、路线/轨道、锚点和端点缓冲；不存在时写明 TDM 依据。
- **生产画面：**以网页生产渲染与同图 TDM/派生层叠图确认道路贴合、路线中心和单位脚底；只看测试名称或 PNG 资源存在性不算目视验收。

## M0 盘点结果

- 41/41 正式场景均解析到唯一 TDM 及尺寸；映射由运行时代码和地图 JSON 得出，不依赖文件名猜测。
- 当前有 36 份带主题的地图静态审计。缺少独立静态审计文档的是 Level 1–4 与 Level 41；这些行仍有地图 JSON/测试入口，缺报告不等于已证明有缺陷，也不等于结论已闭合。
- [玩家碰撞审计](player-collision-audit.md)记录的原始修复批次覆盖27张地图；后续共享断言已把静态对象框、单位锚点和 raw36 边界探针扩展到41张。新增桥面测试逐一覆盖41张地图的已渲染可走连通桥段；地图特有对象会话覆盖和生产画面核对仍按 M2 继续。
- M1 已形成 41 张静态路线/道路层联系表并逐图目视核对；目前仍没有 41 张完整生产战斗画面对照，故“生产画面”列继续标为未逐图核对，不把静态联系表外推为动态单位或碰撞验收。

## M1 路线与静态图层结果

- 41/41 张地图均读取正式运行时 `GameView.route` 或 `GameView.routes`；路线节点与对应 TDM 路径交叉核对。通用展开器与运行时数据逐路线匹配 40/41 张；Cactusville 的角落出生点不适用于“按边界首个命中方向”推导入口方向，改由 `cactusville-map.test.ts` 独立检查三条路线、出口、路线格及方向分支。该异常属于审计器假设错误，不是网页路线差异。
- 41/41 联系表以 `map.background` 和 `map.streets` 的实际 `RenderTile`、生产图集资源和裁剪框生成，并叠加运行时路线中心、出生点、出口和转向点。逐图检查未发现路线中心与道路/桥层明显错位，也未见路线折线退化成直线回退。
- Tech Town TDM raw code 66 的铁轨交叉由 `tech-town-map.test.ts` 覆盖，是有效路线交叉，不应按“普通道路格”误报。
- 联系表不是完整 `drawGame()` 输出，不能据此关闭玩家脚底/碰撞、动态单位走位、装饰物排序或相机裁切。上述项仍按 M2/M3 和“生产画面”列分别验收。

## M2 现有自动覆盖与剩余缺口

- **已全图自动检查：**`player-collision.test.ts` 逐关检查41张地图上每个 APK 静态对象 TDM marker 都只生成一个对应尺寸的碰撞框，并排除明确不阻挡的 marker；`player-unit-anchor.test.ts` 逐关核对活动单位/唤醒角色脚底锚点，并对每张地图选一个 raw36 墙边做短移动探针。表格“我方脚底/碰撞”列据此标为 `M2 全图自动覆盖`。
- **已做真实桥面移动的地图：**`all-maps-player-bridge.test.ts` 遍历41张正式地图的生产桥面绘制命令，按 TDM 格码和阻挡岸边划分实际可走连通桥段；每个桥段均以对应正式地图数据建立短 `GameSession`，检查沿桥移动及两侧边界停靠。覆盖 raw80 横桥、Railroad Ranch（Level 9）实际桥面贴图上的 raw81 横桥，以及 raw88 竖桥。该测试不是 Android 原版运行画面对照。
- **已做真实对象阻挡会话的代表地图：**Snake River、Loot Lakes、Six Grandfathers、Badlands、Ghost Town、Ice Rocks、Frost Station、Wayne Waters 和 Tech Town 覆盖睡眠/活动单位、Saloon/Fort/Shack、树石/骨骸/水塔、铁路挡车器、水岩、解锁 Casino/Dynamite 和奖励接触。碰撞框生成对41图逐 marker 检查；真实移动按 APK 对象类别及特殊规则覆盖，不代表逐个移动过每张地图上的每个对象实例。
- **已做定点生产 Canvas 观察：**`tests/e2e/t43-player-bridge-anchor.spec.ts` 的 Cow Gulch raw80 横桥、Cow Gulch raw36 墙边和 Steam Valley raw88 竖桥三项均通过，记录脚底 fine 坐标并保存窗口/静音画面；命令为 `PLAYWRIGHT_PORT=4174 pnpm exec playwright test tests/e2e/t43-player-bridge-anchor.spec.ts --workers=1`。坐标、截图路径和 APK 同帧画面对照限制见[经验记录](experience-log.md)。这三处是网页生产画面的代表样本，不是41图逐图截图，也不是 Android 运行验证。
- **M2 结论：**41张地图的自动静态框、单位锚点、raw36 边界探针和已渲染可走桥段会话覆盖均完成；主要对象类别以代表地图真实会话覆盖。网页生产画面只对 Cow Gulch 与 Steam Valley 做三处定点观察，未完成41图逐帧视觉比对。精确差异与未知边界见[玩家碰撞审计](player-collision-audit.md)和[经验记录](experience-log.md)。

## M3-A 交通实体存在性

[正式关卡交通实体清单](map-transport-inventory.md)逐关记录静态火车/蒸汽船组、初始格点和波次运输请求。正式 41 关中，27 关有地图摆放运输单位（48 组、238 个部件），其余14关没有初始 `train-*`/`steamer-*` 组；41 关的波次定义均含至少一种敌方运输组请求。该结果关闭 M3-A 的存在性分类。

## M3-B 现有行为测试覆盖审计

## 审计状态更新规则

每次关闭一张地图的一类检查，只更新对应单元格，并在该行链接具体来源和测试。可用状态为：源数据已核对、自动断言已核对、生产画面已核对、有差异待修、不适用（附 TDM 依据）。交通实体列中的“M3-B 覆盖已审；行为缺口见清单”表示现有测试覆盖已逐图登记，不代表该关的运输行为已经通过；具体组数和动态路线缺口见[交通实体清单](map-transport-inventory.md)。未闭合事项写清缺少的证据/操作与复核判定；禁止以“测试全绿”“相邻地图相同”或“截图未发现问题”关闭其他地图。
