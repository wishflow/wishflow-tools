# 产品规格

本文是产品目标、用户可见行为和原版规则的唯一真源。目标能力不表示已经实现；当前进度和未完成任务见[实施计划](implementation-plan.md)。模块边界见[架构](architecture.md)，持久化及模拟协议分别见[存储契约](storage-contracts.md)和[模拟与自动化契约](simulation-and-automation.md)。

## 目标与范围

以 Guns’n’Glory FREE 1.8.6 的离线玩法为原版基线，提供无需安装原生客户端的浏览器游戏，并支持观察规则、复现操作与比较数值方案。玩家需要完整战役、操作反馈、进度和设置；学习者需要暂停、单步与状态检查；测试者需要确定性回放、失败分类和无画面批量运行。

目标内容为六个区域、每区十关，共60个真实关卡。APK 中63个地图文件不等于63个关卡：战役关卡1–10映射 map01–10，关卡11–60映射 map14–63；map11–13不在该战役映射中。完整关卡还包括初态、波次、对象、解锁和结果规则，不得以地图加载或合成样本计数。

浏览器支持桌面鼠标与手机/平板触屏，使用英文原版文案并补充中文；共享站点语言状态由 `@wishflow/site-shell` 管理。画面保持16:9逻辑比例，Canvas逻辑画布1024×576。正式档案保存进度、设置和本地高分；未完成关卡重开，不提供正式战局续玩。游戏内容可离线游玩，但不承诺首次断网打开或PWA全量预缓存。

广告、支付、统计SDK、外部排行榜、多人同步、服务端权威战斗、任意代码插件、通用编辑平台和未证实的新玩法不在范围内。后端不是纯前端正式版前置；身份、远程档案、内容分发与批量服务各自单独规划。

## 用户可见能力

- 选择已开放区域、关卡、难度与可用单位；通过鼠标/触屏选择、移动、雇用、升级及操作特殊对象。
- 理解生命、现金、波次、目标、伤害和胜败；关卡结束后查看结算并保存进度。
- 在桌面和移动视口内拖动地图/镜头并准确点选；界面可读、输入可取消、后台恢复不追帧。
- 暂停、逐帧推进、检查只读状态并从明确初态重放操作；观察工具不改变规则结果。
- 创建独立数值方案，冻结场景、策略与样本后比较胜率、生命、时间、经济和波次压力；未完成运行不算胜负，实验不写正式档案。
- 通过本地脚本/CLI复用生产规则，区分胜败、预算、取消、无效输入和执行错误；并行执行不得改变单场语义。

## 内容基线

研究分支 `codex/gunsnglory-spec` 的 `apps/gunsnglory/docs/research/` 以 `R/` 表示；先用 `git worktree list --porcelain` 定位该分支的实际 worktree，不写死绝对路径。若分支/worktree不可用，先从本地分支建立临时 worktree；资料仍缺失时只阻塞依赖该项的验收并说明原因。该资料是 APK 逆向与导入参考，不是原始源码；REA/JADX 输出属于反编译分析产物。构建和运行使用游戏自有内容，不依赖研究目录、REA 或分析工具。遇到冲突追到实际消费代码，不按摘要名称猜测。

静态清单已整理60关配置、527条 `newWaves`、1,377条 `addToWave`、86个生成池动作、63个地图文件、21个 unit type 映射、14组共44行升级数据、9行敌人设计数据，以及943个 PNG 路径和67个已导出 OGG。数组行数、文件数和 tile 标记都不是实际敌人数、可玩关卡数或功能覆盖率。八名可雇用角色为 Desperado、Mexican、Cannon、Indian、Grandpa、Sniper、Pyromaniac、Salesman；车辆/武器组件含 Train、Gatling、Steamer、DoubleCannon；特殊对象含炸药触发器/箱、Gambler/Casino。实际首次出现和解锁由关卡映射及消费者共同决定。

## 世界坐标、地图与移动

世界 fine 坐标每格为7680。Cow Gulch 是17×17地图。TDM action1/2/3分别表达生成点、转向点与出口，敌人在格心消费路线方向和分支。地图底图、道路、PriorityMap、碰撞对象和屏幕像素是不同数据；PriorityMap 不是寻路器。敌人路线按原版字段和状态实现，不能为视觉观感移动路线，也不能以 A*、通用物理或背景碰撞替换未经确认的规则。

原版玩家步行边界使用中心坐标。`edgeMarginFine = trunc(30720 / realTilesize)`；X为`[3840-edgeMarginFine, mapWidth×7680-3840+edgeMarginFine]`，Y为`[7680-edgeMarginFine, mapHeight×7680+edgeMarginFine]`。地图外背景格返回−1，不因此额外要求精灵完整留在地图纹理内；屏幕裁切属于 Renderer。敌人碰撞与玩家移动分离：原版敌人管理器碰撞框为7678×7678 fine units，使用物理坐标，不含绘制偏移，只登记 type8、4、5、6、3、7；同组排除，地图/地形/玩家单位不参加此查询。碰到异组敌人时撤销位移并恢复方向；紧邻碰撞者为同组时该成员本次不移动。type1/2步兵不参加管理器碰撞。越界清理与逃逸处罚分开，type8牵引件移除不扣生命或难度。

Cow Gulch map01 唯一东向 action1 生成点为(0,10)，首成员锚点(-11520,80640)。每次生成先沿行进方向临时后移共享生成字段两格，预检所需运输敌人，再通过公共出口恢复两格；碰撞失败保留池请求，成功才消耗。该临时值不得跨请求累计。

敌人 route、玩家碰撞、地图对象占格、列车轴向组移动、Steamer水域移动各自实现。保留原始异常字段，除非证据证明规格，否则不以外观改地图。实现/验收需固定世界坐标、镜头与状态，分开比较背景、道路/桥覆盖、静态对象、敌人路线和己方移动。

## Cow Gulch 开局、单位与波次

原始 L01 初始现金65、生命50、升级上限0、八波。原图有8个 tile96 枪手待雇用槽、7个 tile97 Mexican槽、1个 tile104 活动枪手；tile101/130按解锁规则判断，tile98–100/131不在图中。tile96–101、130–131在新局可创建activity4待雇用对象，仍受解锁控制；摘要中“仅从存档恢复时创建”是错误结论。tile102是type7 `DynamiteTrigger`，tile110是type8 `DynamiteBox`，不可互换。L01没有生成建筑tile112–114，也没有spawn-pool actions。

雇用把既有activity4对象切换为activity5并扣价，不新建单位或改其速度。枪手合法雇用边界为75现金；Mexican初始价100，速度1500 fine units/100ms、重型伤害500、AOE基础范围7680（一格）。L01不能升级；其65现金初态不能被测试注资覆盖。fixture可以单独验证75/74现金和重复确认边界。

速度按每100ms fine units消费并保留方向、逐帧整数截断和碰撞；基础伤害不等于实际扣血。枪手初始射击计数6、当前冷却为普通装填一半。实际静止射击且有目标时才消耗一发；每次先设普通冷却，第6发将特殊冷却加到普通冷却并重置计数。无目标不消耗；移动期间冷却仍更新。升级将计数重置6、冷却设成新档普通冷却一半。无其他奖励时第6发后各档冷却为2000/1650/1650/1300ms。

波次配置按原始 `GameDesignWaves` 调用顺序解释，`newWaves`/`addToWave`不可按数组下标配对；一波可有多个调用。wave pool type 2–11 经 WaveManager 映射到 EnemyDirector request type，不能混为敌人 type。L01 pool type2–5映射为type1步兵组，成员数1–4；每个请求先抽一次`90+random(20)`速度比例供全组共享，成员各自无放回取四种绘制偏移之一，再抽男女外观和颜色，并有独立unitGroup。

Wave03 raw vector `[0,0,0,0,0,3,0,0,0,0]` 的第六项是 pool type7，映射为 request type4；每次成功生成type8牵引与type4车厢同组，不是生成type7敌人。该波HP60%、speed100%、spawn0、base delay3000ms；请求成功间隔6000ms、碰撞失败以3000ms重试且不消耗请求。运输组按波速100%，车毁乘员另抽速度。第四至八波混合池。配置调用数不等于最终敌人数。

敌人 type4/5/6死亡派生残车与最多4名步兵。乘员数`n=trunc(random(trunc(difficulty/50)+average×10)/10)`，average分别2/4/0；type1/2随机、使用四种固定绘制偏移`(-1280,-1760),(1280,-1760),(-1280,800),(1280,800)`。偏移只用于显示/特定目标分支，不改寻路与碰撞坐标。乘员沿原车方向，使用当波HP倍率、`90+random(20)`速度和独立组号。对象规则、奖励、残片/乘员只由 Game 更新，不由动画回调生成。

## 战斗与结算

玩家选择存活敌人作为优先目标。输入点先补偿Y四分之一格，输入与敌人绘制偏移均量化到十分之一格；选择距离严格小于`0.8²`格的最近目标。重复目标取消，半径外不清标记；点type8转为同组非type8车体。目标标记不取消己方选择。

自动攻击候选为存活、非type8、在射程内的敌人，要求`50 < d² < maxSquareRange`。分数=`getPrio(fullX,fullY)×(damageKindPenetration[weapon.damageType]+1400)`；持续受伤且武器有燃烧弹时先整数减半，优先标记再乘10。按敌人列表顺序扫描，仅严格更高分替换，同分保留先到者。越界PriorityMap值−1，地图内未赋值为0。目标死亡清标。敌人 HP、抗性、伤害类型、持续伤害/减速/毒/治疗、奖励及逃逸扣命使用各自消费公式，不可用显示偏移代替物理坐标。

玩家难度 Easy/Medium/Hard 与全局动态难度不同。新局全局值1000。击杀位置优先值`((PriorityMap[x,y]-minValue)×1000)/(255-minValue)`；反馈为`(1500-priority)×weight`，权重默认1，敌type3/4/5/6/7权重2/6/8/10/15。逃逸反馈0，权重`(200/maxLives)×penalty`；type1/2/3/4/5/6/7处罚1/1/1/2/3/4/10，type8单独移除。波次清空后全局难度`(当前值+累计反馈均值)/2`，Java整数向零截断；下一池请求缩放使用未限幅值，HP及难度反馈初值限幅：Easy 500–1250，Medium/Hard 500–1500。正池请求按`count×difficulty/1000`四舍五入、至少1；首波不缩放。玩家难度另决定敌人HP倍率。

普通投射物style0–5的基础飞行比例依次为10%、50%、50%、75%、75%、75%。`baseSteps=trunc(projectileSpeed/10)`；`distanceSteps=trunc(((100-baseTimePercent)×baseSteps×distanceSquare)/maxSquareRange)`；`totalTravelMs=trunc((baseTimePercent×baseSteps+distanceSteps)/100)×10`，按Java向零截断；style6火箭另有两段路径。活动目标移动时更新终点；目标移除后飞向最后缓存点。普通弹不换目标，范围弹到达后执行范围效果。普通投射物AOE与炸药箱爆炸不是同一规则，AOE边界须由R5独立核实。炸药箱为5000伤害、type2、半径3格，以fine坐标距离平方与`(3×7680)²`比较，边界`≤`；普通投射物范围边界不可套用此规则。

新战局动态难度运行基线独立于关卡 Easy/Medium/Hard；清波/下一波规则如上。每帧先检查`lives<=0`判败；否则waveEmpty且敌人列表空时自动进入下一波，不需人工开波。正waveDelay按帧倒数；倒数按钮只加速倒计时。Cow Gulch八波delay均为0，但每波对白会暂停并等玩家关闭。清波不等于胜利：池请求、敌人和待清理运输对象均为空且第8波完成才胜。正式终局只由Progress写一次；失败、未完成和旧样本不标为通关，重开回初态。

## 表现、输入与验收基线

原版不存在通用受击闪光，不新增。步行动画以实际移动距离驱动；枪手默认帧/阈值`(0,1536),(1,3072),(0,4608),(2,6144)`。攻击图集：枪手`(0,100),(1,200),(0,1000)`，Mexican`(0,200),(1,400)`；每次move先按旧计时选帧，再加dt，阈值跨越帧不能提前换帧。死亡和车辆烟雾依据各自剩余计时，不统一浏览器定时换帧。

L01 Wave03第一个action2为(4,10)东转南；type4转向200ms，type8为100ms；方向、帧、镜像和图集按APK类别表。敌人生命条只为活着且type>2、type≠9、HP>0、HP低于`(maxHP×95)/100`整数阈值时显示；背景RGB(63,0,0)，填充宽度保留Java float32和整数除法顺序。伤害3/4/5/6未命中投射物的float32弹道和深度切换按APK公式，首次切层在绘制当前帧后生效；峡谷/非道路只决定拖尾。

New Mexico背景曲`music_loop1`在进关、下一波和败北播放；本波首个单位实际开火后按`wave % 3`循环`music_loop2/3/4`；整关胜利播放`music_level_won`。后台暂停、返回恢复，静音不改变随机消费。浏览器音频手势受限需可重试；损坏/解码失败可无声继续但不算音频验收。必需地图/玩法定义/图像缺失时拒绝新局并给恢复入口。

视觉基线：1024×576逻辑画布，比较同关卡、难度、波次、世界坐标与状态；裁掉原版系统栏和广告区，不拉伸。逐项比地图格/裁片、路线和脚底锚点、对象图层、动画帧、HUD/数字图集、小地图、离散数值与音效事件。随机地图只要求落入完整合法候选集合。抗锯齿/字体栅格化不使用单一全图相似度；每个实质差异归入实现项或明确阻塞。中文通过站点语言切换，检查未翻译键、截断和溢出。截图用于对照展示，不能代替行为断言。

完整游戏验收以60关为固定分母，每关完整波次、对象与正式结算，并保留有效通关结果。载入、预算终止、合成样本和单次战斗不能计作通关；三档难度与解锁边界均须核对。各关关卡配置由游戏自有内容驱动，静态地图数量不是完成率。

## 术语

- **战役/区域/关卡/地图/波次**：完整解锁集合 / 10关内容组 / 地图、初态、波次及结果共同定义的挑战 / 场地布局文件 / 一组进攻与生成规则。地图文件数不是关卡数。
- **单位/敌人/特殊对象**：玩家可操作角色 / 进攻角色 / 炸药箱、赌场、列车等具独立交互规则的对象。
- **战局/正式档案**：一次游戏过程 / 跨会话的战役进度、解锁、设置和高分；不含未完成战局。
- **原版基线/数值方案**：确认的1.8.6行为与参数 / 不可变版本化的运行数值差异。
- **场景/策略/实验/运行/回放**：冻结的关卡及环境输入 / 只按允许观察做决策 / 方案与场景样本比较活动 / 单次确定执行 / 可重建输入、时间及环境的记录。预算失败不是游戏败北；检查点是可恢复状态，不是截图。
