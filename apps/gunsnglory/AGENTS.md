## 稳定约束

- 用深 Module 组织能力：Interface 包括调用者需要知道的输入、结果、不变量、顺序、错误和性能要求。行为测试与真实消费者共享公共 Seam，内部实现封装其调用链。
- 游戏规则由单个战局实例拥有，同步计算；环境 Adapter 提供显式输入，I/O 放在步进之外。公共查询提供隔离值，表现层只读。
- 存储通过所属 Module 的内部 Seam 替换；上层依赖业务行为与统一失败语义。Adapter 的选择集中在装配入口。
- 原版基线和实验分别管理；数值、时间与随机语义的变更必须可追溯。正式档案只接受正式游戏的结算。
- 规格与来源冲突先在唯一真源中解决，列明受影响的内容及验证范围；未知参数不得按猜测写入原版基线，主动调平衡使用独立实验版本。
- 游戏拥有迁入的素材及配置。研究工具、证据与中间文件只用于研发参考；游戏构建和运行从游戏自身内容取得依赖。
- 从一个应用、普通 TypeScript Module 开始。新增依赖或实现范式按根规则先确认；只有真实变化需求出现时才增加 Seam。

## 实现与交付

1. 选择服务于当前产品里程碑的纵向切片，一并交付所需参数、规则消费、素材表现、交互和行为测试。字段、计数器或静态图片只代表对应部分完成；新增辅助平台能力须说明如何解除当前里程碑阻塞。
2. 行为测试优先走真实消费者使用的最高 Interface；预期来自独立源数据、公式或行为案例，不能由同一导入器同时生成实现与正确答案。fixture 用于边界测试，正式内容覆盖由真实关卡路径验收；存储契约测试验证 Adapter 可替换性，浏览器测试验证真实输入和表现。内部重构保留外部行为测试，移除已被覆盖的内部转发测试。
3. 按用户明确指定，在 `gunsnglory` 集成分支推进；这项项目约定优先于根规则中“每项工作从 master 创建分支”的默认方式。每轮验证通过后均按实施计划合并到 `master`、推送、等待 CI/CD，并用 Codex 内置浏览器线上实测；并行任务从最新已验证提交建立 worktree，完成后同步并集成回该分支。
4. 按改动范围运行实际存在的检查，记录命令、结果、兼容性、回滚限制和未验证项。命令以实现后的配置为准，计划中的命令不是执行证据。
5. agent 可加载入口按根规则用 `pi` 实际加载并完成真实调用；AGENTS 文档变更验证启动加载和按指针读取，CLI/MCP 等入口验证自身调用链。
6. 提交前核对只包含本次文件；Markdown 检查差异、链接和跨文档一致性，并用 `cp` 按仓库相对路径复制成品到 `/tmp/var/wishflow-tools/`。

[CLAUDE.md](CLAUDE.md) 仅导入本文件。新增文档时先指定单一职责及触发阅读条件，再添加指针；稳定约束留在本文件，详细定义留在所属文档。
