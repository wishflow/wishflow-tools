# Guns’n’Glory 游戏开发约束

## 1. 状态与阅读入口

当前目录处于设计阶段，仅有协作、架构、接口和实施文档，尚未实现游戏、安装应用依赖或登记导航。文档中的模块、接口和命令是实现契约或计划，不代表已有能力。

根目录 [AGENTS.md](../../AGENTS.md) 继续生效；本文件只补充本应用约束。当前文档交付不授权执行完整实施计划；开始实现时，以用户指定的阶段和范围为准。

| 工作类型 | 必须先阅读 |
| --- | --- |
| 首次接手、模块拆分、依赖调整 | [架构设计](docs/architecture.md) |
| 档案、内容加载、实验持久化、后端存储 | [存储契约](docs/storage-contracts.md) |
| 输入、脚本、AI、回放、机器人、批量模拟 | [模拟与自动化接口](docs/simulation-and-automation.md) |

研究工具及其中间文件不属于游戏模块、运行时依赖或部署产物。迁入的素材由游戏自身管理，研究侧保留文件引用；不为研究证据建立游戏运行时机制。

## 2. 产品边界

- 以 Guns’n’Glory FREE 1.8.6 的离线玩法为基线，逐步完成战役、界面、美术、音效和数值；移除广告、支付、统计 SDK 路径。
- 实时战斗在浏览器运行。后续后端只承担档案、内容资源管理和批量模拟；服务端权威战斗、多玩家同步不是当前架构目标。
- 纯前端采用 Vite、TypeScript、Canvas 2D；站点外壳与语言状态使用 `@wishflow/site-shell`。
- 支持桌面鼠标、手机和平板触屏，保持游戏画面比例；英文为基线并提供中文。
- 正式档案保存进度、设置及本地高分。未完成关卡重新开始，不提供正式战局续玩；实验回放与调试检查点是独立能力。
- 原版基线与实验参数版本分开保存。实验运行不写正式进度、高分或解锁状态。

## 3. 模块边界

- `core` 拥有游戏状态和规则；`application` 拥有用例与战局控制；`ports` 定义存储及运行执行契约；`adapters` 实现浏览器、存储、网络等环境接入。
- `ui`、`render`、`simulation` 通过公共接口使用游戏能力。界面和脚本提交相同语义的命令，批量模拟使用同一个生产内核。
- `core` 同步运行、无 I/O。时间、随机初始状态、输入及必要环境状态由调用者显式提供；不直接读取 DOM、系统时钟、网络、存储或全局随机数。
- 内核状态由战局实例独占。渲染只读；外部查询返回隔离的数据视图，不能取得可修改内部状态的引用。
- 存储端口统一异步；热路径步进保持同步。不得在逐帧计算中读写存储或等待网络。
- 只在启动装配入口选择适配器。上层业务不识别 IndexedDB、localStorage、数据库类型、HTTP 状态或 S3 路径。
- 首阶段在单应用内使用普通 TypeScript 模块。新增共享包、框架、依赖或大范围接口变更按根规则先确认，不预建通用 ECS、插件平台或事件总线。
- 具体依赖矩阵、状态所有权和目录归属以架构文档为准；实现时为依赖方向建立自动检查。

## 4. 规则与内容变更

- 原版基线保留已确认的时间、整数截断、随机源共享关系、遍历和更新次序。优化必须证明不改变这些语义；新规则进入明确的实验版本。
- 数据可表达的单位、关卡和数值差异放入版本化配置；新行为在负责该规则的模块实现并添加针对性回归，不为每个内容条目复制整套逻辑。
- 绘制排序与逻辑集合次序分别维护。绘制帧率、统计采样、是否播放音频不得额外消耗玩法随机数。
- 由规则决定的随机选择和音效请求条件在确定性步骤中完成；实际播放、绘制、网络耗时不反向决定同一帧的玩法。
- 变更需说明受影响的规则版本、内容版本、档案格式、回放格式及兼容策略。旧实验的依赖版本不可用时明确拒绝重放，不静默套用新版本。
- 地图、素材、数值和文案属于游戏资产。正式内容清单只引用可随应用取得的资源；本机绝对路径和研究工作目录不得进入发布包。

## 5. 接口与持久化

- 用业务操作定义存储接口，统一缺失、冲突、容量和失败语义。接口和契约测试共同约束实现，不能只以类型匹配判断可替换。
- 小档案与大型回放、实验产物分别管理。适配器不支持必要语义时，在初始化或操作边界明确报错；不悄悄退化并发或持久性保证。
- 调试使用有类型的命令、查询和场景输入。避免暴露任意执行代码、任意修改实体字段的入口。
- 场景运行记录配置、策略、时间方案、随机源及规则/内容版本。结果包含停止原因和失败样本，不能把超时、取消或错误算成正常败北。
- 资源解码、声音播放、存档失败应形成可见状态。正式档案写入失败不能显示“已保存”；恢复策略由应用层统一处理。

## 6. 变更验证

| 变更 | 最低验证 |
| --- | --- |
| 文档 | `git diff --check`、相对链接与跨文档契约一致性 |
| 规则或参数 | 相关规则测试、固定场景回归、受影响基线的差异解释 |
| 存储实现 | 共享契约测试、实际介质集成测试、失败及冲突路径 |
| 输入、渲染、语言 | 浏览器交互测试、固定视口对照、Codex 内置浏览器检查 |
| 脚本、批量执行 | 无画面真实场景、串并行结果一致性、错误/取消/超时处理 |
| agent 可加载入口 | 用 `pi` 实际加载并完成真实调用，保留命令与关键输出 |

AGENTS.md 等上下文文档应验证实际加载；未来 CLI、MCP、skill 或扩展必须验证自身入口，不能用读取其源码代替调用。若环境无法验证，明确列出未验证项和原因。

实现后以 `package.json` 的实际命令为准；未创建的计划命令不能报告为已执行。公开应用变更遵循根目录的 CI/CD 和线上实测要求；仅文档交付不报告游戏已实现或上线。
