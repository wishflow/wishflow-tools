# 自行车精细建模补充规格

> 状态：2026-10-14 资料补齐与建模方案，待用户确认后实现。本文补充 [bicycle-spec.md](./bicycle-spec.md)，提供 Blender Agent 可执行的几何输入与交付合同；当前没有生成或采用新模型。

## 1. 审核结论与资料分级

现有整车规格可以限定比例，却缺逐件截面、安装基准、机械层级和导出约定。本轮通过原厂技术文件、公开通用零件资料和社区源码补齐可确认项；对原厂未公开的外形给出可复现的展示设计值。参数齐备与实车精确复刻是两件事：下列 D 值使 Agent 能重复建出同一个模型，不代表测得了 Giant 原厂零件。

| 等级 | 含义 | 使用方式 |
| --- | --- | --- |
| F | 原车规格已确认 | 由 Giant 指定车型与尺码，或其明确型号的原厂技术文件支持 |
| P | 其他真实零件的代理规格 | 有制造商来源，但未确认原车安装此件；作为无品牌展示零件的尺寸基准 |
| C | 计算值 | 写清输入、公式、单位和残差；精度受输入限制 |
| D | 展示设计选值 | 明确固定本模型的尺寸/曲线；用户确认前是方案，不升级为原厂事实 |
| U | 未知 | 没有可核验的公开资料；说明原因及所需证据 |

所有表中未特别说明的长度以 **mm** 为单位；写入 Blender、GLB 与浏览器时转换为米。F/P 是来源等级，±2 mm 等是网格对指定值的数值容差，两者分别记录。

## 2. 建模顺序与完成条件

1. **解基准**：读取 F/P/C 参数，建立轮轴、中轴、座管和转向轴；导出后测量关键坐标与轴距。完成条件：第 3 节的闭合残差在界限内。
2. **做轮廓**：按第 4 节管件截面与第 5 节零件表搭建外形，使用原厂照片与已核验社区资源检查侧视、前视和 3/4 视图。完成条件：每个造型有来源等级；管件接缝闭合，无大球遮接头。
3. **做机构**：建立第 7 节运动树，解链条、刹片和侧撑的装配关系。完成条件：零件围绕指定轴心运动，各挡位和停车姿态满足对应接触/间隙合同。
4. **做交付**：按第 8 节保存生成脚本、源场景和 GLB，复用应用已有场景生成/检查流程。完成条件：从脚本重建后的资产与源场景关键测量一致，节点标签可映射到现有部件 ID。
5. **做验收**：从最终网格测量尺寸，并在内置浏览器检查第 9 节视角和交互状态。完成条件：测量报告、画面问题及修正记录齐全。

## 3. 坐标、基准与可计算几何

浏览器坐标为 `(x 前, y 上, z 传动侧)`；Blender 原生坐标为 `(X 前, Y 非传动侧, Z 上)`。转换为 `Blender=(x,-z,y)`，反向为 `Three=(X,Z,-Y)`，是保留手性的旋转。表中坐标全部使用浏览器坐标、单位 mm；Blender 脚本统一转换一次。

Blender 使用 METRIC、Unit Scale=1。原点是后轴垂直投影，不是后轴心。glTF 导出启用 `export_yup` 后处理 Z-up→Y-up，应用侧直接采用导出的 Y-up 结果；不能再给整车额外旋转 90°。自定义属性使用 `export_extras` 保存。依据：[Blender 导出 API](https://docs.blender.org/api/4.4/bpy.ops.export_scene.html)。

基准测量姿态：转向=0、拆解=0、车体直立、侧撑收起。轮胎外半径 `R=349` 是 D 估算输入；622 是胎圈座直径，不能充当轮胎外径。Schwalbe 明确指出实际胎宽/滚动周长随内圈宽、气压和负载变化：[尺寸标识](https://www.schwalbe.com/en/technology-faq/tire-sizes/)、[实际尺寸说明](https://www.schwalbe.com/en/technology-faq/tire-dimensions/)。

| 基准点/方向 | 浏览器坐标或值 | 等级与计算 |
| --- | --- | --- |
| 后轴 A | `(0,349,0)` | C，使用选定 R |
| 前轴 B | `(1075,349,0)` | F 轴距 + D 外半径 |
| 中轴 O | `(440.9365,289,0)` | C，`x=sqrt(445²−60²)`，`y=R−60` |
| 头管上中心 H | `(850.9365,845,0)` | C，`O+(410,556,0)` |
| 头管下中心 J | `(893.2604,722.0826,0)` | C，`H+(130 cos71°,−130 sin71°,0)` |
| 座管名义顶中心 S | `(299.1362,752.8078,0)` | C，`O+(−485 cos73°,485 sin73°,0)`；不是座垫位置 |
| 转向轴向下方向 d | `(0.325568,−0.945519,0)` | C，穿过 H/J；前叉、把立和车把围绕此直线转动 |
| 中轴/轮轴方向 | `(0,0,1)` | F/C，沿车轴方向 |
| 前叉偏移 | 50，垂直于转向轴测量 | F；不是简单沿 x 加 50 |

用头管、71° 和 50 偏移求前轴 `x=H.x+(H.y−349)cot71°+50/sin71°=1074.6040`，与轴距相差 **0.3960**。优先锁定 1075 轴距，允许前叉闭合调整不超过 1 mm，并记录由取整产生的调整。有效上管的水平定义可复算为 579.986，按 580 验收；不要把 580 当作斜上管实体长度。

同一组模型值推导 Trail 约 67.289；Giant 表为 69.4。轮胎外半径未实测，不能同时强行锁定 349 与 69.4。官方 Trail 与跨高 754 保留参考属性，暂不作为最终网格精确断言；跨高还缺厂商指定测量位置。整车外长约 `1075+2×349=1773`。

## 4. 车架与前叉造型的展示设计值

以下均为 D。截面 `a×b` 是全直径：a 位于自行车侧面、垂直于该管中心线，b 沿左右方向；t 从起点 0 到终点 1。截面尺寸以平滑三次插值过渡；端部按相邻管真实交线裁切并并接。默认展示壁厚 1.5，仅供端口剖面显示，不作为真实管壁。

三维曲管处按正交框架解释截面：将车体左右向量投影到中心线切线的法平面，归一化为 b 方向，再以叉积求 a；沿路径平行移动框架并保持符号连续。不能把倾斜切线与固定世界左右轴直接当成互相垂直的截面两轴。

| 管件 | 中心线/接点 | t=0 / 0.5 / 1 的椭圆截面 |
| --- | --- | --- |
| 上管 | S 接至头管 `J+0.78(H−J)`；中心线基本直，端部自然收口 | `34×26 / 36×28 / 38×30` |
| 下管 | O 接至 `J+0.16(H−J)`；中心段轮廓直，头管端圆顺过渡 | `48×32 / 44×30 / 50×34` |
| 座管 | O→S；座杆孔沿 73° 座管轴 | `34×32 / 34×32 / 34×32` |
| 头管 | J→H；外径下 48、上 44，碗组轮廓独立 | 外部渐变圆截面；内轴承、锥管尺寸仍 U，不刻画伪精确内部 |
| 后下叉，左右各一 | O 邻域 `(O.x,289,±25)`→`(200,310,±50)`→`(0,349,±67.5)`，C¹ 连续曲线 | `24×16 / 20×14 / 18×12` |
| 后上叉，左右各一 | `(S.x,735,±18)`→`(140,550,±48)`→`(0,349,±67.5)` | `16×12 / 14×10 / 12×9` |
| 前叉 | 叉冠 `C=J+20d`（沿转向轴向下）；两腿起点 `C+(0,0,±25)`，中点约 `(980,535,±45)`，终点 `B+(0,0,±50)` | `30×20 / 24×16 / 18×10`；控制点按接触/偏移合同复核 |

前叉曲线只固定叉冠/叉端与整体 50 偏移关系，不能以“叉腿沿转向轴”的句子把两腿建成一根直圆杆。前轮 100 OLD、后轮 135 OLD 是 P 代理装配，不是原车已确认值；对应前后勾爪内侧面分别 `z=±50/±67.5`。

节点焊道采用独立窄带：宽 2.5、高 0.6、波纹节距 2.0，沿实际接缝走向；端部融合倒圆 2–4。这些均为 D；外露管件闭合连接后再加焊道。螺纹、内部壁厚和不可见焊接结构不作原厂复制。

三交叉编法为 D：每侧索引 k=0…15，圈孔角为 `22.5k°`，另一侧错开 `11.25°`；对应法兰孔 j 在 k 为偶数时取 `(k+3)%16`，奇数时取 `(k−3)%16`。法兰与圈同侧初相位一致，得到 ±67.5°；每侧 16 个法兰孔各用一次。交叉处加有方向的约 1 mm 出入错层，内外孔交替，保持车轮孔位和末端连接准确。

辐条中心路径近似长度 `L=sqrt(R_e²+R_f²−2R_eR_f cos67.5°+c²)`：`R_e=302`、`R_f=30.5`、c 为该侧中心距。得到前左右约 292.686/293.797，后左右约 293.827/292.502；这是模型中心线长度，未扣除 J 弯、帽内插入量，不能用作实物下料长度。实际网格必须从本轮端点生成，而不是使用一个固定长度圆柱旋转。

把立安装按 D 选择正向上扬：基座先取 `H−20d`，标称15°按相对转向轴法平面的上扬角解释，侧视水平夹角为 `90−71+15=34°`；把夹中心约 `(919.039,914.238,0)`。官方没有定义该角的安装朝向/完整堆叠，因此这一坐标是 C/D；用户确认外形时可整体调堆叠和安装朝向，保留90长度与25.4夹径。

座垫姿态采用 D 端点解释：本模型将350定义为杆底到导轨夹持中心、插入250后外露100；将53解释为导轨夹持平面到顶面参考高，因此顶面约 `S.y+100sin73°+53=901.4`（C/D）。厂家未公布这两个字段的端点，也未给夹头 offset；此计算只是本模型的骑姿选值，不能验证原车真实座垫高度。

机构安装点采用 D：前卡钳片面中心相对前轴以半径69、侧视极角130°定位（x正向为0°），后卡钳以半径69、极角40°定位，z分别与前/后碟片面一致；卡钳安装耳/转接座使用选定PM74接口图，实体连接到实际前叉/后叉。后拨尾钩连接点先取 `(15,318,76)`；上导轮以当前后齿片节圆半径 `r` 与导轮半径26.534、间隙6构成距离 `r+26.534+6`，在后轴侧视−65°方向取初始轴心，z对齐该齿片；下导轮与导板姿态按离散链节闭合解修正。以上是可复现初始装配，复核时可以调整D接点，尾钩与车架保持固定、导轮与齿片避免干涉。

单动片制动采用 D 可见形变：碟片安装中心/螺钉保持固定，外摩擦带向静片侧（本模型−z）偏移最多0.25，内外带间平滑过渡；动片总行程约0.5，直到两片接触摩擦面。刹把展开角20°、拉臂10°及拉线位移2为D演示输入，按压力同步插值。它只表示制动机构，未求解真实弹性；不能把整个转子刚体沿轴平移来凑双片接触。

链轮节圆半径按离散节距公式 `r=p/(2sin(π/N))`，不要用连续圆周近似 `Np/(2π)` 代替精确链销接点。40T 得80.934；12/14/16/18/21/24/28/32T 依次24.535/28.537/32.549/36.568/42.605/48.649/56.714/64.785；13T 导轮为26.534。齿顶、齿根和倒角需要单独轮廓，节圆不等于齿顶外径。

链条长度的建模闭合：以偶数链节108作为初值（D，非原车测量）；固定同一条链的节距与节数，建立销心的铰接骨架，使每对相邻销心的**欧氏距离**为12.7，最后一节也闭合。啮合段按每齿 `2π/齿数` 的离散齿位排销，自由段/导轮段共同解每挡导板转角和下导轮位置。连续曲线只作初始导向；按曲线弧长每12.7排销会在小飞轮上缩短销间弦距，不能替代本合同。若108不能在全挡位及 cage 行程内闭合，以2节步进调整并记录最终 N；不能缩放链节、每挡重选节数或移动飞轮堆栈凑长度。包装116节只作为原料长度参考。

## 6. 侧撑与接地状态的可执行定义

侧撑展开状态包含整车向非传动侧倾斜8°（绕 +x 轴旋转−8°）。直立时轮胎相切；倾斜后重新测实际胎面最低点并上移车体，使两轮在零转向的停车姿态仍接地。理想330大半径/19截面圆的近似上移是0.1849，但最终值由网格决定。

展示设计（D）选择铰点 `P=(180,285,−62)`；世界地面脚掌中心 `Q=(150,0,−260)`，脚掌45×30、厚12。先求车体姿态变换 T；脚掌四个底面角点在世界 `y=0`，通过 `T⁻¹` 求其自行车局部顶点，再以局部顶面中心连接杆件。不得只把脚掌中心设到地面，而让底面带倾角。

侧撑夹具固定在非传动侧后下叉 `x=180` 的实际截面；夹圈内表面按该截面外轮廓加0.3间隙生成，连接臂延伸到P，铰轴周围留足转动间隙。夹具转接面采用18孔距、M6螺栓的代理边界，属于D示例安装；不能把P画成悬空铰点，也不能据此宣称原车存在KSA18孔。

理想圆截面算例（C）中，局部底面中心约 `(150,36.002,−257.495)`，局部杆端约 `(150,47.885,−255.825)`；杆长约307.720。以铰点到杆端为展开方向，收起方向为局部 `−x`；固定铰轴为两方向叉积的单位向量，约 `(0,0.632890,−0.774242)`，展开到收起转角约84.405°。脚掌随同一铰轴转动；杆件外包18×12、伸缩下段12×9为 D。实际胎面修正改变 T 时重新计算这些 C 值。

侧撑验收检查所有四个底面角、底面法向和安装点，另检查收起/展开不穿轮胎、辐条、后叉或链条。支撑三角形由两轮实际接点和 Q 构成。此状态是姿态展示，不求质心和支架承载力。

| 状态 | 地面检查 |
| --- | --- |
| 直立、零转向、侧撑收起 | 两轮实际胎面最低点 `0±2`，侧撑不触地 |
| 停车展开侧撑 | 先归零转向，再设置8°倾角/接地位移；两胎面和脚掌底面均满足对应接触合同 |
| 转向演示/骑行 | 倾斜转向轴会改变前轮最低点；以整车小幅俯仰和高度校正对齐前后轮支撑点，不能沿用零转向的固定最低点 |
| 放倒 | 采用约75°展示横滚后，按实际轮胎、把套和踏板几何校正整车高度；接触部件改变，不继续断言侧撑和两胎同时触地 |

## 7. 机械层级与交互绑定

8个 UI 总成是选择/显隐/拆解标签，机械父子树是运动约束，两者分别管理。刹车总成的碟片与卡钳需要不同运动父节点。保留现有 `BicyclePartId` 字符串作为稳定选择标识；一个部件可有多个子网格。显隐作用于匹配标签的可见网格，包含其他标签的机械根仍保留，避免隐藏前轮时意外连带隐藏属于刹车标签的碟片。

```text
bicycle_root（车体姿态）
├─ frame_parts / rear_caliper / rear_axle_QR / saddle_accessories
├─ steering_root（原点H，轴d）
│  ├─ fork / handlebar / front_caliper / front_fender / front_axle_QR
│  ├─ front_wheel_spin（原点B，轮轴）
│  │  └─ front_tire / rim / spokes / hub_shell / front_rotor
│  └─ brake_lever_hinges（各自刹把铰点）
├─ rear_wheel_spin（原点A，轮轴）
│  └─ rear_tire / rim / spokes / hub_shell / rear_rotor
├─ cassette_spin（原点A，同轴独立，轴向位置固定）
├─ crank_spin（原点O，曲柄/牙盘）
│  └─ pedal_hinges（各自在曲柄端轴心，反向补偿曲柄相位）
├─ derailleur_fixed_mount（尾钩连接点不随换挡移动）
│  └─ derailleur_linkage / cage_hinge
│     └─ upper_pulley_spin / lower_pulley_spin（链速驱动）
├─ chain_motion_root（链节沿路径重定位）
└─ side_stand_hinge（原点P，计算后的铰轴）
```

后飞轮在踩踏驱动时与后轮同步，滑行时可保持不转；无需模拟内部棘爪。换挡改变链条所绕齿片和后拨导轮的链线，飞轮各片的轴向堆栈固定。旋转碟片归轮轴，前卡钳归转向根、后卡钳归车架；刹线两端接刹把与卡钳拉臂，转向后按连接点更新曲线。

花鼓外壳/法兰随轮转，固定轴芯/快拆保留在车架或前叉。脚踏反向补偿曲柄相位以保持平台相对车体水平，车体横滚仍由整车姿态决定；导轮围绕各自轴心按链速旋转，cage张紧转动与导轮自转分别更新。

速度大于0时，以设定速度/滚动半径驱动轮转，曲柄/链条按挡位比例联动；拖轮或曲柄输入合成到同一角相位，随后继续按设定速度更新，不改变速度滑杆。速度=0时，拖曲柄/链条只演示传动，不启动整车路线；前轮拖动只转前轮，后轮向前拖动按滑行处理，后轮反向拖动可带动飞轮/链条/曲柄。当前选中挡位的相位与链路保持一致。选择/拆解按标签处理，装回恢复保存的装配矩阵。

从侧撑展开或放倒状态设置正速度时，同一状态更新先扶起/收撑并恢复骑行姿态，再立即按该速度运行；不增加开始按钮或长时间启动动画。

## 8. Blender 源文件与应用侧资产的拟定交付

当前自行车由 Three.js 程序化构建。若用户确认 Blender 产出方案，则使用应用已支持的对象级 Blender 流程作为候选接入方式；这是待确认的资产接入决策，本次没有替换运行时。Three.js 查看器和交互保留，复杂外形从本地 GLB 读取，动态链节/刹线可继续复用程序化更新，不让 Blender Drivers 成为浏览器运行时依赖。

拟交付包含所属模块的 `blender/generate_scene.py`、`blender/scene.blend`、`assets/scene.glb` 与 `scene-contract.json`。生成脚本是可重建依据；MCP 用于所属项目场景的检查/调整，调整要回写生成脚本，不能把用户当前打开的其他场景当作工程源。

每个可选择零件根保存 `partId`、`assemblyId`、`dimensionGrade`、`sourceKey`；需要运动的根再保存局部 `pivot/axis` 和稳定 `motionRole`。命名一经实现纳入场景合同；导出时保留层级/extras，应用加载后建立部件映射，不能依赖临时 `.001` 名称。应用已有命名/检查规则优先，只有不适配时才在批准的实现范围内补合同。

`pivot/axis` 在extras和场景合同中统一采用浏览器Y-up：pivot为**父运动节点局部坐标、米制**，axis为该父局部空间中的单位向量；子运动根原点位于pivot。生成脚本依据对应导出父节点的坐标系转换后写入属性，加载侧直接读取；装配态运动根使用单位缩放，基础朝向与几何朝向分别保存。glTF会转换节点/网格，但自定义数组不会自动跟着转换，因此不能把原生Z-up数字未经转换塞进extras。

Mesh使用已应用的缩放、可预测法线/UV与可导出的材质；源场景保留可编辑曲线或截面参数，导出副本转换为评估后的 Mesh。重复辐条、帽和链板共享网格/材质；不要求 glTF 自动保留所有 Blender 约束和 Drivers。镜像件必须保证传动侧/碟片侧正确。

预算草案沿用应用现有场景检查的量级：GLB≤8 MiB、最终导出三角面≤100,000、纹理边长≤1024。这是 D 上限，实施前先估算轮组/链节/齿片的总成本；不能为过预算悄悄删除已承诺机械细节。超预算时记录原因、画面和替代方案，按用户确认的范围调整。

## 9. 验收与尚未关闭的阻碍

测量最终求值网格与导入 GLB 后的结果；同时记录来源等级、输入目标、实测值和数值误差。关键基准/安装中心容差1 mm，整体外包关键尺寸2 mm；链销节距误差0.05 mm、碟片与卡钳间隙误差0.1 mm。接触项用各相关网格的变换后顶点/截面，不能只以整车包围盒替代。

固定车侧正交、前视正交、顶视、传动侧3/4和非传动侧3/4视角；另检查最大/最小齿片、转向、刹把/拉臂、侧撑展开/收起和放倒。尺寸正确但接头不自然、链条穿片、轮组不成形、侧撑脚掌倾斜或画面材质误用均要修正。外观审核记录问题及依据；只保存截图不算验收完成。
