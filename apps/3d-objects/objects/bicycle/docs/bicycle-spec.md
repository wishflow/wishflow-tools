# 城市通勤自行车对象规格

> 文档状态：2026-10-15 已完成精细化实现并通过本地发布检查；线上验收结果随本次交付说明记录。

本规格说明产品行为和整车基准。使用 Blender MCP 制作精细零件时，同时读取 [blender-modeling-spec.md](./blender-modeling-spec.md) 的坐标、逐件参数、运动树和交付合同；核对原厂/通用件数据时读取 [component-reference-research.md](./component-reference-research.md)；选社区模型或外部素材时读取 [resource-research.md](./resource-research.md)。未公开原厂形状使用明确的展示设计值，不能从“参数完整”推论成“实车精确复刻”。

本轮已将候选模型与生成器源文件下载到 [references/](../references/LICENSES.md)，记录许可、校验和及源文件检查结果；同类车资料与推测尺寸见 [similar-bike-dimensions.md](./similar-bike-dimensions.md) 和零件研究第10节。候选整车、轮组和链条的结构、孔数、面数或链型与目标不符，因此保留自制 Blender 几何。Metal012 三张 CC0 PBR 贴图已嵌入 GLB 并用于裸露金属材质。尺寸合同、八挡导轮路径、后拨笼换挡、拆解和操作已本地实现；未公开的原厂 CAD 与截面仍按有来源边界的展示设计值处理。

## Problem Statement

当前自行车模型以等截面管件和简化的零件形状为主，整体比例、管件连接、机械细节和接地关系不足以支撑近距离观察。用户需要一个尺寸有依据、曲面可信、零件连接清楚，同时保留现有拆解和操作能力的城市通勤自行车。

## Solution

沿用当前 Three.js 对象模块和交互，不新增运行时依赖；以 Giant Escape Disc 4（2025，美国版，M 码）作为尺寸/组件关系参考，复用已采用的 CC0 金属贴图。检查社区现有零件后，因结构、尺寸或面数不匹配而采用自制自行车几何；Blender 源场景/GLB 是可重建模型输入，页面仍由现有 Three.js 查看器驱动。官方未公开的截面、焊道和配件尺寸按有参数的视觉近似处理。

## User Stories

1. 作为自行车结构学习者，我希望看到依据真实 M 码参数搭建的车架轮廓，以便判断车架与 700C 车轮之间的比例。
2. 作为自行车结构学习者，我希望上管、下管、座管、头管和前后叉呈现真实管件的截面与连接关系，以便识别各自如何组成车架。
3. 作为检视者，我希望前叉、花鼓、曲柄和刹车等部件围绕正确的轴心独立运动，以便观察机械关系而不看到零件漂移。
4. 作为检视者，我希望车轮包含正确数量的辐条、清楚的轮圈/花鼓层次和可信胎宽，以便在不同视角观察轮组。
5. 作为检视者，我希望看到闭合且与牙盘、飞轮和后拨相接的链条，以便理解 1×8 传动。
6. 作为操作用户，我希望拨动脚踏、链条、车轮、车把和刹把时能看到关联部件同步反馈，以便用操作理解动力和制动路径。
7. 作为操作用户，我希望速度滑杆可直接设速、设为零立即停车，且刹车反馈正确，以便不必等待长时间加速/减速动画。
8. 作为操作用户，我希望停车侧撑的脚掌接地、轮胎与地面相切，并能在停车后放倒/扶起自行车，以便相信模型的空间关系。
9. 作为手机用户，我希望在窄屏仍能看清主要车架和控制区，并获得简明双语操作提示。
10. 作为后续维护者，我希望每个精确尺寸、外部贴图和视觉近似都能追溯到一手来源或明确说明，以便避免再次混用不一致的规格。

## Implementation Decisions

### 目标与边界

保留现有自行车对象模块、Three.js 查看器和页面交互，不引入后端、远程模型服务或新依赖。升级自行车专属机械网格；复杂外形可按获批的对象级 Blender/本地GLB流程接入，动态机构复用现有更新方式。金属表面继续使用随模块打包的本地贴图。

交互包含两个模式：

| 模式 | 目标 | 能力 |
| --- | --- | --- |
| 检视 | 了解总成和部件关系 | 轨道相机、点选部件、拆解滑块、总成显隐、装回与显示全部 |
| 操作 | 观察通勤骑行机构 | 直接设速、踏动、8 速变速、转向、前后刹车、停车脚撑、放倒与扶起 |

骑行使用封闭路线和简化运动学状态，不求解刚体动力学、地面附着、碰撞或真实道路交通。它用于说明部件和操控关系，不用于工程设计、尺寸放样或骑行安全验证。

### 现实车型参考

以 **Giant Escape Disc 4（2025，美国版，M 码）**作为几何和部件关系参考，不宣称制作官方数字孪生。车型页与官方规格 PDF 可核对车架尺码、关键几何、原厂传动、刹车和轮组；管件的精确截面、焊缝尺寸、管路路径和配件 CAD 未公开，仍需按产品照片做有边界的视觉近似。具体链接、核对结果和未公开项目记录在 [`resource-research.md`](./resource-research.md)。

模型不复用或发布 Giant 商品图，不使用 Giant 商标或型号贴花。维持现有无品牌深青绿色外观；货架、挡泥板、反光件和侧撑作为独立的通勤展示配件，不把它们标成该车原厂标配，也不声称具体配件适配。

### 坐标与主要尺寸

模型坐标以米为单位：`x` 轴从后轮指向前轮，`y` 轴向上，`z` 轴沿车轴方向，传动侧为 `+z`；车体侧面位于 `x-y` 平面。定位基准是后轮轴心的垂直投影：后轴心 `(0, 0.349, 0)`，前轴心 `(1.075, 0.349, 0)`，地面为 `y=0`。浏览器世界坐标和对象局部坐标必须采用同一套转换，不能让几何、路线、阴影和接地点各用一套原点。

以下优先采用 Giant 官方 M 码数据；官方未公布的值标为展示近似，不伪装成实测规格。

| 尺寸/部件 | 目标值 | 依据与精度 |
| --- | ---: | --- |
| 轮胎/轮圈 | 700×38C；622 mm 胎圈座直径；外半径约 349 mm | Giant 规格为 700×38C；622 mm 是 ETRTO 700C 轮圈标称直径，外半径按轮胎名义宽度估算 |
| 轴距 | 1,075 mm | Giant M 码官方数据；前轴 `x=1.075` |
| 车架几何 | 上管 580 mm、座管 485 mm、头管 130 mm | Giant M 码官方数据；上管长度为 effective top tube |

### 模型输入与造型顺序

模型说明按“硬尺寸 + 部件表 + 视觉参考 + 可验证视角”编写；单独一句“写实自行车”不作为造型输入。几何和组件数值以本规格和制造商技术资料为准，官方产品图只辅助判断轮廓与表面比例。输入/生成步骤按以下顺序收敛：

1. **定尺寸**：先按 M 码几何锁定两轴、五通、头管、座管、把宽和曲柄，不添加细节。
2. **定轮廓**：用车侧正交视图校正车架三角、前叉角、挡泥板/货架留空和轮胎外径；保持品牌中立，不画商标。
3. **定机构**：明确每个部件的独立根节点、真实转轴和连接点，再补链节、碟片、卡钳、刹线和辐条。
4. **定表面**：最后分配车架漆面、橡胶、皮革和金属材质。材质纹理不得遮盖尺寸/形状错误。
5. **逐视角复核**：保存车侧、前视、传动侧和 3/4 视图，以及拆解、侧撑展开和刹车态；通过几何断言和内置浏览器画面检查后再交付。

本表用于整车比例；精细零件制作使用补充规格的 F/P/C/D/U 分级、逐件参数和闭合约束。模型输出不得自行偏移有官方来源的尺寸。未公开的截面/焊缝/配件按明确 D 值制作，视觉依据可从产品图复核，不据此声称相对实车毫米级精确。

### 几何精细化目标

现有 `bicycle-model.ts` 用等截面圆柱连接车架节点，能支撑拆解和运动演示，但会形成“圆杆拼的自行车”观感。精细化的主线是保留 Three.js 和当前对象接口，集中升级自行车专属网格和可验证的尺寸：

| 部位 | 目标形态 | 可确认边界 |
| --- | --- | --- |
| 车架 | 依官方 M 码几何重建双三角车架；上管、下管、座管及后叉使用有变化的椭圆/扁圆截面和自然过渡；在头管、五通、座管簇、后勾爪处表现合理连接与细焊缝 | 官方只给材料等级、单抽管和外形照片，不给截面、壁厚与焊缝尺寸；截面和焊道是视觉近似，不以大球节点遮接缝 |
| 前叉与转向 | 转向围绕 71° 头管轴线；两叉腿从叉冠曲线落到前轴，前轴相对转向轴垂直偏移50 mm；体现碗组、把立、640 mm 平把和机械刹线路径 | 叉腿截面、叉冠和刹线夹点按补充规格展示参数构建；轮/碟片/卡钳的运动父节点分别定义 |
| 车轮 | 38 mm 胎体截面、700C 胎圈、具层次的双层圈、两侧法兰/辐条帽/花鼓、每轮准确 32 根辐条和可识别的交叉走线；轮胎与轮圈同轴转动，碟片随轮、卡钳固定在叉/车架 | 官方给胎宽、轮圈类别、32 孔和辐条规格；轮圈截面、花鼓型号、辐条长度与交叉数未公开 |
| 传动 | 40T 牙盘、170 mm 曲柄、8 片已确认齿数的飞轮、可读链节、后拨导板和两只导轮；闭合链路经过牙盘、下/上导轮与当前飞轮；换挡移动后拨笼和链线，飞轮堆栈轴向位置固定 | 齿廓、片间距和后拨外形按展示参数构建；当前模型选116节、12.7 mm节距，并逐挡求解导板角以保持链路总长。链节沿曲线弧长分布，不等同逐销刚体链条 CAD |
| 碟刹 | 160 mm 有开孔/承力臂的转子、机械卡钳、来令片、拉线、把端合金刹把；刹把转动、拉线位移和来令片夹合有连续可见关联 | 官方只确认机械类型与碟片直径，不补造液压油管、活塞或未经确认的卡钳型号 |
| 座垫与通勤配件 | D-Fuse 合金座杆轮廓、座垫壳体与导轨；货架、挡泥板支架、灯/反光片、螺栓和侧撑分别可识别 | Giant 官网没有确认本车型带货架、挡泥板或侧撑；它们是模块的独立示例配件 |

表面细节优先用可复用材质和程序化小几何，不以装饰性贴图替代错误的车架比例、连接位置或转轴。车架截面、机械部件和接地点属于几何验收项；材质只负责表达漆面、金属、橡胶、皮革的差异。

### 总成与可拆解结构

模型由可独立显隐和拆解的 8 个总成组成。拆解量为 0–100%，每个总成沿局部方向移开；装回将拆解量归零。

| 总成 | 主要部件 |
| --- | --- |
| 车架 | 上管、下管、座管、后下叉、后上叉、头管、中轴壳、后叉端 |
| 转向 | 前叉、碗组、把立、平把、把套、刹把 |
| 前轮 | 外胎、胎纹、轮圈、32 根辐条、花鼓、反光片 |
| 后轮 | 外胎、胎纹、轮圈、32 根辐条、花鼓、反光片 |
| 传动 | 牙盘、曲柄、脚踏、链条、8 片飞轮、后拨与导轮 |
| 前刹车 | 刹车卡钳、来令片、刹车线、前碟片 |
| 后刹车 | 刹车卡钳、来令片、刹车线、后碟片 |
| 座椅与配件 | 座杆、座垫、前后挡泥板、后货架、车灯和反光片、侧撑 |

总成之外，界面还允许按部件选择和查看名称、材质、关联部件及简要功能。总成隐藏后，部件不可点选；“显示全部”恢复所有总成。拆解和总成显隐仅在检视模式生效。每个需要转动或拆解的零件必须有独立网格根节点和真实轴心；配件仍可留在当前 8 个显示总成中，但不能合并到无法单独选择的装饰网格里。

UI 总成通过标签组织，机械运动树独立：前碟片归前轮旋转节点、前卡钳归转向节点，后碟片归后轮旋转节点、后卡钳归车架；座管是固定车架管件，座杆是插入其中的独立部件。不得按 UI 总成把旋转碟片和固定卡钳合并到同一运动父节点。

### 操作与状态

### 检视

- 拖动空白区域旋转视角，滚轮缩放，右键拖动平移；提供放大、缩小和复位视角控件。
- 点选部件后显示高亮框、名称、材质、关联部件和说明。
- 拆解滑块按总成展示结构间距；提供“装回”和“显示全部”。
- 切换到操作模式时，总成回到装配状态并展示封闭骑行路线。

### 操作

- 速度滑块直接设定 `0–12 km/h`：设为 `0` 立即停车，设为正速度后立即按该速度沿路线运动；前后刹车也立即停车。
- 页面控件支持踏动、前后刹车、变速、转向、侧撑和放倒/扶起，不提供开始或结束骑行按钮。
- 画布聚焦后支持键盘操作：`W`/`↑` 增加 `1 km/h`，`S`/`↓` 设为 `0`，`A`/`←` 和 `D`/`→` 转向，`[`/`]` 换挡，`P` 在停稳时展开或收起侧撑，`L` 放倒或扶起，`R` 复位。
- 拖动前轮、后轮、曲柄、链条、车把或刹把可直接观察对应机构的反馈；鼠标操作期间保留轨道相机的基础旋转与缩放能力。
- 骑行速度、挡位、转向角、刹车压力、路线位置和脚撑/倒地状态通过页面状态展示。速度大于 `0 km/h` 时禁用侧撑和放倒；设为 `0` 后才可操作。

运动关系使用简化模型：踩踏通过当前齿比驱动后轮和链条；骑行期间两轮按行进距离滚动，曲柄按齿比同步；刹车立即将速度设为 `0`，刹把与刹车皮同步动作；转向使前叉转动并影响车体姿态。该模型不模拟部件受力或真实制动距离。

### 材质、资源与加载

- 车架采用青绿色涂装，胎面使用深色橡胶，座垫和把套使用棕色材质，传动和金属部件采用钢/铝色调。
- 金属色、OpenGL 法线和粗糙度贴图来自 ambientCG 的 `Metal012`，按 CC0 1.0 许可随对象本地分发并嵌入 GLB。来源、资产记录和材质应用范围见 [`resource-research.md`](./resource-research.md) 与 `assets/manifest.json`。
- 缩略图为模块内绘制的 SVG，不依赖远程图片。
- ambientCG Metal012 的颜色、OpenGL 法线和粗糙度图用于五种小型裸露金属材质；生成器为带贴图材质的网格写入平面 UV，按12次/米重复，并将贴图嵌入 GLB。大面积挡泥板使用无纹理的抛光铝合金，避免金属微划痕贴图破坏薄板曲面观感。场景检查器验证贴图材质、UV 和导出槽位；纹理不证明零件的原厂材质或加工工艺。
- 贴图加载、模型构建和 WebGL 初始化分别报告状态；贴图失败时可重试，WebGL 初始化失败时重载页面再初始化。

## Testing Decisions

现有 Playwright 场景测试覆盖路由、速度、变速、模式切换和窄屏，并通过侧撑总成包围盒的最低点检查接地。包围盒单点接触不足以证明脚撑脚掌平放、轮胎真实接地或模型比例正确；精细化实施必须让几何测量和画面审核互相补充。

| 验收面 | 检查内容 | 判定方式 |
| --- | --- | --- |
| 尺寸合同 | 轴距、轮胎外径、车把宽、曲柄长和中轴落差与指定建模值一致 | 在零转向、零拆解、直立基准态测最终坐标/网格；关键尺寸误差≤±2 mm。记录来源等级；估算值的网格容差不代表相对实车精度 |
| 接地合同 | 基准直立时两轮相切；展开侧撑时按停车倾角解两轮与脚掌接触；转向/放倒另定义接点 | 检查胎面实际轮廓和脚掌全部底面角点/法向，接触误差≤±2 mm；姿态与脚掌计算见补充规格，不能以父组包围盒最低点替代 |
| 机械合同 | 前叉绕转向轴、车轮绕花鼓轴、曲柄绕中轴、刹把绕铰点、侧撑绕安装点转动 | 自动检查轴向、轴心位置及父子关系；操作状态前后零件不漂移、不离开连接件 |
| 组件合同 | 车轮各32根辐条、40T牙盘、已确认逐片齿数的8速飞轮、前后160 mm碟片 | 核对几何数量/齿数/直径与页面状态；链节节距和实际安装接口使用补充规格的测量基准 |
| 视觉审核 | 车侧、前侧、传动侧、拆解态、刹车/脚撑操作态 | Playwright 固定相机截图由开发者通过 Codex 内置浏览器逐视角检查；记录车架闭合连接、轮胎/地面关系、零件重叠和材质方向问题，再修正后复查 |
| 行为回归 | 速度直接设置和立即停止、换挡、踏动/轮转、转向、制动、脚撑、放倒/扶起 | 保留现有 `scene.spec.ts` 浏览器验收；新增几何断言只针对上述外部可观察合同，不绑定内部函数名或网格实现细节 |

截图审核不能替代尺寸断言；尺寸断言也不能判断车架轮廓、管件粗细和机械细节是否看起来可信。两个环节都通过才算模型验收。

## Out of Scope

- 真实刚体、轮胎抓地、道路碰撞、制动距离或骑行安全模拟。
- 可直接用于生产/放样的 Giant CAD、管壁厚度、焊缝工程尺寸或官方数字孪生。
- 未经确认新增外部模型依赖、运行时服务、付费素材或品牌商标。
- 多尺码车辆配置；此轮只按 M 码基准核对比例。

## Further Notes

模型性能与发布边界：

使用实例化网格绘制辐条、胎纹、牙盘齿、碟片孔和链节，减少重复几何的场景对象开销。全部贴图随应用打包；模型不请求外部服务。

验收关注：模块被对象目录自动发现；中英文内容随站点语言切换；模型可加载、旋转、缩放、点选和拆解；总成显隐和装回有效；车体尺寸、管件轮廓、部件连接、接地点和转轴通过 Testing Decisions 中的合同；速度滑杆直接设定/停车，骑行操控使车轮、曲柄、链条、转向和刹车产生可见反馈；侧撑展开接地、倒地状态正确；窄屏控件可访问；资源来源和许可可追溯。
